# SATURN Heat1 + DHW2 Integration

## 1. Архитектура

- Один физический Saturn представляется одним RAW устройством WB.
- RAW устройство преобразуется в два виртуальных:
  - отопление (схема 1);
  - ГВС (схема 2).
- Для двух Saturn создаются 4 виртуальных устройства (низ/верх).

## 2. Что читает RAW

Базовый набор:
- T1..T5, AI1, AI2;
- T1_error..T5_error, AI1_error, AI2_error;
- DI1..DI10;
- DO1..DO11;
- AO1, AO2;
- V_battery, S1_ID, S2_ID.

## 3. Логирование

Принят формат:

`[система][скрипт][контекст]; ТИП=событие; параметр=значение`

Использованы теги:
- `[сатурн]` — инициализация и связь;
- `[отопление]` — события отопления;
- `[гвс]` — события ГВС (добавлять по мере расширения сценария).

Контекст:
- `[нижние]`
- `[верхние]`

## 4. Ограничения

1. В этом шаблоне реализована диспетчеризация и отображение, а не полный алгоритм управления ИТП.
2. Часть технологических статусов `S1_Status_*`, `S2_Status_*` требует подтверждения адресов по финальной карте регистров Saturn.
3. Право записи в уставки и режимы в текущую версию не включено намеренно.

## 5. Проверка перед пуском

1. Проверить связь Modbus с каждым Saturn.
2. Проверить, что значения T/AI обновляются в RAW.
3. Проверить, что виртуальные устройства повторяют RAW.
4. Проверить события `АВАРИЯ`/`СОСТОЯНИЕ` по тесту ошибок датчиков.
5. Убедиться, что поиск по логам работает по тегам `[сатурн]`, `[отопление]`, `[гвс]`.

## 6. Риски

- Неподтвержденные сервисные регистры могут давать некорректные значения.
- При смене `device id` RAW необходимо синхронно обновлять конфигурацию `SATURN_CONTROLLERS`.
- При подключении нескольких писателей к одному исполнительному каналу возможен конфликт логики.
