# Постоянный контракт разработчика/Codex для NL Project 3.x

## Разделение ответственности

**ChatGPT-координатор (до передачи задачи в Codex):**
- Ведёт [Issue #145](https://github.com/psv76/Neirolinks/issues/145) и [реестр незавершённых работ](docs/engineering/NLP_WORK_REGISTER.md).
- Сверяет **все** связанные Issues, PR, branches, включая docs-only и прототипы, а также TechDocs.
- Определяет текущее принятое состояние, зависимости, scope, target release, исходный SHA и критерии приёмки.
- Подготавливает **полное конкретное задание**, проверяет исполнение и интеграцию; до релиза сверяет все обещанные функции с фактическим UI/runtime.
- **Не перекладывает на Codex** инвентаризацию GitHub, восстановление контекста из разных чатов, формирование release coverage или принятие продуктовых решений.

**Codex / исполнитель конкретной задачи:**
1. Получает от координатора **одну готовую задачу**: ссылку на task brief, ветку, исходный SHA, разрешённые пути, ограничения, критерии и необходимые документы.
2. Читает **только относящиеся к задаче** исходники, документацию и тесты.
3. Реализует код и необходимые для него тесты; правит локальную нормативную документацию **только если это явно включено в scope**.
4. Выполняет предусмотренные проверки, сохраняет коммиты и сообщает точные SHA, тесты, изменения и остаточные блокеры. При недостаточном контракте возвращает узкий вопрос координатору.
5. **Не обязан и не должен** самостоятельно обходить все открытые Issues, PR, Git-ветки (в том числе docs/spikes), искать «забытые» задачи, систематизировать backlog или собирать release manifest.

**Отдельно:** Issue #145 — точка входа **координатора**, а не обязательное самостоятельное исследование для Codex. Если подготовленное задание ссылается на конкретный раздел #145 или документ реестра, Codex читает только указанный фрагмент по необходимости.

## Постоянные запреты

- Не принимать самостоятельно новые предметные или архитектурные решения.
- Не считать Issue, PR или chat history заменой действующей документации.
- Не изменять рабочие данные NL Project 1.0/2.0 из задач 3.x.
- Не подключаться к произвольному active DWG; live CAD — только по явно заданному target после identity check.
- Не выполнять неявный Save и не закрывать AutoCAD автоматически.
- Не объявлять Release/live-ready только по automated tests.
- Не переносить cache, `.venv`, `build`, `dist`, временные SQLite/DWG в source of truth.
- Внутреннее Python-имя `nl_project_2` — compatibility detail, а не пользовательская версия.

## Правила изменений

**Координатор** выбирает Issue, интеграционную/рабочую ветку, базы stacked PR и release scope.

**Codex** работает в заданной ветке, не создаёт Issue, не объединяет в `main`, не занимается очисткой веток и не выполняет release без отдельного разрешения в задании.

При изменении нормативных контрактов в scope нужно сохранить parity human docs ↔ machine resources.
