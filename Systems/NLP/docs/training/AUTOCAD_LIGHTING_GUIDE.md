# Практическое руководство: освещение в AutoCAD → NL Project 3.0

**Учебная редакция 0.1.** Здесь собраны только правила, которые подтверждены действующей документацией. Все ID и имена в примерах ниже **условные**; на реальном объекте их выдаёт ответственный проектировщик.

## 1. До начала черчения

**AutoCAD остаётся местом, где рисуется план.** NL Project 3.0 считывает и согласует структурированные данные DWG с моделью Project.

- Работаем в координатах **1 единица DWG = 1 мм** по X и Y. `INSUNITS` сам по себе не является пересчётом координат для NLP.
- `MOUNT_HEIGHT` — высота установки от **чистого пола**, в миллиметрах. Это не абсолютная строительная отметка.
- Если есть линейное изделие (`LIGHT_LED`), `LENGTH` в DWG также задаётся **в мм**.
- Используем **канонические block definitions** из согласованной библиотеки проекта. Важны **точное имя блока и точный набор ATTDEF**. Одинаково выглядящие самодельные условные обозначения не эквивалентны нашим блокам.
- Не меняем имена определений, не добавляем «удобные» собственные атрибуты внутрь канонического блока, не переносим legacy-поля.
- Поля `BUILDING` и `ROOM` должны согласовываться с карточкой объекта NL Project (помещение идентифицируется парой **здание + имя помещения**). Если помещение ещё не заведено или названия расходятся, уточняем, а не придумываем.
- Если DWG не подготовлен как корректный масштабированный исходник, **остановить импорт** и обратиться к ответственному проектировщику.

[Источник: AutoCAD Block Contract](../product/20_AUTOCAD_BLOCK_CONTRACT.md) · [Объект и помещения](../product/11_OBJECT_AND_ROOM_MODEL.md).

## 2. Выбор блока — сначала физический тип, затем функция

| Что хотим разместить | Имя canonical block |
|---|---|
| Накладной светильник, 230 В | `LIGHT_OUT_230V` |
| Встраиваемый светильник, 230 В | `LIGHT_IN_230V` |
| Накладной DALI-светильник, 230 В | `LIGHT_OUT_DALI_230V` |
| Встраиваемый DALI-светильник, 230 В | `LIGHT_IN_DALI_230V` |
| Светильник на треке 230 В | `LIGHT_TRACK_230V` |
| Светильник на треке 48 В | `LIGHT_TRACK_48V` |
| Светильник на DALI-треке 48 В | `LIGHT_TRACK_DALI_48V` |
| Линейное LED-изделие | `LIGHT_LED` |
| Линейное LED-изделие IP67 | `LIGHT_LED_IP67` |
| Физический трек 230 В | `TRACK_230V` |
| Физический трек 48 В | `TRACK_48V` |
| Физический DALI-трек | `TRACK_DALI` |
| Внутренний одноклавишный выключатель | `SW_IN_1` |
| Внутренний двухклавишный выключатель | `SW_IN_2` |
| Внутренняя двухкнопочная панель | `BTN_IN_2` |

Это **не полный перечень**. Полный перечень — 71 canonical definitions и их индивидуальные атрибуты — находится в [точном справочнике блоков](../autocad/AUTOCAD_BLOCK_ATTRIBUTE_REFERENCE.md). Точное имя смотрим там, а не выводим по аналогии.

`DEVICE_NAME` — человекочитаемое описание изделия. `LOAD_TYPE` — **нормализованное назначение нагрузки**, допустимо только в тех блоках, где такой ATTDEF предусмотрен.

У обычных светильников 230 В допустимые `LOAD_TYPE`:
- `LIGHT_MAIN` — основное;
- `LIGHT_DECOR` — декоративное;
- `LIGHT_TECH` — техническое;
- `LIGHT_NIGHT` — ночное;
- `LIGHT_STREET` — уличное.

Не пишите свободные синонимы вроде `ОСНОВНОЙ` в `LOAD_TYPE`, если допустимым кодом является `LIGHT_MAIN`.

## 3. Из чего состоит обычная точка освещения

Для `LIGHT_IN_230V` и `LIGHT_OUT_230V` **точный набор атрибутов** один и тот же:

```text
DEVICE_NAME
BUILDING
ROOM
MOUNT_HEIGHT
CABLE_ID
CABLE_TYPE
BOARD
CABLE_SOURCE
MOUNT_WAY
GOFRA_TYPE
GOFRA_COLOR
GOFRA_ID
LOAD_TYPE
LOAD_NAME
CALC_POWER
COMMENT_1
COMMENT_2
```

У этих блоков **нет** полей `BUS_POINT_ID`, `BUS_SOURCE`, `DEVICE_TYPE` и `PHASE`. Нельзя вручную добавлять их «на всякий случай».

Практическая группировка для заполнения:
- **Где и что**: `DEVICE_NAME`, `BUILDING`, `ROOM`, `MOUNT_HEIGHT`.
- **Какая линия**: `CABLE_ID`, `CABLE_TYPE`, `BOARD`.
- **Откуда физически идёт входящий кабель**: `CABLE_SOURCE`.
- **Как проложен входящий участок**: `MOUNT_WAY`, `GOFRA_*`.
- **Для чего нагрузка**: `LOAD_TYPE`, `LOAD_NAME`, `CALC_POWER`.
- **Пояснения**: `COMMENT_1`, `COMMENT_2`.

**Пустой атрибут не равен отсутствующему атрибуту в definition.** Даже если в конкретной вставке значение допускает пустоту, каноническое определение должно содержать точный набор ATTDEF.

## 4. Кабельные ID и физические связи

Обычная `CableLine` имеет базовый `CABLE_ID=XYY`; точка одной линии может иметь формат `XYY.ZZ`. Суффикс `.ZZ` — **не новый кабель**, а номер точки в той же линии.

- `BOARD` — **какому щиту принадлежит линия** в модели Project. Не означает автоматически, что щит является непосредственным источником входящего кабельного участка каждого устройства.
- `CABLE_TYPE` — тип физического кабеля; задаётся для базовой линии по выданным проектным данным.
- `CABLE_SOURCE` — **непосредственный источник входящего кабельного участка для конкретной точки**.

Примеры допустимого формата `CABLE_SOURCE`:
```text
<пусто>       линия непосредственно от корня в щите
111.01        обычная предыдущая точка линии
BOX.010       физическая коробка
902.003/K1    физический порт шинного полевого устройства
```

**Учебный пример 1 — два обычных светильника одной линии.**

Это демонстрация связности, **не готовое назначение ID для объекта**:

| Атрибут | Светильник 1 | Светильник 2 |
|---|---|---|
| canonical block | `LIGHT_IN_230V` | `LIGHT_IN_230V` |
| `CABLE_ID` | `111.01` | `111.02` |
| `CABLE_SOURCE` | пусто | `111.01` |
| `BOARD` | щит по заданию | тот же щит |
| `CABLE_TYPE` | кабель по заданию | тот же кабель |
| `LOAD_TYPE` | `LIGHT_MAIN` | `LIGHT_MAIN` |

Результат физической topology: **корень линии → 111.01 → 111.02**. В обоих устройствах заполняются здание/помещение/высота, характеристики нагрузки и доступные атрибуты трассы по заданию. Не назначайте несогласованные марки кабеля, мощность или щит «для примера» в реальном проекте.

[Источник: топология кабелей](../autocad/CURRENT_TOPOLOGY_ARCHITECTURE.md) · [кабельные сегменты](../product/22_CABLE_LENGTHS_AND_CONDUITS.md).

## 5. Выключатели и кнопки

В `SW_*` и `BTN_*` **нет** `CABLE_SOURCE`: одна физическая UTP может последовательно проходить через несколько точек. Для их общей линии `CABLE_ID` задаётся **2YY.ZZ**; `.ZZ` определяет порядок устройств, например:

```text
201.01 → 201.02 → 201.03
```

Это **одна линия**, а не три кабеля. В `SW_IN_2` существуют `KEY_1` и `KEY_2`, но `LOAD_TYPE` отсутствует. Назначения клавиш не угадываются — они берутся из функционального задания и действующего правила.

**Exact ATTDEF для `SW_IN_2`:**

```text
DEVICE_NAME
BUILDING
ROOM
MOUNT_HEIGHT
CABLE_ID
CABLE_TYPE
BOARD
MOUNT_WAY
GOFRA_TYPE
GOFRA_COLOR
GOFRA_ID
LOAD_NAME
KEY_1
KEY_2
COMMENT_1
COMMENT_2
```

Не добавлять `CABLE_SOURCE` и `LOAD_TYPE`. Для выключателей и кнопок число `KEY_n` должно соответствовать **конкретному типу блока по справочнику**, не по догадке.

[Источник: exact reference → Выключатели/Кнопки](../autocad/AUTOCAD_BLOCK_ATTRIBUTE_REFERENCE.md).

## 6. Светодиодная линия и DALI — следующий уровень

**LED:** `LIGHT_LED` / `LIGHT_LED_IP67` содержат `LENGTH` в мм и `LED_TYPE`, где допустимы только `MONO`, `CCT`, `RGB`, `RGBW`. Значение `MIX` в DWG не принимается вместо `CCT`. Прежде чем заполнять мощность и тип линии, уточните исходный паспорт.

**DALI 230 В:** `LIGHT_IN_DALI_230V` и `LIGHT_OUT_DALI_230V` содержат **две независимые физические сети**: обычное питание (`CABLE_*` и `CABLE_SOURCE`) **и** DALI (`BUS_POINT_ID`, `BUS_SOURCE`, `BUS_CABLE_TYPE`, `BUS_MOUNT_WAY`, `BUS_GOFRA_*`). Не подменяйте одну сеть другой.

Для DALI:
- `BUS_POINT_ID = 905.001` — условный пример точки на шине `905`;
- `BUS_SOURCE = 905.000` — явная связь с её корнем;
- ветвление разрешено, но parent должен существовать и принадлежать **той же шине**;
- `BUS_POINT_ID` — не DALI short address.

Для RS-485: линейный порядок определяется числовым суффиксом `BUS_POINT_ID=9YY.ZZZ`, а не `BUS_SOURCE`. Нельзя переносить DALI-логику на RS-485.

Для трековых светильников соединение *через трек* не создаёт фиктивного отдельного внешнего кабеля/трубы. Следуйте exact ATTDEF-set конкретного трека/светильника.

[LED](../product/21_LED_LINES_AND_PWM_EQUIPMENT.md) · [DALI/RS-485](../product/23_DATA_BUS_TOPOLOGY.md) · [точная модель](../autocad/CURRENT_TOPOLOGY_ARCHITECTURE.md).

## 7. Прокладка и трубы

У обычной кабельной линии `BOARD` и `CABLE_TYPE` — свойства **линии**, а `MOUNT_WAY`, `GOFRA_TYPE`, `GOFRA_COLOR`, `GOFRA_ID` — свойства **входящего физического сегмента**.

Принятые способы прокладки: `По полу`, `В стяжке`, `По потолку`, `В стене`, `В брусе`, `В кабель-канале`. Выбор и детализация трубы — по заданию объекта и [нормативному разделу 8](../product/22_CABLE_LENGTHS_AND_CONDUITS.md), а не по предположению нейросети.

Не рисуйте произвольные полилинии с ожиданием, что они автоматически создадут физическую topology NLP. Связи определяются ID и атрибутами.

## 8. Проверка перед сдачей DWG

1. Масштаб: одна drawing unit по X/Y соответствует 1 мм.
2. Все устройства — известные **canonical block definitions**, не внешне похожие замены.
3. Имена блоков и существующие ATTDEF соответствуют [exact reference](../autocad/AUTOCAD_BLOCK_ATTRIBUTE_REFERENCE.md).
4. `BUILDING`, `ROOM`, `MOUNT_HEIGHT` заполнены по согласованным данным.
5. Каждая используемая `CABLE_ID` однозначна по своей линии/точкам; `BOARD` и `CABLE_TYPE` согласованы внутри линии.
6. `CABLE_SOURCE` существует только там, где предусмотрен; ссылки не указывают на отсутствующие точки и не создают циклов.
7. У выключателей/кнопок `CABLE_SOURCE` отсутствует, порядок задан `.ZZ`.
8. `LOAD_TYPE`, `LED_TYPE` и другие перечисления — только допустимые для блока значения.
9. DALI и обычные электрические кабели не смешаны.
10. После изменения block definition существующие INSERT должны быть синхронизированы штатными средствами AutoCAD.
11. DWG **сохранён пользователем**; ответственный проектировщик знает, с каким target DWG работать.
12. Неясные проектные решения записаны отдельным списком, не заменены выдуманными значениями.

**При синхронизации:** обычные односторонние изменения обрабатываются автоматически при `Обновить`; настоящий конфликт/неопределённость требует действия пользователя. После записи из NLP в AutoCAD **DWG автоматически не сохраняется**.

[Источник: DWG Sync](../product/25_DWG_SYNCHRONIZATION.md) · [проверка definition](../autocad/AUTOCAD_BLOCK_ATTRIBUTE_REFERENCE.md).
