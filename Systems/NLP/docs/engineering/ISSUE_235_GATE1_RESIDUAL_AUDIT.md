### Воспроизведение и правильные критерии исправления

`python -B Systems/NLP/tools/probe_issue235_height_evidence.py` читает pinned pure source main `8f566f7a1eddb2c7eb4242dd275cdd775ca79a89` и #231 `ff9b0ef52f89d5f9445b55b468414adbaf8a331e`. Git objects должны быть доступны локально. Application/SQLite/AutoCAD не импортируются. Exit 0 означает воспроизведение дефекта, не acceptance.

При X1=0/X2=2000, Y=0, H1=H2=1000 мм, B=-250 мм, R=3 м: норматив 6 м; main 6 м; #231 5,5 м. AC-033: main 8,4 м; #231 8,1 м. Это подтверждает ошибку формулы на существующем нормативном примере.

Ранее отмеченное отсутствие B в required/signature CEILING **не является самостоятельным дефектом правильной формулы**: потолок от B не зависит. Нельзя исправлять это добавлением обязательного B. Для FLOOR основание обязательно; для CEILING обязательны H/R, а сравнение нескольких владельцев должно включать только фактические входы соответствующей формулы.

Требуемые регрессии будущего исправления #231:

- C=R×1000, 6 м и AC-033 8,4 м; изменение только B не меняет потолок.
- Отсутствующий B не блокирует CEILING при известных H/R, но блокирует FLOOR. Отсутствующие H/R для CEILING не подменяются нулём.
- Разные H/R у нескольких owner дают ambiguity; разные только B не создают ложный конфликт CEILING.
- Ordinary/BUS parity, сохранение ручных длин, assignments и остальных исправлений Decimal/запасов #218/#231.
- Не конвертировать существующие MOUNT_HEIGHT/Room-поля. Межуровневые переходы не выводить из относительных высот догадкой; это не причина блокировать обычный подтверждённый расчёт.

Production-код #231 в этой работе не менялся: действует исходный запрет пользователя. Нормативный смысл H1 разрешён; реализация/регрессии остаются открытым техническим gate. Runtime/Windows/live PASSED не заявлен.

## Остальные границы

- **Транзит:** последовательные однозначные BOX разрешены; ветвь с неизвестной принадлежностью — `Требует внимания`, без guessed геометрии/длины/Conduit. Порядок BOX не сообщает segment-specific MOUNT_WAY/GOFRA. Не копировать ordinary свойства коробки на все транзитные кабели. Сохранить подтверждённые Project facts; новый ATTDEF/branch-синтаксис требует решения, сейчас не нужен.
- **Legacy passive BUS_POINT_ID:** old point → unique BOX/TRACK mapping должен охватывать downstream BUS_SOURCE, endpoint/segment owners, accepted baselines, assignments и ручные overrides. Дубликат/неизвестный owner/cross-bus — отказ от зависимой записи, без удаления старого графа. Не создавать short address пассивной точке. Это implementation/migration gate, не новый выбор DALI-модели.
- **Owners:** #228 защищает единственную DWG GOFRA-проекцию вставки от last-writer-wins; #229 блокирует неподдержанный BUS FIELD_DEVICE mirror. Новые passive BOX/TRACK/transit нельзя считать покрытыми этим стеком автоматически. Нужны no-op/rollback/owner roundtrip проверки в #237.
- **PSU и Stretch:** внешний PSU не подменять фиктивным узлом; PSU_ID не принят. LENGTH ATTDEF не доказывает Stretch readback. Нужны отдельно разрешённые CAD scope/acceptance, не исправление документа догадкой.
