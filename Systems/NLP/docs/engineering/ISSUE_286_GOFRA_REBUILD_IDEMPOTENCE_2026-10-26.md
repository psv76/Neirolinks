# Issue #286 — идемпотентный GOFRA_ID при пересборке объекта (2026-10-26)

## Действующее решение и границы

Объект `05 44 Богданович`, `House_2/working.dwg`. Новый объект в SQLite
предлагается **пересобрать** по авторитетному текущему DWG без пересмотра
`CABLE_ID`. Из старого состояния объекта сохраняются **только**
23 помещения (названия, отметки, высоты, цвета) и 10 настроек проекта
(включая шесть параметров длины и запасов). Старые WB экземпляры, BUS roots,
топология, BOARD назначения, CableLine, Conduit и старые объединения труб
не переносятся. Фактический первый импорт — **только на тестовой копии**;
рабочие SQLite/DWG по-прежнему не изменены.

В текущем чертеже `GOFRA_ID` пока не очищен. Для проверки использован
снимок DWG, в котором в памяти виртуально обнулены
`GOFRA_ID`/`BUS_GOFRA_ID`, без записи в AutoCAD.

## Принятый механизм

1. Если у нового обычного физического CableSegment задана труба по способу
   прокладки, но `GOFRA_ID` в DWG пуст, Project создаёт индивидуальный Conduit
   со стабильным ID и `path_json.origin=AUTO_SEGMENT`.
2. На повторном Preview пустой DWG `GOFRA_ID` и заполненный автоматический
   Project `GOFRA_ID` дают **`PROJECT_CHANGED`**, а **не ошибку**
   `BOTH_CHANGED_CONFLICT`. Это **задание на Project→DWG запись**,
   которое нельзя скрывать статусом `EQUAL` — иначе штатная двусторонняя
   синхронизация станет невозможной.
3. Повторный выборочный Apply по другим линиям **не должен перенумеровывать
   или удалять** Conduit с `origin=AUTO_SEGMENT`, уже назначенный тому же
   физическому сегменту. Участку без назначения выдаётся новый свободный ID.
   Если у существующей авто-трубы тип/цвет противоречит новому DWG,
   Apply **fail-closed**, без молчаливой перенумерации.
4. Явный ручной `GOFRA_ID` в DWG остаётся авторитетным входом для
   проверки/разрешения реальных конфликтов. Нельзя трактовать все пустые
   `GOFRA_ID` как согласие на смену ранее ручного назначения.
5. Project→DWG writeback — отдельный строго подтверждаемый шаг штатным
   `plan_project_to_dwg` и `execute_write_plan`. Никакого AutoCAD Save/Close.
   В рамках этой задачи физическую DWG **не изменяли**.

## Не относится к этому узкому ремонту

- `25` `LAYER_FUNCTION_GROUP_MISMATCH` и `23`
  `BUS_TYPE_REQUIRED` — независимые диагностические категории.
  Нельзя объявлять весь DWG **INVALID=0** до их предметной обработки.
- Корневые WB/900 BUS пользователь планирует заново — старая BUS-топология
  не должна тайно восстанавливаться из прежней Project.
- `BUS_GOFRA_ID` для будущих вновь созданных BUS-контуров требует
  отдельной приёмки, когда появятся новые BUS roots; это не доказательство
  готовности всех будущих BUS маршрутов.
- Чистая тестовая пересборка сама по себе не является разрешением на
  изменение рабочей SQLite, DWG или установку недопринятого Routes B UI.
