# Issue #286 — видимые ошибки DWG-синхронизации и существующий cross-line EL_BOX (27.10.2026)

## Нормативное поведение кнопки «Обновить»

1. Сканирование DWG, Preview и применение — разные операции. **Ошибка
   транзакции означает, что все её выбранные изменения откатились**, даже
   если другие строки в Preview были корректны.
2. Если автоматический `DWG → Project` Apply завершился ошибкой, **сразу
   показать причину в модальном предупреждении** и разместить тот же полный
   текст в **первой строке** окна «Ошибки и нерешённые изменения DWG», а
   также над таблицей в отдельном читаемом поле. Не скрывать ошибку за
   списком отсутствующих BUS roots и сотнями иных предупреждений.
3. В статусе явно показывать **«ошибка импорта — изменения не применены»**.
   Нельзя выдавать состояние «Актуально» после неудачного Apply.
4. Если ошибка ссылается на `BOX.XXX`, подсказать идентификатор физической
   коробки, линию владельца и зависимые линии, найденные в **данном
   проверенном снимке DWG**. Не утверждать, что Project не содержит коробку
   только по отсутствию её в наборе текущего выборочного применения.
5. Ошибка записи диагностического журнала не должна маскировать настоящую
   ошибку Apply; исходное сообщение остаётся доступным в UI.
6. **`Project → DWG` никогда не выполняется автоматически** в составе
   нажатия «Обновить». Ожидающие изменения показаны как отдельное число.
   Если в одном Preview есть входящий импорт, пользователь завершает его
   и сканирует повторно перед outbound write; это исключает запись на
   устаревшем Preview. Если входящих изменений нет, явная кнопка
   **«Записать в DWG…»** запрашивает отдельное подтверждение
   (ответ по умолчанию — «Нет»). По этой операции AutoCAD-файл **не
   сохраняется автоматически**.
7. Исправление исключает автозапись 313 сгенерированных `GOFRA_ID`,
   пока пользователь её явно не подтвердит.

## Причина сбоя № 864 / BOX.024

Наблюдение на исходной рабочей версии 26.10.2026:
- текущий INSERT `SOCKET_ETHERNET`, handle `858E5`, line `864`:
  `CABLE_TYPE=FTP 6e`, `MOUNT_HEIGHT=6500`;
- база: `FTP 5e`, `3000`;
- Preview: два корректных `DWG_CHANGED`;
- `sync-apply.jsonl` дважды зарегистрировал Apply=NOT_APPLIED, причина:
  `Распределительная коробка BOX.024 ещё не принята в Project`.
- В действующей SQLite `BOX.024` **существует** (handle `B5CC`,
  line 114), имеет `cable_point`, membership и owner endpoint. От неё
  идут розетки линии `125.01`.
- При выборочном Apply target-line 125 (без активной source-box 114)
  старый `_materialize_snapshot` искал owner endpoint **только
  среди точек текущего selection**, а не среди уже принятых в SQLite.

Исправление: для cross-line физической коробки при отсутствии owner
в `endpoint_ids` искать **только принятый и однозначный**
`cable_topology_endpoint` с совпадающими `logical_identity`,
`cable_line`, `point_kind=EL_BOX` и существующей membership от
source handle; **не создавать фиктивную непроверенную точку**. Если
принятого owner нет/владение не совпадает — оставить явную ошибку
без частичного изменения SQLite.

## Приёмка и границы

- На **копии реальной базы** одновременное изменение 864 CABLE_TYPE
  и высоты плюс изменение геометрии розетки `125.01` через источник
  `BOX.024` теперь PASS; ранее на такой же копии был
  `DwgSyncError`, rollback.
- Новые синтетические регрессии: accepted cross-line source remains
  byte-identical, source not accepted — fail-closed, видимость ошибки
  в первой строке/баннере UI, диагностический контекст BOX.024/114/125,
  обратная запись без подтверждения невозможна.
- 98/98 выбранных CAD-sync/UI регрессионных тестов PASS, плюс четыре
  дополнительных теста отсутствия outbound write на failed Apply PASS.
  Три старых теста, не относящихся к этому изменению,
  намеренно исключены — они **воспроизводимо падают и на исходном
  main f03b099** (неполная проверка root_endpoint и старое ожидание
  3 строк таблицы вместо 2). Не считать весь suite зелёным.
- Рабочую SQLite, `working.dwg`, AutoCAD при диагностике и ремонте
  **не менять**. Перед переключением runtime установить исходники из
  принятого GitHub main, выполнить startup smoke на SQLite-копии.
- Следующий реальный приёмочный шаг — открыть уже обновлённую
  NL Project, нажать «Обновить», убедиться, что по линии `864`
  `FTP 6e`, `MOUNT_HEIGHT=6500`, сообщения читаемы, в DWG
  не появились самовольные `GOFRA_ID`. Это не выполнено в рамках
  copy-only tests.
