# Критерии приёмки MVP NL Project 2.0

## Актуализация Repair 08

Для topology/AutoCAD contour действуют exact machine contract `3.0.0`/71 definitions, schema head `000000000011` и active equipment catalog Repair 05 `18 passports / 31 products`. Ordinary root определяется `CABLE_SOURCE` и derived `ROOT_ENDPOINT`; field-port projection обязана reconciles как тот же edge. DALI root — `.000` с ветвлением, RS-485 points — `.ZZZ` с линейным порядком; physical `BusSegment` учитывается отдельно. Старые формулировки `.RKn`, `OUT_*`, `SENSOR_M1W2`, 17/30 и contract 2.2.0 ниже считаются superseded там, где противоречат этому разделу.

## 1. Назначение

Критерии применяются к рабочей версии MVP на реальном объекте `05 44 Богданович`. Каждый результат подтверждается наблюдаемым состоянием интерфейса, сохранёнными данными проекта, объяснимой трассой проверки или контролируемым повторным чтением DWG. Способ внутренней реализации критериями не задаётся.

## 1.1. Evidence policy

Все 60 технических критериев остаются обязательными, но после решений `UI-DR-A…G` они не являются достаточным условием пользовательского MVP. Дополнительно обязательны UI acceptance criteria из `WORKING_UI_IMPLEMENTATION_PLAN.md` и representative пользовательская приёмка без сопровождения. Колонка `Действие пользователя` описывает требуемый сценарий и наблюдаемое поведение системы, но не задаёт обязательный канал доказательства для каждого пункта.

По `TEST_STRATEGY.md` каждый критерий получает evidence type `AUTOMATED`, `MANUAL_REQUIRED` или `MIXED`. Automated evidence допустимо только когда test/application/E2E contour воспроизводит тот же public/domain result без специальных production-ветвей по тестовым ID и без подмены реально необходимого внешнего поведения mock-success.

Реальная ручная приёмка сохраняется для representative workflows, где требуется человек или live external application. Технический статус перенесённого baseline и ограничения приёмки указаны в `docs/STATUS.md`; перенос не закрывает пользовательскую приёмку.

## 3. Итог прохождения

MVP принимается только при успешном прохождении всех 60 технических критериев, всех обязательных `UI-AC-*` из `WORKING_UI_IMPLEMENTATION_PLAN.md` и отдельной representative пользовательской приёмки. PASS может опираться на automated, manual или mixed evidence согласно `TEST_STRATEGY.md`; отсутствие 60 отдельных ручных действий пользователя само по себе не является основанием NOT EXECUTED, если технический критерий полностью доказан допустимым automated evidence. Это не заменяет обязательный ручной UI workflow без сопровождения. Предупреждение или `DATA_INCOMPLETE`, прямо разрешённые продуктовым документом, являются ожидаемым результатом соответствующего критерия и не могут быть произвольно преобразованы в успех либо блокировку.

Критерии не требуют скрытого автоматического подбора, полного расчёта нагрузок объекта, балансировки фаз, селективности, выходного DWG щита, PDF, ПНР или коммерческого раздела. Обязательные согласованные массовые операции не являются скрытым автоподбором. Требование к file-export кабельного журнала определяется только `GATE-UI-002-CABLE-JOURNAL-EXPORT-FORMAT`.
