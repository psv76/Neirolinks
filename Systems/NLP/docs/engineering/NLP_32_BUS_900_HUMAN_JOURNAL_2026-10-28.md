# NLP 3.2 — инженерный смысл шин 900 в кабельном журнале

Дата: 2026-10-28. Канонический репозиторий: `psv76/Neirolinks`, ветка `main`, путь `Systems/NLP`.

## Проблема

Пользователь не видит физический щит-источник, направление обслуживания и инженерное назначение шин `9YY`. До исправления `BusService.journal_cards()` выводил тип интерфейса и выдуманное резюме аппаратных типов: `RS485 · SENSOR_MSW / WB_M1W2`. В DWG уже сохранены `BUS_ID`, `LOAD_NAME` и `ROOM`; но сервис журнальной проекции не читал их при формировании родительской строки.

## Реальные подтверждённые данные объекта NL.05.441.03

- `903`: источник **ВРУ-20 · WB-21 / RS485-1**. Участники имеют `LOAD_NAME`: **Датчик комбинированный MSW**, **Преобразователь WB-M1W2**. Помещения: Постирочная, Прихожая, Санузел.
- `904/905`: источник **ЩР-21 · WB-23 / RS485-1, RS485-2**; направления по помещениям, включая Детская 1/2, Будуар 1/2 и ванные детских.
- `921`: источник **ЩР-21 · WB-24 / RS485-1**; пять `CABLE_OUTLET_BUS` с различными `LOAD_NAME` электрокарнизов (окна/дверь). Нельзя объявлять один из пяти `LOAD_NAME` названием всей шины.
- `931`: источник **ЩР-21 · A05 / DA1**; `LOAD_NAME` = **Подсветка карниза** у трёх участников DALI.
- `941`: источник **ВРУ-20 · A04 / DA1**; `LOAD_NAME` = **Свет гостиная 1**.

Источник щита получается строго по `bus.root_resource_id → instance_resource → project_instance.board_id → board.designation`. Для WBE2-I-RS485-ISO без прямого `board_id` щит определяется по **сохранённому MODULE_INSTALLATION** между `INTERNAL_EXPANSION_MODULE_ATTACHMENT` и `INTERNAL_EXPANSION_SLOT` контроллера. **Никаких проверок/переносов гипотетического WB-23/MOD3 на реальном объекте.**

## Внесённое изменение

- `BusService._journal_human_context` в одном read-only проходе получает реальные источники шин, реальные физические щиты, все связанные `bus_endpoint → field_device` и `LOAD_NAME` каждого участника; чужие `BUS_ID` игнорируются, отсутствующие `LOAD_NAME` не заменяются выдуманным названием.
- Родительская строка в столбце «Источник»: **`Щит · Контроллер/порт`**; полный путь в tooltip. Если физический щит неизвестен, вместо догадки остаётся технический порт.
- В столбце «Назначение»: первое/второе уникальное значение `LOAD_NAME` и счётчик остальных (если есть). Полный список `9YY.ZZZ: LOAD_NAME` при наведении.
- В дочерних строках `9YY.ZZZ` в первую очередь отображается `LOAD_NAME` соответствующего физического устройства, а затем — `DEVICE_NAME` только как fallback. Топология, кабельные данные и позиция точки не меняются.
- Фильтр «Щит» группирует физические BUS по щиту, а не создаёт отдельный фильтр для каждого порта. Поиск по линиям работает и для полного списка `LOAD_NAME` за пределами короткого заголовка.
- Столбец «Помещение» остаётся фактическим местом назначения по каноническим или исходным `ROOM`. Если фактический конечный щит не задан физическими данными, **он не изобретается по месту**.
- Никаких миграций схемы/паспорта; только изменён read-model и Qt-рендер журнала. Работающая SQLite и DWG **не изменены**, шина 903 физически **не перенесена**.
