# Issue #216 — полная спецификация с одним источником на физическую Conduit (read-only)

**Статус:** предпросмотр, не выпуск в закупку. Source of truth: `main`; staged PR #303 → #313 → #314 → #319. Не заменяет Q03/Q06 acceptance или промышленную приёмку.

## Цель

В дополнение к `preview_single_conduit_specification` теперь есть
`SpecificationService.preview_integrated_conduit_specification(project_id)`.
Она собирает **полный** набор источников по уже используемым правилам
`SpecificationService.build()` и только в памяти заменяет старые физические
трубы (`CONDUIT` и `BUS_SEGMENT_CONDUIT`) на **ровно один `CONDUIT.id`**
для каждой активной физической трубы. Все остальные источники, включая
`CABLE_LINE`, `BUS`, поле, оборудование, LED и материалы, сохраняются без
изменений. `build()`, экспорт, `source_navigation` и закупочная ведомость
не изменены.

### Защитные требования

- Сверка project revision в начале и в конце расчёта. Устаревший расчёт
  отвергается, никакой автоматической записи нет.
- Любая незакреплённая BUS-потребность в трубе (источник
  `BUS_SEGMENT_CONDUIT` без назначенной активной Conduit) выдается как
  блокирующая ошибка, а не теряется без предупреждения.
- Не допускаются повторные physical `Conduit.id`, пропущенные физические
  Conduit, неопознанные виды источников, фиктивная числовая длина для
  `BLOCKED_*` и повторные ключи любых источников.
- `146.PP20` остаётся отдельной физической трубой, содержит CABLE 204/205,
  сохраняет `quantity=None` и блокирующую `PHYSICAL_CONDUIT_QUANTITY_BLOCKED`.
  `INCOMPLETE_SHARED` не разрешается выбором min/max/sum кабельных длин.
- Источники 80 BUS Conduit используют кандидаты расчёта Q08, но весь
  предпросмотр имеет `preview_only=True`, **`can_publish=False`**.
- Наличие `quantity=None` в одной из однотипных позиций приводит к
  `None` у соответствующей сгруппированной закупочной строки, не к
  количеству с пропущенным участком.
- Никаких изменений `SQLite`, `DWG`, схемы, каталогов и назначений.
