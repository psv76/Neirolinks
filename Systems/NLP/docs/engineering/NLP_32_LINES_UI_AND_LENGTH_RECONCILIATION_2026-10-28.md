# NL Project 3.2 — читаемость линий, физические BOX и расхождения длины

Дата: 28.10.2026. Исходники: `psv76/Neirolinks/main/Systems/NLP`.

## 1. UI таблицы линий

- Фильтры разнесены на строку поиска и строку независимых подписей. Отдельная дублирующая подпись поиска убрана (подсказка находится в самом поле), исключая наложение при масштабировании Windows.
- Выделенный текст — **#FFFFFF**, фон **#174A75**. Контраст **9,24:1** (нормальный текст). Нормативный ориентир: WCAG 2.2 SC 1.4.3 минимум 4,5:1 для обычного текста; SC 1.4.11 минимум 3:1 для важных визуальных состояний элемента. Источник: https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html
- Нейтральный невыделенный текст остаётся тёмным. Старый Qt stylesheet + ForegroundRole не гарантировал белые символы при активном/наведённом ID. Добавлен `ContrastCellDelegate`: реальные glyphs выбранной/наведённой ячейки рисуются `#FFFFFF` непосредственно на `#174A75`; проверено **пиксельным Qt viewport/grab тестом**, а не только значением палитры. При снятии выделения возвращается обычный текст. У цветных чипов помещений сохраняется свой собственный контраст.
- Высота обычной строки **30 px** (не растягивать массово до 39), ширины столбцов умеренные и редактируемые, сохранение пользовательского layout не удалено.
- Ячейки назначения уже поддерживают полный tooltip; зависимые подсказки (длина/физический источник) сохраняются.

## 2. Откуда сообщения «нет длины»

На копии реальной SQLite обнаружено **115 из 329** CableSegment с расхождением между `calculated_length_m_decimal` и повторным прочтением геометрии `segment_geometry_diagnostics`. Это не «пустое поле»: геометрия сохранена, но результаты **несогласованы**.

Контроль по резервной копии **27.10.2026**, созданной до текущих исправлений UI: **116 из 328** сегментов уже имели ту же проблему и тот же профиль повторяющихся отклонений. В актуальной копии — 115 из 329. Значит, текущая верстка таблицы не создала эти расхождения; они существовали раньше.

У большинства несовпадений наблюдаются точно повторяющиеся сдвиги **±0,2888 м** и **±0,3578 м** на различных линиях/щитах. У некоторых разница меньше миллиметра — погрешность округления. Это системный эффект, не доказанное ручное перемещение отдельного щита.

Код `CableService.topology` признавал **любое ненулевое** отличие старого и текущего результата «устаревшим», возвращал `cable_length_m=None` и UI писал «⚠ нет длины». Кнопка «Обновить» обновляет таблицу, а **не выполняет пересчёт исходного CableSegment**.

Исправлено только представление:
- если изменение меньше или равно **0,001 м**, это шум округления, статус не переводится в INCOMPLETE;
- существенное расхождение отображается как **сохранённые метры с пометкой «⚠ устар.»**, а tooltip показывает сохранённое и требуемое текущей геометрией; старые метры **не добавляются автоматически** к новым валидированным итогам;
- есть отдельное действие «Пересчитать выбранную линию», **только по выбору инженера**; массового запуска по открытию/обновлению нет. Добавлено действие «Проверить устаревшие длины» с read-only-preview и защищённым групповым пересчётом по явному подтверждению.

**Причина расхождения установлена по журналу dwg_scan/dwg_observation.** Сканирование от **26.10.2026 20:37:36** сообщало координаты:
- ЩР-21 `BOARD_IN`, handle `3BDFD`: Y = **11753,5 мм**;
- ЩР-22 `BOARD_IN`, handle `C12D`: Y = **15737,4 мм**.

Следующее принятие скана **26.10.2026 22:40:41** сообщило для тех же handles **11464,7 мм** (−288,8 мм) и **15379,6 мм** (−357,8 мм). Совпадает с отклонениями сохранённых расчётов, составленных по более ранней геометрии. Между этими сканами изменились координаты **40 блоков** из 584 общих handles, а также число наблюдений 585→620. Версии адаптера и контракта прежние (`1.1` и `3.2.0`), hashes принятых снимков различаются. Данные не доказывают, **почему** изменения геометрии появились в DWG/COM (изменение чертежа, динамика блоков, обновление базы вставок и т. д.). Нельзя утверждать, что пользователь сейчас перемещал щиты.

**Системный дефект синхронизации/производных данных:** после изменения координат BOARD в DWG→Project сохранённые сегментные длины некоторых зависимых кабельных линий остались со старыми геометрическими величинами. Табличное «Обновить» **не пересчитывает** и не должно тайно менять эти метры.

**Самостоятельное восстановление через UI:** добавлено **«Проверить устаревшие длины»**. Сначала READ-ONLY сравнение старого расчёта с Project-геометрией и предпросмотр изменений. Разница ≤0,001 м считается погрешностью округления; для существенных отклонений требуется явное согласие (по умолчанию **Нет**), затем `create_verified_backup` рабочей SQLite и только после этого избирательное `CableService.recalculate(segment_ids=…)`. Не требуется ChatGPT или ручное редактирование БД. На КОПИИ рабочей SQLite **96 существенных отклонений в 93 линиях → 0** после пересчёта; все 207 CableLine IDs, 329 сегментов, 415 труб, 329 назначений в трубах, 27 шин сохранены, integrity_check=ok, FK=0. **На рабочей базе пересчёт не выполнялся.** Если инженер считает координаты из скана неверными, применять пересчёт нельзя, пока не проверен источник геометрии.

**Остающаяся инженерная задача:** делать точечный пересчёт всех линий, зависящих от изменённого BOARD, непосредственно при разрешённой DWG-синхронизации; это не решается простым обновлением таблицы и требует отдельной regression acceptance.

## 3. «Линия не раскрыта» и UUID

Реальная причина: у линий 125 и 131 есть `cable_topology_endpoint.cable_point_id`, указывающий на **существующий общий физический BOX** другой линии. Старый `CableService.topology` выбирал только `cable_point.cable_line_id == выбранной линии` и падал с сырым `KeyError('<UUID>')`.

- Линия **125** ссылается на общую BOX.024 другого кабельного направления.
- Линия **131** ссылается на общую BOX.010.
- Чтение точек исправлено: дополнительно загружаются **упомянутые данной линией point IDs** строго внутри текущего Project. Исходный владелец физической точки остаётся прежним, дубликаты точек и кабелей не создаются.
- Если указатель физической точки действительно неразрешим, UI получает понятное описание и статус INCOMPLETE вместо KeyError UUID.

Проверка `CableService.topology` для реальной копии линий 125/131 — PASS, без изменения DB.
