# Issue #286 — аварийное закрытие при «Обновить» после добавления DALI (2026-10-27)

## Подтверждено

- Работающая NL Project 3.1 (`main de686e1`) завершилась неуправляемым
  падением процесса `pythonw.exe` в Windows около 12:58:16 (+05)
  непосредственно после нажатия «Обновить».
- Windows Application Error 1000 и WER 1001:
  `Qt6Gui.dll 6.11.1`, адрес `Qt6Gui+0x6a87a0`,
  `0xc0000005` (access violation) и последующее `0xc000041d`.
  Обе записи относятся к одному PID 31724. Локальные дампы:
  `%LOCALAPPDATA%\CrashDumps\pythonw.exe.31724.dmp` и
  `pythonw.exe(1).31724.dmp`. Дамп показывает переход на
  некорректный адрес через машинную инструкцию `jmp rax` внутри
  Qt; это **не Python exception** и его нельзя поймать QMessageBox.
- `operations.jsonl` до падения завершил AutoCAD `document_identity`
  и `fingerprint` около 12:58:15, а новой записи `DWG_TO_PROJECT`
  Apply не обнаружено. Не утверждать, что именно DALI-паспорт или
  данные SQLite вызвали нарушение доступа к памяти.
- Рабочая SQLite: schema head не менялся,
  `PRAGMA integrity_check=ok`, FK=0, 25 шин всего:
  **13 RS-485 и 12 DALI**. Новые DALI-связи сохранились.
- Проверенная online SQLite backup **перед кодовым ремонтом**:
  `D:\NLP_3_BACKUPS\issue-286-dali-qt-crash-20261027\pre_crash_repair_20261027T081151Z.sqlite`,
  SHA256 `8e8312f3db3e54eda16d2621d742e327bf744f346d3d62a965d2dd5fcfb0ed89`.
- Падение оставило одну открытую `work_session`, id
  `72579490-08a1-48ac-8c18-1f84a5431618`, старт
  `2026-10-27 07:47:08 UTC`. Восстановление требует сохранения интервала
  до документированной секунды Windows crash `07:58:18 UTC`, не удаления
  строки и не продления времени до момента ремонта.

## Исправление — только UI-поток, без изменения CAD/DB контрактов

`presentation/background_operation.py` прежде передавал
`progress=self.progress.emit` непосредственно в
`ThreadPoolExecutor` worker. При сканировании DWG worker мог обращаться
к живому Qt signal, а UI-объект/диалог прогресса мог уничтожаться или
перестраиваться. Это **опасная связка жизненного цикла Qt**; дамп не
доказывает, что она была единственной причиной конкретного падения.

Теперь worker публикует только простые Python события в
потокобезопасный `SimpleQueue`. Существующий `QTimer` GUI-объекта
внутри главного Qt-потока забирает накопленные события и вызывает
`self.progress.emit` там же, **до** `completed/failed/cancelled`.
После уничтожения Qt receiver worker больше не вызывает его API.
Не меняются `DwgSyncService`, topology, типы шины и обратная запись в DWG.

## Copy-only acceptance

- Тесты `tests/operations/test_background.py`: рабочая нить отлична
  от GUI нити, все 80 уведомлений доставлены в GUI, допускается
  уничтожение Qt-контроллера при продолжающемся worker без исключения.
- Focused Qt/operations checks **6 PASS**.
- Related operations/objects/sync/DALI GUI checks **37 PASS**.
- Нативное Qt Windows приложение на **копии реальной SQLite** (25 шин,
  12 DALI) и read-only AutoCAD DWG: вся цепочка «Обновить» →
  сканирование → Preview → 3 импортируемых изменения →
  диалог решений **PASS, process exit 0**. Наблюдения:
  10884 сравнений, 153 диагностических сообщения,
  321 ожидаемая Project→DWG запись (она НЕ выполнялась),
  ни одного шага изменения реального DWG/SQLite.
- Не считать единичный успешный native smoke абсолютной гарантией
  отсутствия редкого Qt native crash. После установки проверить
  рабочее окно и повторное пользовательское действие.

## Recovery/операционные ограничения

- AutoCAD 2024 и `House_2/working.dwg` не изменять.
- Устанавливать GitHub `main` только после тестов/PR и с защитой
  рабочего репозитория от dirty changes.
- Оставшуюся после аварии `work_session` закрывать **только через
  `WorkTimeService.pause(reason=PROCESS_CRASH_RECOVERY)`** при
  доказанном отсутствии работающего NLP-процесса и verified backup;
  момент окончания = время WER crash, не текущее время. Сохранить
  строку и историю интервала. Это отдельный контролируемый шаг
  исправления рабочих данных (не миграция schema).
- После исправления вернуть программу пользователю открытой;
  live «Обновить» не запускать автоматически без отдельного разрешения,
  поскольку это меняет данные Project по DWG.
