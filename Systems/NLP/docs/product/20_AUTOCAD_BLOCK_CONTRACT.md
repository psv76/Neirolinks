# Блоки планировки AutoCAD NL Project 3.0

## Целевой AutoCAD-контракт NLP 3.0 — #235 (draft до принятия PR #236)

Целевой единый **CAD authoring contract `3.2.0` / 72 canonical definitions** составлен из #235 (пассивные DALI BOX/TRACK) и #227 (`CABLE_OUTLET_BUS`). Обе независимые ветки ранее использовали обозначение `3.1.0` для разных составов каталога, поэтому авторский объединённый набор выделен отдельно. **Это не активный runtime-контракт NLP**. В действующем `main` до принятия #235 остаётся `3.0.0`. Exact canonical names, ATTDEF sets и `LOAD_TYPE` allow-lists определяет [AUTOCAD_BLOCK_ATTRIBUTE_REFERENCE.md](../autocad/AUTOCAD_BLOCK_ATTRIBUTE_REFERENCE.md); topology/ownership определяет соседний [CURRENT_TOPOLOGY_ARCHITECTURE.md](../autocad/CURRENT_TOPOLOGY_ARCHITECTURE.md). Machine projection — [resources/autocad/block_contract.json](../../resources/autocad/block_contract.json); расхождение с exact reference является ошибкой parity.

Target planning ATTDEF не содержат `DEVICE_TYPE`, `POSTS`, global `SOURCE`, исходящие box fields, `CABLE_LINK`, `BUS_LINK`, `LINE_ROLE`, `ROOT_ENDPOINT`, `BUS_TYPE`. **Исключение:** `BUS_ID=9YY` — реальный DWG ATTDEF **только у пассивных DALI `EL_BOX_OUT_100x100` и `TRACK_DALI`**, вместо прежнего `BUS_POINT_ID`. На остальных адресуемых блоках `BUS_ID` — derived из `BUS_POINT_ID`. Эти правила — часть #235, а не старого 3.0.0. `DEVICE_NAME` остаётся пользовательским planning fact.

`CABLE_ID` задаёт самостоятельную CableLine/point; `CABLE_SOURCE` на downstream point задаёт immediate upstream `<empty> | BOX.NNN | TRACK.NNN | XYY.ZZ | 9YY.ZZZ/PORT`. У `LIGHT_TRACK_*` ссылка `TRACK.NNN` означает derived внутреннюю связь, не внешний монтажный кабель. У `EL_BOX_OUT_100x100` новый `CABLE_TRANSIT` содержит физический непрерывный транзит других ordinary кабелей (`301;401`, `301-1`), не splice и не электрическое ребро. Для неоднозначного транзита в разветвлённой линии — `Требует внимания` без угаданной геометрии. `EL_BOX` имеет independent `BOX_ID`; box может быть physical-only, cable-only, bus-only или dual-network. Switch/button order задаёт только numeric `.ZZ`, без `CABLE_SOURCE`. Global source, box suffix topology и outgoing box projections являются только retired legacy input и никогда не target-valid/writeable.

Physical ports `COM1/COM2/K1/K2/IN_1/IN_2/W1/W2` — editable projections canonical edges. Reciprocal port/`CABLE_SOURCE` uses previous Project baseline: one changed side wins deterministically; consistent two-side change passes; incompatible change = `DUAL_PROJECTION_REQUIRES_ATTENTION`, no silent winner. `WB_MRM2_MINI` has one feeder set and independent ports; `WB_M1W2` has `W1/W2`.

Bus identity: `BUS_ID=9YY` — собственный идентификатор шины; reserved root `9YY.000`; **адресуемые** DALI / RS-485 точки получают `BUS_POINT_ID=9YY.ZZZ` (с независимым DALI short address), а **пассивные DALI BOX/TRACK** получают `BUS_ID` и остаются физически идентифицируемыми как `BOX.NNN` / `TRACK.NNN`. `BUS_TYPE` остаётся Project-owned. Новый адресуемый `CABLE_OUTLET_BUS` использует `BUS_POINT_ID=9YY.ZZZ`, не `BUS_ID`, не ordinary `CABLE_ID`; его универсальный протокол (RS485/DALI/KNX) определяется Project Bus; у RS485 значение присутствующего в definition `BUS_SOURCE` пусто, у DALI/KNX родитель задаётся явно. Нельзя считать неизвестную шину RS485 по умолчанию. DALI uses explicit `BUS_SOURCE` branching through root `9YY.000` / `BOX.NNN` / `TRACK.NNN` / addressable `9YY.ZZZ` without cross-bus/cycles. RS-485 has no `BUS_SOURCE`, order is `.ZZZ`. `BUS_CABLE_TYPE` is line-owned; `BUS_MOUNT_WAY/BUS_GOFRA_*` belong to incoming `BusSegment`. Derived `CABLE_LINK/BUS_LINK=TRACK` creates no fake external cable/conduit.

Exact canonical successors include `LIGHT_*_230V`, `WB_M1W2`, `WB_MAI2` and four ordinary/DALI cable-outlet variants. Retired generic light/sensor names are input-only explicit aliases and never emitted. Ordinary lights/outlets have no bus fields; DALI 230 V variants have independent ordinary+bus networks; track lights contain no route facts for internal track links. Socket/phase/PoE boundaries follow exact reference.

Project-to-DWG intersects its closed allow-list with the exact ATTDEF set, performs exact read-back and never saves DWG automatically.

## Единицы координат и длины

Для DWG, используемого NL Project 2.0, одна единица координат `X` и `Y` должна соответствовать `1 мм`. NL Project должен интерпретировать считанные значения `X` и `Y` как миллиметры.

Системная переменная AutoCAD `INSUNITS` не должна использоваться NL Project как коэффициент пересчёта координат. Значение `INSUNITS=0` само по себе не запрещает обработку DWG. Если фактическая геометрия DWG выполнена в другом масштабе, DWG должен быть приведён к масштабу `1 drawing unit = 1 мм` до использования в NL Project.

**Подтверждённая семантика высот (уточнение пользователя 23.10.2026):** `MOUNT_HEIGHT` в AutoCAD задаётся в миллиметрах **от чистого пола**. В настройках помещения NLP бетонное (черновое) основание задаётся относительно чистого пола со знаком минус; высота помещения — от чистого пола до потолка. Это действующие определения документа 11 и AC-002/AC-033, а не основание для миграции старых значений. Формулировку Q05 о едином нуле нельзя использовать для переинтерпретации этих полей как абсолютных отметок здания, добавления room/floor offsets или автоматической конвертации DWG/SQLite.

`LENGTH` линейного изделия в DWG задаётся в миллиметрах; значение не пересчитывается по эвристике масштаба.

**Треки (#234/#235):** `TRACK_230V`, `TRACK_48V`, `TRACK_DALI` получают physical `TRACK_ID=TRACK.NNN` и `TRACK_MOUNT_WAY=накладной|встроенный|подвесной`; `MOUNT_WAY` остаётся способом прокладки входящего кабеля. `TRACK_DALI` допустим как на реальном внешнем питании 230 В (`3YY`), так и 48 В (`4YY`) — слой и классификация должны согласоваться с напряжением и `CABLE_ID`, а не выводиться только из имени блока. Dynamic Stretch должен реально обновлять машиночитаемую `LENGTH` в мм. Само наличие `ATTDEF LENGTH` не даёт такой гарантии.
