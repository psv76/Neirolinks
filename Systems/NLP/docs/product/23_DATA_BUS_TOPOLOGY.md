# Топология шин данных NL Project 2.0

## 1. Назначение и границы

Документ описывает принятую Repair 08 модель физических шин. Exact DWG-поля определяет [AUTOCAD_BLOCK_ATTRIBUTE_REFERENCE.md](../autocad/AUTOCAD_BLOCK_ATTRIBUTE_REFERENCE.md), ownership и правила топологии — [CURRENT_TOPOLOGY_ARCHITECTURE.md](../autocad/CURRENT_TOPOLOGY_ARCHITECTURE.md). Machine projection — [resources/autocad/block_contract.json](../../resources/autocad/block_contract.json); физическое хранение — migration `000000000011_topology_autocad_contract.py`. Диаграмма является представлением этих данных.

## 2. Идентификаторы и источники

`BUS_ID` — самостоятельная Project identity физической шины; `BUS_ID` и `BUS_TYPE` не являются ATTDEF планировки. Канонический адрес точки — `BUS_POINT_ID=9YY.ZZZ`. Трёхзначный суффикс `.000` зарезервирован для root `9YY.000`; остальные точки имеют ненулевой трёхзначный ordinal той же шины. Ordinal не является автоматически Modbus slave address.

Привязка шины к конкретному ресурсу источника хранится в Project:

- DALI: экземпляр `Wiren Board WB-DALI3`, паспорт `gateway.wirenboard.wb_dali3`, ровно один порт `DA1`, `DA2` или `DA3` на физическую шину;
- KNX: экземпляр `Wiren Board WBE2-I-KNX`, паспорт `module.wirenboard.wbe2_i_knx`, ресурс `KNX_PORT`;
- питание и коммуникационная связь независимы; назначение порта не доказывает питание;
- другие source products требуют отдельного принятого изменения каталога, автоматического выбора нет.

## 3. Физический участок

Каждое соседство образует отдельный `BusSegment`. Ordinary `CableSegment` не используется для хранения участка шины. Отдельный пользовательский номер участку не присваивается. Полная длина — сумма уникальных физических участков; геометрия и conduit accounting определяются [22_CABLE_LENGTHS_AND_CONDUITS.md](22_CABLE_LENGTHS_AND_CONDUITS.md).

`BUS_CABLE_TYPE` принадлежит всей шине и должен быть согласован на её точках. `BUS_MOUNT_WAY` и `BUS_GOFRA_*` принадлежат входящему `BusSegment`. Один физический участок и его труба учитываются ровно один раз. Derived link `TRACK` не создаёт внешнюю длину кабеля или трубу. Полилинии DWG для задания топологии не требуются.

## 4. RS-485: линейный порядок

RS-485 не допускает ответвлений. После root `9YY.000` точки соединяются по числовому порядку трёхзначных суффиксов `.ZZZ`: например `902.000 → 902.001 → 902.003`. Пропуск ordinal не меняет правило порядка. Scan order и порядок вставок DWG не определяют соседство. У специализированных RS-485 блоков ATTDEF `BUS_SOURCE` отсутствует; у универсального вывода присутствует с пустым значением.

## 5. DALI: явные связи

DALI поддерживает ветвление от root `9YY.000`. В DWG immediate upstream задаётся явно в `BUS_SOURCE` дочерней точки; никакого неявного порядка по ordinal, геометрии или scan order нет. Parent должен существовать в той же физической шине. Цикл, cross-bus reference, неоднозначный parent и недостижимая от root точка недопустимы.

Project-представление упорядоченными ветвями сохраняет те же явные edges: первая ветвь начинается от root, первая точка последующей ветви уже присутствует в ранее заданных ветвях и обозначает место ответвления. Остальные точки ветви задают последовательность от него. Повтор точки допустим только как начало дополнительной ветви; повтор физического участка недопустим. Трёхзначный ordinal идентифицирует точку, но не задаёт общий порядок обхода DALI. Логические группы DALI хранятся в Project независимо от геометрии и физической топологии.

## 6. KNX: совместимые Project-правила

Для KNX сохраняется принятая явно заданная Project-модель ветвей с теми же правилами первой и последующих ветвей и трёхзначными адресами `9YY.ZZZ`. Она не получает автоматический порядок по ordinal. Для универсального `CABLE_OUTLET_BUS` связи KNX задаются `BUS_SOURCE` по тем же physical-edge правилам, что DALI. Привязка `KNX_PORT`, отдельная проверка питания, запрет повторных участков и обязательная достижимость точек сохраняются.

## 7. Проверки

NL Project выявляет неверный формат адреса, несовпадающую шину, отсутствие источника/root, отсутствующий parent/endpoint, отсутствие пути от root, запрещённое RS-485 ветвление, DALI cycle/cross-bus/двойного parent, недопустимое начало дополнительной Project-ветви, повтор точки вне места ответвления и повтор участка. Неполнота не подменяется придуманными связями.

## 8. Представление

Диаграмма строится из canonical bus points/edges/branches и `BusSegment`; она не является вторым источником топологии. Mermaid допустим как средство отображения, но его текст не хранится как нормативная модель.

## Универсальный кабельный вывод шины

`CABLE_OUTLET_BUS` — одна физическая точка шины на слое `BUS`, с типом
устройства `CABLE_OUTLET`, `bus_link_kind=CABLE` и без ordinary cable link.
Тип RS485/DALI/KNX принадлежит Project Bus, не имени блока и не наличию
ATTDEF `BUS_SOURCE`. При неизвестной шине пользователь выбирает тип и
свободный физический источник; неизвестный тип не заменяется RS485.
Несовместимость типа существующей шины со специализированным блоком — конфликт.

`BUS_POINT_ID=9YY.ZZZ` — физическая identity, не аппаратный адрес.
`.000` принадлежит Project root и запрещён для полевой вставки.
Для RS485 значение `BUS_SOURCE` пусто: порядок определяется числовым `.ZZZ`.
Для DALI и KNX TP значение обязательно и указывает ближайшую upstream точку
той же шины, включая `.000`. Разрешены линия, звезда и дерево; запрещены
кольца, двойной parent, неизвестный parent и недостижимые точки.
Общая механика физических edges не меняет ограничения питания, адресации,
длины/числа устройств и логических групп каждого протокола.

Один входящий `BusSegment` учитывается один раз. `BUS_CABLE_TYPE` принадлежит
шине; `BUS_MOUNT_WAY` и `BUS_GOFRA_*` — входящему сегменту. Пустой
`BUS_GOFRA_ID` допустим до штатного назначения трубы по conduit contract.
Входящий и отходящий кабель у привода не требуют двух вставок вывода.
Вывод не создаёт обычную CableLine, привод, нагрузку или ProjectInstance;
отдельная розетка питания остаётся отдельным физическим объектом.
