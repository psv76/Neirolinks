# Топология шин данных NL Project 2.0

## Актуализация Repair 08

`BUS_ID` — самостоятельная identity шины. DALI root имеет point ID `XYY.000` и поддерживает ветвление. RS-485 point ID имеет строго трёхзначный ordinal `9YY.ZZZ`, root резервирует `.000`, а порядок остальных точек линейный. Каждое соседство materializes отдельный physical `BusSegment` с route/conduit facts; эти сегменты не являются ordinary cable segments. `BUS_CABLE_TYPE` согласован по всей шине.

## 1. Назначение

Документ определяет представление последовательных и разветвлённых шин данных, порядок точек и расчёт участков между устройствами.

## 2. Идентификатор шины и точек

`BUS_ID=XYY` идентифицирует одну физическую шину данных; это не ordinary `CABLE_ID`.

Полный `POINT_ID=9YY.ZZZ` идентифицирует отдельное устройство или точку RS-485. Полевой `RELAY_DEVICE` с интерфейсом RS-485, например `WB_MRM2_MINI`, может быть такой точкой.

Суффикс `.ZZZ` хранится в трёхзначном формате; `.000` зарезервирован для root. Он является проектным идентификатором порядка и не должен автоматически трактоваться как Modbus slave address, если отдельный контракт явно не установил такое совпадение.

Привязка шины к конкретному порту источника должна выполняться внутри NL Project и не должна храниться в блоках планировки AutoCAD.

### 2.1. Источники MVP

- Источник DALI — экземпляр `Wiren Board WB-DALI3` с паспортом `gateway.wirenboard.wb_dali3`; каждая физическая шина привязывается ровно к одному из отдельных портов `DA1`, `DA2` или `DA3`.
- Источник KNX — экземпляр `Wiren Board WBE2-I-KNX` с паспортом `module.wirenboard.wbe2_i_knx`; физическая шина привязывается к его единственному ресурсу `KNX_PORT`.
- Питание устройства/шины и наличие коммуникационной связи являются независимыми состояниями. Назначение DALI/KNX-порта не доказывает корректность питания.
- Другие DALI/KNX source products не выбираются автоматически и требуют отдельного изменения канонического каталога.

## 3. Участок шины

Каждая связь между двумя соседними точками топологии образует отдельный расчётный `CableSegment`. Этот термин совпадает с общей физической моделью участков `22_CABLE_LENGTHS_AND_CONDUITS.md`; отдельный пользовательский номер сегменту не присваивается.

Длина участка должна рассчитываться по координатам блоков параллельно осям `X` и `Y` в соответствии с `22_CABLE_LENGTHS_AND_CONDUITS.md`.

Полная длина шины должна равняться сумме длин всех уникальных участков от источника до устройств и между устройствами.

Полилинии AutoCAD для задания трассы шины не требуются.

## 4. Линейная последовательная топология

Для `RS-485` должна использоваться линейная последовательная топология без ответвлений.

Порядок устройств определяется числовым порядком суффиксов `.ZZ`.

Шина рассчитывается последовательно:

```text
источник
→ XYY.01
→ XYY.02
→ XYY.03
→ ...
```

Для `RS-485` суффикс `.ZZ` одновременно:

- идентифицирует устройство;
- определяет физический порядок устройств на шине.

## 5. Разветвлённая топология

Для `DALI` и `KNX` допускается разветвлённая топология.

Разветвлённая топология должна задаваться перечнем упорядоченных ветвей.

Первая ветвь начинается от назначенного источника шины.

Первая точка каждой последующей ветви должна быть устройством, уже присутствующим в ранее заданной ветви. Эта точка является местом ответвления.

Остальные точки ветви определяют последовательность устройств от места ответвления до конца ветви.

Для `DALI` и `KNX` суффикс `.ZZ` является уникальным идентификатором точки и не задаёт общий порядок обхода всей шины.

Точка может повторяться в перечне ветвей только как первая точка дополнительной ветви, обозначающая место ответвления.

## 6. Проверки топологии

NL Project должен выявлять:

- точку с базовым `CABLE_ID`, отличным от идентификатора шины;
- отсутствие назначенного источника;
- отсутствие пути от источника до устройства;
- ответвление у `RS-485`;
- дополнительную ветвь, первая точка которой отсутствует в ранее заданных ветвях;
- повторное включение одной точки в топологию вне допустимого места ответвления;
- повторное описание одного участка;
- ссылку на отсутствующий блок устройства;
- нарушение двухзначного формата суффикса `.ZZ`.

## 7. Представление в интерфейсе

Источником данных являются шина, её точки и перечни ветвей.

Графическая диаграмма должна формироваться из этих данных и не должна становиться отдельным источником топологии.

Использование Mermaid как средства отображения допускается, но Mermaid-текст не должен храниться как нормативная модель шины.
