# Кабельная система мультимедиа (AV) NL Project 2.0

## 1. Назначение и границы модели

Документ определяет модель кабельных линий мультимедиа `AV`, их представление в AutoCAD и NL Project, расчёт длины, подбор кабеля и готовых изделий HDMI, проверки и включение в выходные документы.

NL Project не должен моделировать мультимедийную систему как оборудование. В модели не должны создаваться отдельные сущности акустических колонок, AV-ресиверов, медиаплееров, усилителей, AV-стоек и другого оборудования мультимедийного подрядчика.

Для кабельной системы `AV` NL Project должен учитывать только:

- место вывода кабеля;
- щит или узел назначения кабеля;
- назначение кабеля;
- тип или марку кабеля;
- расчётную либо полную ручную длину;
- выбранное готовое изделие для линии HDMI.

Оборудование мультимедийного подрядчика не должно включаться в спецификацию NL Project.

## 2. Представление в AutoCAD

Функциональная группа и слой AutoCAD для кабельных линий мультимедиа должны иметь имя `AV`.

Точка вывода AV-кабеля должна обозначаться существующим блоком `CABLE_OUTLET`. Отдельный блок `AV_CABLE_OUTLET` не должен создаваться.

Точка назначения AV-линий должна обозначаться существующим блоком `BOARD_IN` со следующими значениями атрибутов:

- `DEVICE_TYPE=BOARD`;
- `LOAD_TYPE=BOARD_AV`;
- `BOARD_ID` содержит обозначение AV-щита.

Блок `CABLE_OUTLET` на слое `AV` должен использовать существующие атрибуты:

- `BOARD`;
- `CABLE_ID`;
- `LOAD_TYPE`;
- `CABLE_TYPE`.

Общие правила блоков и атрибутов, не заменённые этим документом, определяются документом `20_AUTOCAD_BLOCK_CONTRACT.md`.

## 3. Щит `BOARD_AV`

`BOARD_AV` должен отображаться в разделе интерфейса `Щиты` как отдельный тип щита.

`BOARD_AV` является логической точкой назначения AV-кабелей и не должен:

- содержать внутренние аппараты или другое внутреннее оборудование;
- содержать DIN-рейки;
- участвовать в расчёте питания;
- участвовать во внутреннем электрическом распределении;
- включаться в спецификацию.

Координата блока `BOARD_IN` с `LOAD_TYPE=BOARD_AV` является общей конечной точкой расчёта длины всех AV-линий, у которых атрибут `BOARD` ссылается на этот щит.

## 4. Идентификация AV-линий

Формат электрических линий `XYY` и `XYY.ZZ` не должен применяться к AV-линиям.

Значение `CABLE_ID` для AV-линии:

- вводится проектировщиком как свободный текст по обозначению разъёма или назначению линии;
- автоматически приводится к верхнему регистру;
- сохраняется без пробелов в начале и конце;
- должно быть уникальным в пределах одного `BOARD_AV`.

Однозначным идентификатором AV-линии является сочетание `BOARD + CABLE_ID`.

Одинаковое значение `CABLE_ID` допускается в разных щитах `BOARD_AV`.

Дубликат `CABLE_ID` внутри одного `BOARD_AV` должен блокировать сохранение данных.

Обозначения отдельных линий HDMI вводятся проектировщиком вручную. NL Project не должен выполнять автоматическую нумерацию и автоматическое перенумерование AV-линий.

## 5. Связь линии с `BOARD_AV` и неполные данные

Для каждого блока `CABLE_OUTLET` на слое `AV` атрибут `BOARD` обязателен и должен ссылаться на существующий щит с `LOAD_TYPE=BOARD_AV`.

NL Project должен разрешать временное сохранение и сканирование AV-линии с диагностической ошибкой при любом из следующих нарушений:

- `BOARD` не заполнен;
- указанный в `BOARD` щит не существует;
- указанный в `BOARD` щит имеет другой `LOAD_TYPE`;
- `CABLE_ID` не заполнен;
- `LOAD_TYPE` не заполнен;
- `CABLE_TYPE` не заполнен.

Такие данные должны оставаться доступными для последующего исправления.

Дубликат `CABLE_ID` внутри одного `BOARD_AV` является исключением и должен блокировать сохранение.

## 6. Допустимые типы AV-линий

В области версии 2.0 допускаются только два значения `LOAD_TYPE` для AV-линий:

- `SPEAKER_CABLE`;
- `HDMI`.

Атрибут `CABLE_TYPE` должен содержать тип или марку кабеля и не обязан определять конкретное товарное изделие.

## 7. Расчёт длины

Длина AV-линии должна рассчитываться от координаты назначенного `BOARD_AV` до координаты соответствующего блока `CABLE_OUTLET`.

Для AV-линий должны применяться общие правила ортогонального расчёта по координатам `X` и `Y`, учёта высоты точки, способа прокладки, запаса у щита, дополнительной длины и полной ручной длины, установленные документом `22_CABLE_LENGTHS_AND_CONDUITS.md`.

Если указана полная ручная длина, она является итоговой длиной AV-линии и заменяет автоматический расчёт.

Промежуточные помещения без устройств линии не должны автоматически включаться в расчёт трассы.

## 8. Линия `SPEAKER_CABLE`

`SPEAKER_CABLE` является погонным кабелем.

Для линии `SPEAKER_CABLE` значение `CABLE_TYPE` должно выбираться из каталога кабелей. Проектировщик должен иметь возможность добавить в каталог новый кабель.

Кабель `Premiera CX-225` должен допускаться как позиция каталога, но не должен назначаться стандартным AV-кабелем по умолчанию.

В спецификации одинаковые позиции кабелей должны объединяться, а их итоговые длины — суммироваться. Для них должны применяться общие правила округления и запасов кабельных линий.

Полная ручная длина должна заменять расчётную. Итоговая длина должна включаться в кабельный журнал и спецификацию.

## 9. Линия `HDMI`

Линия `HDMI` должна учитываться как готовое изделие фиксированной заводской длины.

Значение `CABLE_TYPE` должно содержать тип или марку HDMI-кабеля. Конкретное товарное изделие должно выбираться отдельно и содержать:

- производителя;
- модель;
- артикул;
- заводскую длину;
- другие предусмотренные каталогом характеристики.

Требуемой длиной для автоматического подбора должна быть полная ручная длина, если она указана, иначе — расчётная длина линии.

Автоматический подбор должен выполняться только среди изделий, соответствующих выбранному `CABLE_TYPE`.

По умолчанию NL Project должен выбирать самое короткое изделие, заводская длина которого не меньше требуемой.

Проектировщик должен иметь возможность заменить автоматически выбранное изделие более длинным или вручную выбрать изделие короче требуемой длины.

Выбор изделия короче требуемой длины должен сопровождаться предупреждением и не должен блокироваться.

Если у линии уже выбрано изделие, а расчётная или полная ручная длина изменилась, NL Project должен запросить у проектировщика решение о дальнейшем использовании выбранного изделия.

Если среди изделий выбранного `CABLE_TYPE` нет изделия достаточной заводской длины, NL Project должен автоматически назначить самое длинное доступное изделие и показать предупреждение. Проектировщик должен иметь возможность добавить в каталог изделие другой марки или заводской длины.

## 10. Кабельный журнал и спецификация

AV-линии должны включаться в общий кабельный журнал. Кабельный журнал должен содержать отдельные колонки `BOARD` и `CABLE_ID`.

В представлениях, требующих одной однозначной подписи линии, должно использоваться сочетание `BOARD / CABLE_ID`.

Для линий `SPEAKER_CABLE` и `HDMI` в кабельном журнале должна выводиться расчётная длина либо заменяющая её полная ручная длина.

Заводская длина выбранного HDMI-изделия не должна выводиться в кабельном журнале.

В спецификации:

- `SPEAKER_CABLE` должен учитываться в погонных метрах;
- одинаковые позиции `SPEAKER_CABLE` должны объединяться с суммированием длины;
- `HDMI` должен учитываться как готовое изделие в штуках;
- заводская длина HDMI должна включаться в наименование выбранного изделия.

`BOARD_AV` и оборудование мультимедийного подрядчика не должны включаться в спецификацию.

## 11. Представление в интерфейсе

AV-линии должны отображаться в общем разделе `Кабельные линии`. Раздел должен позволять выделить AV-линии фильтром или группировкой `AV`.

AV-линии должны также отображаться внутри соответствующего `BOARD_AV` в разделе `Щиты`.

Отдельный верхнеуровневый раздел `Мультимедиа` не должен создаваться.

## 12. Проверки

К AV-линиям не должны применяться проверки:

- мощности;
- напряжения;
- защитных аппаратов;
- каналов управления;
- электрического распределения;
- внутреннего устройства щита;
- DIN-компоновки.

Для AV-линий должны выполняться проверки:

- заполнения обязательных данных;
- нормализации `CABLE_ID`;
- уникальности `CABLE_ID` внутри `BOARD_AV`;
- связи с существующим `BOARD_AV`;
- допустимости `LOAD_TYPE`;
- наличия `CABLE_TYPE`;
- расчёта длины;
- выбора кабеля;
- выбора HDMI-изделия;
- достаточности заводской длины выбранного HDMI-изделия.

Блокирующие и неблокирующие результаты этих проверок определяются разделами 5 и 9 этого документа.

## 13. Выходные документы

Отдельный печатный документ по AV не должен создаваться.

Для AV должны использоваться общий кабельный журнал и общая спецификация.
