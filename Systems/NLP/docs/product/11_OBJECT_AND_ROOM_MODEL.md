# Объект, здания и помещения NL Project 2.0

## 1. Назначение

Документ определяет общие данные объекта, сведения о зданиях и помещениях, а также настройки объекта, необходимые для проектирования и выпуска документации.

Документ не определяет структуру SQLite, классы Python и расположение элементов интерфейса внутри конкретного окна, кроме принятого разделения карточки объекта на вкладки.

## 2. Карточка объекта

Карточка объекта должна содержать вкладки:

1. `Общие данные`;
2. `Помещения`;
3. `Настройки`;
4. `Время работы`.

## 3. Вкладка `Общие данные`

Вкладка должна содержать поля:

- `Название объекта`;
- `Шифр проекта`;
- `Тип объекта`;
- `Адрес объекта`;
- `Общая проектируемая площадь, м²`;
- `Заказчик`;
- `Ответственный проектировщик`;
- `Примечание`.

Перечень допустимых значений поля `Тип объекта` определяется отдельно.

## 4. Вкладка `Помещения`

Вкладка должна содержать таблицу помещений.

Для каждого помещения должны храниться:

- здание;
- название помещения;
- отметка бетонного основания пола относительно уровня чистого пола;
- высота помещения;
- цвет маркировки помещения.

Помещение должно однозначно определяться сочетанием `Здание + Название помещения`.

Уровень чистого пола является нулевой отметкой помещения.

Отметка основания обозначает отметку бетонного основания пола, расположенного ниже чистого пола и используемого как плоскость прокладки кабельных линий со способом `По полу`. Значение задаётся в миллиметрах относительно уровня чистого пола. Значение ниже уровня чистого пола должно быть отрицательным, например `-250 мм`.

Отметка основания не является отметкой чистого пола и не изменяет нулевую точку отсчёта `MOUNT_HEIGHT`.

Высота помещения должна измеряться от чистого пола до чистового потолка.

Цвет маркировки является свойством помещения и должен одинаково использоваться во всех представлениях объекта, где применяется маркировка помещений.

### 4.1 Каноническое помещение Project

Сущность `Room` в Project является единственным каноническим источником текущих имени, здания и цвета помещения. `field_device` хранит устойчивую ссылку `room_id`; Lines и другие Project-представления получают отображаемые `Room.name` и `Room.color` через эту связь, а не из сохранённого текстового значения `ROOM` блока DWG.

Текст `ROOM`, прочитанный из DWG, сохраняется как наблюдение и reconciliation evidence. Он не подменяет каноническое имя Project и не теряется при разрешении ссылки на помещение.

Для привязки значения `ROOM` из DWG к уже настроенному помещению Project разрешены только детерминированные правила в пределах выбранного здания, по порядку:

1. точное совпадение канонического имени;
2. точное совпадение после нормализации регистра и пробелов;
3. единственное совпадение ведущего числового префикса вида `N.`;
4. единственное точное совпадение имени после удаления ведущего числового префикса.

Неоднозначное или отсутствующее совпадение не создаёт помещение и не назначает `room_id` автоматически.

### 4.2 Цвета помещений

Канонический цвет хранится в `Room.color`. Для помещений с уже заданным цветом значение сохраняется; автоматическое назначение применяется только к белому цвету по умолчанию `#FFFFFF`.

Фиксированная палитра наследует проверенные цвета NL Project 1.0: `#EEF0F2`, `#D7E3FC`, `#DDF4E7`, `#FEEFC3`, `#FADFC8`, `#FAD2CF`, `#F8D7E8`, `#EADCF8`, `#CCF3F0`. Прежний hash/QSettings-механизм выбора цвета не используется.

Автоматическое назначение детерминировано: помещения обходятся в естественном порядке по числовому префиксу, затем по имени и идентификатору; начальные счётчики учитывают уже занятые цвета; выбирается наименее использованный цвет, а при равенстве — цвет с наибольшей детерминированной дистанцией оттенка от предыдущего помещения и затем порядок палитры. Существующие цвета не перебалансируются. Повторный запуск, переименование, повторное открытие или добавление помещения не меняют уже сохранённые цвета.

Текст на цветном маркере должен получать читаемый контраст, вычисленный из сохранённого цвета.

## 5. Вкладка `Настройки`

Вкладка должна содержать поля:

- `Папка проекта`;
- `Папка вывода`;
- `Папка версий`;
- `Начальный номер страниц`;
- `Запас кабеля у щита`.

Значение `Запас кабеля у щита` применяется по правилам документа [22_CABLE_LENGTHS_AND_CONDUITS.md](22_CABLE_LENGTHS_AND_CONDUITS.md).
