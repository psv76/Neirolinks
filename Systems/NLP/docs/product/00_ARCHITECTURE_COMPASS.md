# Архитектурный компас NL Project 3.0

## Миссия

NL Project превращает разрозненные проектные решения в связанную цифровую модель объекта.

Программа должна хранить не отдельные таблицы и подписи, а связи между кабельными линиями, полевым оборудованием, щитами, аппаратами, каналами, питанием и выбранными изделиями. Изменение проектного решения должно отражаться во всех представлениях и выходных документах через одну модель, а не переноситься вручную между AutoCAD, Excel и другими файлами.

NL Project не заменяет инженера. Он сохраняет принятые решения, показывает их последствия и выявляет незавершённые или противоречивые связи.

## Место в рабочем процессе

AutoCAD остаётся рабочим чертежом. AutoCAD Electrical остаётся средой построения подробной электрической схемы. Excel и PDF остаются форматами выдачи.

NL Project занимает место между исходными данными и выпуском документации:

```text
планировка и исходные данные
→ проектные решения
→ связанная модель NL Project
→ проверки
→ DWG, Excel, PDF и данные для настройки
→ монтаж, сборка, наладка и эксплуатация
```

Project не конкурирует с CAD. Он подготавливает, связывает и проверяет данные, на основании которых CAD формирует чертежи и схемы.

## Основной принцип архитектуры

Единым источником истины является модель проекта.

Таблицы, карточки, компоновка щита, отчёты и выходные документы являются разными представлениями этой модели. Они не должны создавать независимые версии одного инженерного решения.

Связь должна задаваться один раз и использоваться везде, где она нужна:

- при распределении кабельных линий;
- при выборе и размещении аппаратов;
- при назначении каналов;
- при расчёте питания;
- при проверках;
- при формировании спецификации;
- при создании выходных DWG и монтажных данных.

## Конструктор цепей

Конструктор — не отдельный экран и не графический редактор.

Это принцип построения в NL Project цепей питания, управления и измерения из:

- требований кабельных линий и оборудования;
- паспортов аппаратов;
- экземпляров аппаратов в проекте;
- назначенных функциональных связей.

Конструктор должен позволять определить:

- какие аппараты входят в цепь;
- какую функцию выполняет каждый аппарат;
- какие ресурсы аппарата заняты;
- откуда цепь получает питание или сигнал;
- чем и как управляется нагрузка;
- совместимы ли элементы;
- является ли цепь полной и непротиворечивой.

Проверки должны применяться к построенной цепи, а не заменять её набором специальных правил для отдельных таблиц.

## Граница между NL Project и AutoCAD Electrical

NL Project должен учитывать аппарат настолько подробно, насколько это необходимо для выбора, распределения ресурсов, построения функциональной цепи и инженерной проверки.

Project должен знать, например:

- назначение и основные характеристики аппарата;
- количество и типы его функциональных каналов;
- напряжение и род тока питания;
- параметры катушки, выхода или измерительного входа;
- общие группы каналов;
- допустимые подключения и ограничения;
- занятость ресурсов конкретного экземпляра.

Project не должен дублировать подробную монтажную схему и хранить прохождение каждого проводника через все физические контакты, клеммы, перемычки, нулевые и защитные шины.

Подробная схема с конкретными выводами, проводами, жилами, клеммами, перемычками и маркировкой создаётся в AutoCAD Electrical на основании данных NL Project и паспортов оборудования.

## Роль паспорта аппарата

Паспорт должен превращать товарную позицию в элемент конструктора.

Он должен описывать функциональные возможности и ограничения аппарата, необходимые NL Project для построения и проверки цепей.

Паспорт не обязан становиться полной копией электрической схемы изделия. Физическая карта выводов может использоваться для формирования выходного DWG, но не должна заставлять NL Project дублировать работу AutoCAD Electrical.

## Критерий направления

При принятии архитектурного, предметного или интерфейсного решения необходимо проверять:

1. Укрепляет ли решение единую связанную модель проекта?
2. Помогает ли оно строить и проверять цепи питания, управления или измерения?
3. Устраняет ли оно ручное дублирование данных?
4. Остаётся ли подробное черчение в CAD?
5. Не превращает ли оно NL Project во второй AutoCAD Electrical?

Если решение ведёт к связанной модели, проверяемым цепям и автоматической выдаче — оно направлено к цели NL Project 3.0.
