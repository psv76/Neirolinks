# Канонический каталог оборудования NL Project 2.0

## 1. Назначение и статус

Этот документ вместе с файлами `catalogs/equipment_passports.json` и `catalogs/products.json` определяет канонический каталог оборудования MVP. Действующий release, identities/counts и хеши payload объявлены в [resources/catalogs/catalog_manifest.json](../../resources/catalogs/catalog_manifest.json); packaged payload и нормативные JSON должны совпадать.

Каталог является исходным рабочим набором, а не окончательным корпоративным стандартом производителей. Новый совместимый товар может быть добавлен позднее без изменения паспорта, если он реализует ту же функциональную структуру и проходит все проверки паспорта.

Документ не определяет таблицы базы данных, классы программы, интерфейс пользователя, миграцию NL Project 1.0 и состав конкретного тестового объекта.

## 2. Место каталога в модели

Уровни `EquipmentPassport`, `Product` и `ProjectInstance` определены в [10_EQUIPMENT_MODEL.md](10_EQUIPMENT_MODEL.md).

- `EquipmentPassport` задаёт функциональную структуру и обязательные проверки.
- `Product` задаёт реальное изделие, его номиналы, размеры и официальный источник.
- `ProjectInstance` задаёт проектное обозначение, размещение, назначения и связи конкретного объекта.

Проектные обозначения `1QF`, `QF.02`, `SF.01`, `SF.02`, `PSU.1` и `PSU.2` не являются идентификаторами паспортов или товаров.

Функциональные ресурсы создаются у экземпляра из паспорта. Каталог не моделирует отдельные физические клеммы, перемычки и монтажные проводники.

## 3. Канонические файлы

- `catalogs/equipment_passports.json` — паспорта, ресурсы, совместимость и параметры проверок;
- `catalogs/products.json` — реальные товарные позиции, номиналы, размеры и официальные источники.

Оба файла используют UTF-8 и уникальные стабильные идентификаторы. Ссылки `Product.passport_id` должны указывать на существующий паспорт.

## 6. Обязательные правила выбора и замены

1. Экземпляр должен ссылаться ровно на один паспорт.
2. Выбранный товар должен ссылаться на тот же паспорт, что и экземпляр.
3. Замена товара не меняет идентификаторы и назначения функциональных ресурсов экземпляра.
4. После замены повторно проверяются все товарные ограничения: ток, мощность, напряжение, отключающая способность, пусковые характеристики, температура и DIN-компоновка.
5. Правило разветвления задаётся семантикой конкретного ресурса паспорта. Для канонических БП `power.acdc.24v.din` и `power.acdc.48v.din` регулируемый выход DC является общим источником питания: один `DC24_OUTPUT`/`DC48_OUTPUT` может иметь несколько совместимых потребителей напрямую в логической модели Project. Проверка БП выполняется по суммарной мощности и току всех активных потребителей; отдельный распределительный узел не требуется только ради разрешения такого one-to-many. Для остальных силовых/DC-выходов действует branching rule их паспорта.
6. Ресурс с `exclusive: true` нельзя назначить двум независимым связям.
7. Значения диапазонов производителя не отменяют проектную характеристику 24 В DC для низковольтного питания Wiren Board.
8. У `module.wirenboard.wb_mcm8` каждый из восьми входов является отдельным эксклюзивным ресурсом с доказанным label `Input 1`…`Input 8`; один физический key не может занимать более одного входа, а один вход — обслуживать несколько физических keys.

Для проверки замены 24-В БП могут использоваться любые два утверждённых товара с паспортом `power.acdc.24v.din`. Они реализуют одинаковые ресурсы `AC_INPUT` и `DC24_OUTPUT`, поэтому связи сохраняются; номиналы, пусковые параметры, температурные ограничения и DIN-размер проверяются повторно. Товары 48 В используют отдельный паспорт `power.acdc.48v.din` и ресурс `DC48_OUTPUT`, поэтому не являются заменой 24-В товара в существующей цепи.

Для `XT.01` основной товар — `product.iek.ynd10_4_11_125`; `product.iek.ynd10_4_07_100` является вторым допустимым товаром того же паспорта. Замена выполняется только пользователем и требует повторной проверки доступных присоединений, тока, сечений и габаритов. Паспорт не выделяет ввод и отходящие клеммы: одна точка каждой используемой шины получает проектную роль источника, остальные могут получить роль потребителей. На одной шине допускается не более одного активного источника.

## 7. Границы подтверждения

- Значение 7 входов WB-MR6C v.2 принято по официальной документации; исследовательское значение 6 не переносится.
- WB-LED принят именно в версии v.1 и описан полным набором четырёх ШИМ-каналов и четырёх входов.
- WB-UPS v.3 описывает встроенную батарею как внутренний не назначаемый ресурс; отдельный товар батареи для MVP не требуется.
- Источник DALI для MVP — только утверждённый пользователем `Wiren Board WB-DALI3`. Три порта DA1–DA3 являются отдельными ресурсами и не объединяются скрыто; AC/DC-питание, upstream RS-485 и DALI-связь хранятся независимо.
- Источник KNX для MVP — только утверждённый пользователем `Wiren Board WBE2-I-KNX`. Это внутренний модуль для контроллеров Wiren Board 6…8 с одним KNX-портом; наличие host attachment не доказывает наличие KNX-связи, а для работы требуется питание KNX-шины.
- `Wiren Board WB-MCM8` является обязательным каталоговым устройством 2.0. Подтверждены восемь входов для сухого контакта/open collector, питание 9–28 В DC, RS-485/Modbus RTU, потребление 0,1 Вт и корпус 2 DIN; прочие неподтверждённые характеристики не добавляются.
- `Wiren Board WB-MGE v.3` имеет два независимых физических ресурса `RS485-1` и `RS485-2`, каждый из которых может быть отдельным корнем RS-485-шины Project. Также подтверждены Ethernet 10/100, Wi-Fi 2.4 ГГц, WBIO, питание 9–28 В DC, потребление 1 Вт при 24 В и корпус 2 DIN.
- Не опубликованные официально габариты WB-DALI3 и WBE2-I-KNX сохранены как `null`; ширина WB-DALI3 в три DIN-модуля подтверждена изготовителем, WBE2-I-KNX не получает вымышленную DIN-ширину.
- Для `XT.01` принят IEK YND10-4-11-125; IEK YND10-4-07-100 добавлен как пользовательская альтернатива. Legrand 400408 исключён из активного канона прямым решением пользователя.
- Поле карточек IEK «Количество полюсов: 3» хранится отдельно как термин производителя и означает число фазных полюсов. Обозначение `3L+PEN`, руководство, чертёж и фотографии подтверждают четыре физически отдельные изолированные шины.
- У изделий IEK нет подтверждённой отдельной вводной клеммы. На каждой шине имеются равноправные присоединительные точки: 11 для YND10-4-11-125 и 7 для YND10-4-07-100. Их число и допустимые сечения определяются выбранным товаром.
- `din_modules` у двух IEK сохранено как `null`: общего нормативного правила пересчёта официальной ширины в DIN-модули комплект пока не содержит. Официальная ширина сохранена в `dimensions_mm`.
- `pwm_load_compatibility` у выбранных HDR-БП не заявлена производителем. Это сохранено как `NOT_DECLARED_PROJECT_CHECK_REQUIRED`, а не заменено предположением. При прямом питании ШИМ-нагрузки требуется отдельная проектная проверка по [21_LED_LINES_AND_PWM_EQUIPMENT.md](21_LED_LINES_AND_PWM_EQUIPMENT.md).
- Канонический набор LED-лент MVP содержит ровно шесть товаров Arlight: `048822`, `044515`, `049060`, `044196`, `045179`, `046937`. Запись Elektrostandard `85128/00` из legacy-таблицы `led_tapes` является шинопроводом и в каталог 2.0 не переносится.
- У LED-паспортов функциональная структура отделена от товарных значений. `CUT_INCREMENT`, `REEL_LENGTH`, `SALE_MODE` и минимальная закупочная единица находятся только у товара и проверяются по [21_LED_LINES_AND_PWM_EQUIPMENT.md](21_LED_LINES_AND_PWM_EQUIPMENT.md).
- Для `044515` каноническим принято структурированное значение `Warm 3000 K` с диапазоном 2900–3200 K. Текст рекламного описания содержит противоречащее значение 3500 K; расхождение сохранено в `official_source.reconciliation_note`.
- Для `045179` обозначение производителя `MIX` нормализовано в `CCT`; общая мощность учитывается один раз, два канала проверяются отдельно.
- Для `046937` без исправления сохранены структурированные значения официальной страницы, включая `typ: 17.3 W/m`, `max: 17.2 W/m`, группу RGB и канал W. В расчёте БП используется утверждённая пользователем общая максимальная мощность 17.2 Вт/м один раз; каналные ограничения проверяются отдельно.
- Утверждённый набор DIN-БП MEAN WELL содержит ровно девять товаров: HDR-30-24, HDR-60-24, HDR-100-24, HDR-150-24, NDR-240-24, SDR-240-24, SDR-240-48, SDR-480-24 и SDR-480-48. SDR-120-24 и иные неутверждённые БП в канон не входят.
- Официальные спецификации девяти БП не публикуют `input_apparent_power_va` и `input_capacitance_uf`; в товарах записан явный `null`, без расчётной догадки.
- Предметные правила применения ICL-16R и статусы совместимости определены в [32_INRUSH_CURRENT_LIMITERS.md](32_INRUSH_CURRENT_LIMITERS.md). Логика по обозначению `FI.01`, автоматическое добавление ICL и автоматическая замена БП запрещены.

## 7.1. Конфигурируемый WB-MSW v.4

`SENSOR_MSW` должен поддерживать выбор конфигурации Wiren Board WB-MSW v.4 без переноса legacy-цен как нормативных данных. Официальные материалы производителя подтверждают, что устройство является RS-485/Modbus RTU настенным датчиком и поставляется с выбираемыми заводскими опциями.

Для Project допустимы только опции, присутствующие в актуальном официальном каталоге производителя, включая:

- temperature/humidity;
- illumination + IR transceiver;
- sound;
- motion;
- CO2;
- air quality/VOC;
- verification;
- body color;
- case top type.

Точный набор выбранных опций является частью заказываемой конфигурации и должен сохраняться у физического `SENSOR_MSW`, участвовать в user-facing названии и группировке спецификации. Значения и коммерческие данные должны поступать только из versioned catalog facts; текущая цена с сайта не является постоянным нормативным значением.

Официальные источники для последующей catalog payload implementation:

- `https://wirenboard.com/en/product/wb-msw-v4/`;
- `https://wiki.wirenboard.com/wiki/WB-MSW_v.4_Modbus_Sensor/en`;
- `https://wirenboard.com/en/catalog/pricelist/`.

До добавления evidence-backed passport/product payload отсутствие точной позиции WB-MSW является `CATALOG/PASSPORT_GAP`, но не отменяет обязательность самой конфигурируемой capability в MVP.

## 8. Изменение каталога

Добавление или изменение паспорта является изменением действующего требования и должно сохранять совместимость идентификаторов либо явно оформлять новую версию паспорта. Добавление товара не должно расширять ресурсы паспорта скрытым образом. Если изделию требуется другой набор ресурсов, для него нужен другой паспорт.
