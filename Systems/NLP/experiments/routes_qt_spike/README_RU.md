# NL Project 3.0 — «Трассы»: рабочие прототипы A/B

**Статус:** только UI spike по Issue #216. Не является частью production. Окончательный вариант интерфейса выбирает пользователь.

## Быстрый запуск (Windows)

Выполнить START_A.cmd или START_B.cmd. Либо из терминала этой папки:

    python routes_demo.py --variant A
    python routes_demo.py --variant B
    python routes_demo.py --variant both

Требуется Python 3.10+ и PySide6 (pip install PySide6). Никакие NL Project/SQLite/AutoCAD не требуются.

**Вариант A:** QTreeView; труба — родитель, каждый физический кабельный сегмент — отдельная выбираемая дочерняя строка; «Без трубы» — группа.

**Вариант B:** QTableView + QAbstractTableModel; состав трубы раскрывается встроенными строками сегментов. Сегменты без трубы показаны самостоятельными строками, без родительской группы.

В обоих: девять одинаковых колонок, поиск по трубе/сегменту/кабелю/точкам, сортировка, фильтр «Все / В трубе / Без трубы / Требует трубы», Ctrl/Shift multi-select, сохранение выбранных ID при сворачивании/фильтрации, явный счётчик скрытого выбора, отключённые команды записи.

## Что попробовать (1–2 минуты)

1. Раскрыть 001.PND25: три кабельных сегмента; длина трубы — final, сегмента — G.
2. Раскрыть вторую трубу; первая остаётся открытой. Ctrl-выделить сегменты в разных трубах.
3. Свернуть первую трубу; увидеть счётчик «скрыто выбранных».
4. Поиск Cat5e показывает подходящие сегменты и их трубы.
5. Проверить фильтры «Без трубы» и «Требует трубы», отсутствие назначения ≠ обязательность трубы.
6. Уменьшить окно, горизонтальный скролл, tooltip длинных названий.
7. Сбросить фильтры, раскрыть/свернуть всё.

## Безопасность и источник данных

Источник строго fixture.py: immutable Snapshot, 12 полностью вымышленных труб и 38 вымышленных CableSegment. НЕ используются реальные номера/маршруты/метры рабочей БД. Обозначения только стилизованы под известный контракт. Несколько сегментов в одной трубе имеют одинаковые физические границы, включая обратную ориентацию, и одинаковую чистую геометрию G.

routes_demo.py импортирует только Python standard library, PySide6 и fixture. Нет SQL, COM, DWG, миграций, сети, записи в файлы или production services. Кнопки «Привязать», «Перенести», «Убрать» disabled; Delete ничего не меняет; UI state хранится только в памяти. capture_and_smoke.py может записывать PNG **только в собственную папку**, не обращаясь к рабочим данным.

## Сравнение

| Признак | A: иерархия | B: плоский журнал |
| --- | --- | --- |
| Qt модель | QTreeView + QStandardItemModel | QTableView + QAbstractTableModel |
| Раскрытие | Штатный треугольник дерева | Клик по первой колонке |
| Без трубы | Группа с дочерними строками | Самостоятельные строки сегментов |
| Рабочая выбираемая единица | CableSegment | CableSegment |
| Выбор трубы | Не выбирает детей | Не выбирает детей |
| Скрытый multi-select | Сохраняется с отдельным счётчиком | Аналогично |

**Ограничения:** синтетические данные, отсутствие production read-model и операций записи; UI spike не служит приёмкой business/domain. Стили основных таблиц повторяют QSS из main/Systems/NLP/src/nl_project_2/presentation/lines_workspace.py: выделение #2f6fab, неактивное #607d99, разделитель header #d9dee7, header min 32px, Segoe UI 9. Внешняя оболочка NL Project не воспроизводится. Ширины колонок адаптированы под «Трассы», не являются утверждённым production набором.

## Проверка 20.10.2026

Два настоящих Qt-окна запущены на Windows 11 10.0.26200, Qt/PySide6 6.11.1, шрифт Segoe UI 9, логический экран 1440×960 (DPR 1.75), окно 1360×775. Проверено: старт, горизонтальный скролл, поиск, фильтры, раскрытие, выделение сегментов и сохранение скрытого выбора в обоих вариантах, все write buttons disabled. Скриншоты созданы настоящим QWidget.grab() через Windows Qt renderer. Оба варианта получают один и тот же immutable Snapshot.

**Не проверено:** реальная Windows DPI-конфигурация 100/125/150/200%, два монитора с различными DPI, живая SQLite и DWG, полноценная стыковка со всем UI NL Project, ручная пользовательская приёмка.

## Решение

Выбрать A или B, указать нужные правки. **Ничего из spike не переносить в production до явного решения пользователя.**
