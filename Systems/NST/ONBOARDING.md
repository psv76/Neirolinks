# NST onboarding: первичный снимок незарегистрированного WB (2.5 candidate)

## Назначение

Работает сразу после обычной установки `nst` на WB с неизвестным serial. Регистрация в GitHub, наличие approved Platform и успешный `nst sync` **не требуются**. Само исследование не регистрирует контроллер и не изменяет инженерную логику.

## Команды

```sh
nst --json onboarding collect
nst --json onboarding channels
```

Первая команда создаёт краткий снимок: serial/fingerprint, hostname, список установленных профильных Debian-пакетов, настроенные Modbus-устройства. Вторая создаёт отдельный архив с конфигами и **предварительной** картой подписей.

Архивы лежат в `/mnt/data/var/lib/neirolinks/nst/diagnostics/nst-onboarding-<UTC>-<ID>.tar.gz`. Путь и SHA-256 возвращаются в результате CLI. Ничего не отправляется автоматически ни в GitHub, ни в ChatGPT.

## Состав архива

- `hardware.json` — идентичность, список выбранных установленных пакетов, настроенные в Modbus устройства.
- `config/etc/wb-mqtt-serial.conf` — очищенная копия настроенных Modbus-устройств и портов.
- Для `channels`: `config/etc/wb-webui.conf` — очищенный Web UI; `widget-channels.csv` — подпись, виджет, панель, MQTT path; `channel-map.json` — сопоставление устройств по serial / виджетам / MQTT metadata и отдельно устройства и каналы без **явной** подписи из виджета.
- `config-inventory.json`, `checksums.sha256`, `meta.json` (включая предупреждения).

MQTT metadata считываются **только read-only**, из retained `/devices/+/meta` и `/devices/+/controls/+/meta`, с ограничением времени и размера. Это даёт шанс обнаружить 1-Wire, виртуальные и другие MQTT-устройства, которых нет в `wb-mqtt-serial.conf`. Если MQTT недоступен, архив создаётся с предупреждением и неполной видимостью.

## Интерпретация

Подпись из виджета — свидетельство ранее выполненного именования, **не доказательство** подключения или правильности назначения. Отсутствие подписи означает отсутствие явной подписи в просмотренных виджетах, а не отсутствие маркировки в других источниках. Устройство в serial конфиге может быть отключено или физически отсутствовать; MQTT metadata отражают только доступные сообщения, не независимую проверку проводки.

Не переносить данные между объектами. Оператор передаёт архив в инженерный чат. Инженер по результатам проверки оформляет первичную карту каналов в `Objects/<object>/`; отдельным шагом создаёт `Objects/<object>/controllers/<serial>.json` со статусом `planned` или `active` **после согласования назначения**, не по догадке. Затем CI генерирует controller registry и только approved Platform меняет разрешённый desired state.

## Безопасность

Конфиги проходят существующий NST secret-redaction. Размер каждого файла ограничен 2 MiB, MQTT metadata — 3 MiB, max 10 000 записей. В архив не входят MQTT control values, ключи, пароли или содержимое программных правил. Однако виджеты, имена комнат и устройств являются внутренними объектными сведениями: **не публиковать архивы публично**. Файлы будущего объекта нельзя загружать в публичные GitHub Issues.
