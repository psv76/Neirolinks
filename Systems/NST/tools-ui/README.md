# NEIROLINKS Tools 1.0 — защищённый веб-интерфейс к NST

Отдельный Debian-пакет `neirolinks-tools` устанавливается вместе с **approved NST 2.5**. NST остаётся независимой консольной утилитой без собственного демона. NEIROLINKS Tools — необязательная графическая оболочка.

## Установка одной командой (новый WB)

На контроллере **должен быть создан администратор WebUI**. Под root выполнить:

```sh
wget -qO - https://raw.githubusercontent.com/psv76/Neirolinks/main/Systems/NST/tools-ui/tools/install_latest.sh | bash
```

Команда скачивает проверяемый загрузчик из `main`. Он читает GitHub Releases API, выбирает **максимальную approved-версию** `neirolinks-tools-approved-package-X.Y` (не draft, не prerelease), проверяет Release/catalog SHA-256, комплект и обе Debian-подписи SHA256, после чего запускает `sh install.sh` в закрытой временной папке и удаляет временные файлы.

Без установки (только проверить выпуск/доступ к GitHub/хеши):

```sh
wget -qO - https://raw.githubusercontent.com/psv76/Neirolinks/main/Systems/NST/tools-ui/tools/install_latest.sh | bash -s -- --check
```

Только проверенный approved комплект, никакого `git clone main` или сборки из текущей ветки. При сетевой ошибке, неверном SHA, отсутствии администратора WB или обнаружении старого вручную установленного пилота работа прерывается **до установки**. Используется HTTPS GitHub. На случай отказа GitHub API/доступа к сети остаётся офлайн ZIP ниже.

Важно: как при любом `wget | bash`, загрузчик берётся из текущего `main`, поэтому запускать команду следует только из доверенного репозитория NEIROLINKS. Для фиксации конкретного содержимого загрузчика допустимо заменить `main` на проверенный commit SHA.

## На новом WB (Trixie / HomeUI 2609)

Обязательная предварительная настройка: создать администратора в **Настройки → Пользователи**. На WB **без пользователей** HomeUI автоматически предоставляет admin и service gate не защищает от соседей по сети (официальное ограничение WB). Не выставлять порты gate в Интернет.

1. Получить именно approved пакеты `nst_2.5_all.deb` и `neirolinks-tools_1.0_all.deb` по SHA256 из GitHub Releases; перенести на WB в отдельную рабочую папку.
2. Запустить одной командой:
   ```sh
   apt-get install -y ./nst_2.5_all.deb ./neirolinks-tools_1.0_all.deb
   ```
3. Обновить WebUI. В меню: **NEIROLINKS → Сервис / Спрут / Документация**.
4. Открыть Сервис, выполнить «Первичная диагностика» и «Карта каналов», скачать архивы.
5. Передать архивы инженеру; регистрация serial/object/role выполняется отдельно после проверки. `nst sync` при первичной диагностике не запускается.

Внутренний web backend: `127.0.0.1:18415`. Штатный WB service gate: порт `28415`, роль **admin**; меню содержит три дочерних ссылки `/open-neirolinks-tools` с вкладками `#service/#sprut/#docs`. Это новая вкладка браузера (официальный механизм HomeUI), а не React-страница внутри WebUI. Gate на выделенном порту не работает через стандартный WB Cloud WebUI tunnel; нужны LAN/Tailscale или настройка отдельного WB Cloud Service после проверки прав.

## Безопасность и технические границы

- Пользователь `nst-tools`; systemd, loopback HTTP, запрет shell endpoint. Фиксированный sudo allowlist только для read-only executor (`status,check,inventory,channels,diagnostics`).
- Серверный state ограничивает одновременные задания; same-origin POST с отдельным заголовком; download с токеном ограниченного срока под авторизацией gate.
- `nst onboarding` допускается на неизвестном WB. Автоматической регистрации serial, установки/обновления компонентов или синхронизации нет.
- Никакие WB-rules, HHM, MQTT команда/уставка и реле не изменяются.
- Кандидаты на каналы из виджетов могут содержать ошибки монтажа. Имя из виджета — только предварительное свидетельство.
- Архивы содержат чувствительные объектовые сведения. Не размещать их в публичном GitHub.
- Пилотное вручную установленное окружение Иволги намеренно не перезаписывается: `preinst` блокирует установку поверх файла существующего `/etc/systemd/system/neirolinks-tools.service`, старого nginx include или local custom-menu. Миграция пилота — отдельная работа.
- Пакетная деинсталляция останавливает только `neirolinks-tools` и удаляет его menu/gate; штатные сервисы WB/HHM и данные NST сохраняются.

## Проверка

```sh
dpkg-query -W nst neirolinks-tools
systemctl is-active neirolinks-tools
wb-homeui-gates check
curl --fail http://127.0.0.1:18415/
```

`wb-homeui-gates apply` выполняется postinst и перезагружает только nginx; это сетевое изменение и должно проверяться на новых WB при ПНР. Новый раздел появляется после установки обоих пакетов, не после одиночного `nst_2.5_all.deb`.

Разработка: GitHub Issue #215; приёмка установки и security на новом физическом WB обязательна до массового внедрения. Подразделы «Спрут» и «Документация» пока честно показывают заглушки; реализация Sprut Configurator и объектовых ссылок отдельна.
