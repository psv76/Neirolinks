# Карта каналов — 04 90 Лосиный

**Статус: подтверждённая карта конфигурационных привязок WB WebUI; физический монтаж не проверен.** Каждая строка указывает дословную подпись в виджете, а не акт проверки каналов на объекте. Для общих сведений о контроллере и Modbus см. [README](README.md) и [DEVICE_INVENTORY.csv](DEVICE_INVENTORY.csv).

Для этой карты прочитаны `wb-webui.conf`, `wb-mqtt-serial.conf`, `widget-channels.csv`, `channel-map.json` и доступная одноразовая выборка MQTT metadata. **В конфигурации есть 5 панелей / 18 виджетов, 77 ссылок виджет→канал, 70 уникальных каналов, 63 ссылки с явной подписью, 56 уникальных каналов с явной подписью.**

5. Исходные объектовые конфиги и архив не опубликованы в публичном GitHub. Полный точный список 77 привязок — [WIDGET_CHANNELS.csv](WIDGET_CHANNELS.csv). Имена из исходника сохранены без нормализации, включая неполные подписи.

| `902.10_MSW_CO/{Humidity,CO2,Current Motion}` | Выведены в виджет «Климат», но явные подписи пустые |

**Полный список 102 не подписанных явно control paths именно настроенных Modbus-устройств**, обнаруженных в MQTT metadata, сохранён в [UNLABELED_MODBUS_METADATA.csv](UNLABELED_MODBUS_METADATA.csv). В него входят служебные и настроечные каналы WB-MSW; это список для классификации, **а не ведомость 102 незадействованных физических каналов**.

Для датчиков WB-MSW имеется множество дополнительных MQTT-метаданных (`Serial`, `Buzzer`, `Illuminance`, настройки LED, VOC, CO₂). Они не означают дополнительные **физические** неиспользованные линии. MQTT device `wb-w1` тоже обнаружен, но отдельных именованных каналов в представленном metadata нет.

## 9. Устройство адреса 164 — уточнение предыдущей карты

В `wb-mqtt-serial.conf` RS-485-2 адрес **164**, тип **WB-MAI2-mini/CC-since-fw-4.32**, но нет заданных `id` и `name`. В retained MQTT metadata действительно найден `wb-mai2-mini_164` с драйвером `wb-modbus`, а виджет «Датчики» подписывает `wb-mai2-mini_164/input_1_current` как **«датчик давления»**.

Поэтому: **16/16 настроенных Modbus-устройств сопоставимы с MQTT metadata по источникам** (15 напрямую по конфигурационному ID + одно по адресу/типу). Наличие MQTT metadata не подтверждает, что устройство отвечает именно сейчас. Нестандартная запись без явного `id` выявила ограничение учётчика NST 2.5; записано в Issue #270.

Не подменять `input_1_current` давлением в барах: это токовый канал, фактический масштаб/калибровка `input_1_value` без проверки не установлены.

## 10. План ПНР и уровень уверенности

- **Подтверждено документом:** конфигурации, адреса, MQTT ID, подписи виджетов, контекст панели, retained MQTT metadata, совпадение fingerprint.
- **Гипотезы:** физическое назначение отдельных выходов и датчиков, связь термостата/датчика/реле, инверсия тёплого пола, живой опрос Modbus.
- **Не проверено:** проектный номер `MODULE.CHANNEL`, клеммы, кабели, фактические состояния исполнительных механизмов и нагрузки, гидравлическая защита, исправность датчиков и работоспособность ПНР.

Перед подачей управляющих команд сначала сверить по месту цепи `A04/K1–K2`, `A03/K3`, `A05/Output K1` и инверсные сервоприводы тёплого пола. До этого `nst sync` не запускать. Контроллер `AGYPLABX` остаётся в GitHub в состоянии `planned`.
