## Опыт «Севера» — кандидаты для дальнейшей разработки

Все пункты ниже: **[Предположение] Взято как опыт другого объекта, применимость не подтверждена.** Ничего из этого пока не установлено на «05 45».

| Опыт из handoff | Практическое применение после проверки |
|---|---|
| Разделение температурной обработки, объектовой карты аварий, общего механизма уведомлений и аналитических состояний | Разделить ответственность будущих модулей; не считать упомянутые в handoff `10_DeltaTemp.js`, `20_AlarmRules.js`, `WBHelpers.js`, `30_EquipmentState.js` установленными здесь |
| Таймер температуры запускается при переходе условия, а не заново при каждом изменении значения | Избежать бесконечного откладывания уведомления; гистерезис и выдержки назначить для нового объекта |
| Общий фильтр аварий скрывал короткие события | Согласовать задержку по каждой причине; событие в истории и доставка Telegram — разные факты |
| Восстановление группы причин только после исчезновения всех причин | Сначала установить состав группы и полярность каждой причины; не скопировать маску аварий «Севера» |
| Сообщение содержит объект, зону/МО, оборудование и состояние | Сформировать сообщение, достаточное для выхода бригады; отдельно проверить время, причины, отправку и восстановление |
| Нормализованные состояния и совмещённый график температуры/К/ВО | Анализировать после обеспечения оповещений; отсутствие сигнала не приравнивать к норме |
| Разность температур при асинхронных измерениях | Применять только при наличии подтверждённых пар датчиков и правил свежести данных |
| Режим К/ВО — наблюдение, не диагноз | Не объявлять «оттайку», «открыта дверь», «загрузка» без соответствующего источника |

Число камер, адреса Modbus/WBIO, 1-Wire ID, датчики, Tmax/Delta, задержки, инверсии, Grafana UID, host и таблицы БД «Севера» не приняты для нового объекта. Даже расшифровку РКС и значение «Авария конденсатора» нужно сверить с комплектной схемой: сохранены исходные подписи нового объекта.

## Основа будущего конструктора

Принято по заданию пользователя: общий принцип обработки, разные наборы камер и установок, один/два ВО на компрессор, мониторинг без управления. На данном этапе сохраняются фактические ссылки и неопределённости; runtime и общий шаблон ещё не создаются.

Для дальнейшей модели нужны отдельные сущности: камера/зона, МО, установка, компрессор, список ВО, физический канал, нормализованное событие, политика уведомления. Связи камера ↔ установка, проектный `MODULE.CHANNEL`, активный уровень, качество/свежесть, пороги и задержки заполняются по подтверждённым данным. Это направление разработки, не готовая схема конфигурации.
