# Онигири — контракт будущих правил мониторинга (не исполняемый код)

Головная задача: [#305](https://github.com/psv76/Neirolinks/issues/305).

## Принцип
WB-rules не управляет холодильной автоматикой. **Физические входы только читаются**, команды на компрессор/клапаны/ТЭНы/конденсатор не пишутся. Выходные каналы отсутствуют в этом контракте. Виртуальные состояния для оператора — отдельные каналы без дублей физических температур и давления.

## Планируемые блоки
1. Объектная конфигурация: входы по [CHANNEL_MAP.md](../CHANNEL_MAP.md), роль и подпись, подтверждённый активный уровень, источник и свежесть данных, приоритет, фильтр кратковременных состояний, группа восстановления.
2. Нормализация: `normal / alarm / unknown` — не считать потерю MQTT нулём и не «автоматически восстановленной» аварией. Короткие аварии сохранять в событиях, решение о нотификации по индивидуальному правилу.
3. Событийный монитор: начало/окончание каждой причины, защита от спама, корректный restart и восстановление, независимые причины.
4. Уведомления: объект «Онигири», оборудование (КМ/ВО/КД), причина, время, фактическое восстановление. Сервис доставки выбирать после аудита установленной системы, credentials в GitHub не хранить.
5. SVG: перевод событий/измерений в ID панели после проверки контрактов. КМ/ВО/КД не выводить по эвристике и таймерам как подтверждённый физический факт.

## Входные каналы (read-only)
```text
wb-gpio/EXT1_IN1
wb-gpio/EXT1_IN3..EXT1_IN13
wb-w1/28-0000109d9767
wb-mai2-mini_197/input_1_value
wb-mai2-mini_197/input_2_value
wb_ups_v3_92/battery_status
```
`EXT1_IN2` неизвестен и не назначается.

**Входы alarm:** `EXT1_IN6..13` только после подтверждения активного уровня и корректного контракта. По описанию Алексея авария ТЭНа — не первого уровня, но это не даёт права назначать приоритеты остальным без подтверждения.

## Выходы
Нет физических выходов. Пока неизвестны наличие и имена виртуальных каналов и реальный установленный сервис уведомлений. Решение «один физический канал — один писатель» действует.

## Что нужно прежде, чем писать исполняемые JS
- Инвентаризация live `/etc/wb-rules`, модулей, сервиса уведомлений.
- `wb-mqtt-gpio`/serial конфиги, живые MQTT values/meta и обрыв/задержка.
- Таблица `active_value` и значений нормального/аварийного сухого контакта.
- Подтверждённая система доставки и тестовый получатель (секреты вне репозитория).
- После согласования: полный код каждого файла ES5 по [стандарту](../../../EIM/Standards/WB_coding_standard.md), анимация и логи по [WB logging](../../../EIM/Standards/WB_logging_standard.md). ПНР отдельно.

Не переносить реализацию «Севера» без чтения и проверки исходника. Не разрабатывать исполняемые правила без полярности.
