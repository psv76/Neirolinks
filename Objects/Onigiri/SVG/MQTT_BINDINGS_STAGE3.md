## Изменения визуального контракта

| Элемент SVG / сигнал | Логика при активности |
|---|---|
| `km_pipes_active` и `liquid_on` ← `EXT1_IN3` | Три участка активны: ВО→КМ синий, КМ→КД красный, КД→клапан «Холод» оранжевый. При 0 — нейтральные трубопроводы |
| `feed_on`, `valve_cold_on` ← `EXT1_IN5` | Клапан «Холод» и труба до ВО синие |
| `cond_fan_1_rotor`, `cond_fan_2_rotor` плюс их idle/active изображения ← `EXT1_IN14` | Вращение зелёных лопастей КД, без влияния на трубы; оси из предыдущих версий не менялись |
| `hotpipe_on`, `hotvalve_on`, `feed_defrost`, `suction_defrost`, `suction_tail_defrost`, `evap_coil_defrost` ← `EXT1_IN15` | Вертикальная труба и клапан оранжевые, ВО→КМ жёлтая, клапан «Холод»→ВО оранжевая, регистр ВО тёплого цвета |
| `value_p0` ← `wb-mai2-mini_197/input_1_value` | Чтение пересчитанного давления, округление 0,1 bar без ×1000 |
| `value_pc` ← `wb-mai2-mini_197/input_2_value` | То же, второй датчик |
| `value_temperature` | Сохраняется ранее проверенная привязка с округлением 0,1°C |
| `raw_ext1_in6..13` / `alarm_pill_in6..13` | Вместо 0/1/true/false — нейтральная метка причины (0), красная плашка «!» (1), «?» до чтения |
| `alarm_km_outline_in6..9`, `alarm_vo_outline`, `alarm_heater_outline`, `alarm_cond1_outline`, `alarm_cond2_outline` | Отдельные сдержанные красные окружности/контуры неисправного оборудования по подтверждённым аварийным входам |

Сигналы `EXT1_IN5`, `EXT1_IN14`, `EXT1_IN15`: **1 принимается активным для тестового SVG**; точную полярность и физическое наличие этих каналов на WB ещё необходимо проверить. Отображаемая активность клапана — **сигнал**, не доказательство положения/расхода. При одновременной активности IN5 и IN15 оранжевая оттайка имеет графический приоритет, физическую допустимость состояний не оценивать на основании SVG.

Питание `EXT1_IN1`, status ИБП и сырые AI1/AI2 убраны из нижней информационной полосы для визуальной чистоты; в объектовой карте они сохранены, и в будущем могут быть обработаны правилами/отдельным виджетом.

## Проверки
- XML/JSON разобраны; все 54 SVG ID существуют и не повторяются; все `write.enable=false`.
- В браузере v4.8 **не проверена**: Chromium на рабочей среде блокирует локальные SVG-URL. Контрольные кадры cooling/off/defrost/alarms построены через CairoSVG на тех же слоях, с подстановкой статических состояний.
- Трубы и клапаны фотографические bitmap-маски, выровненные по исходному изображению; нет новых рисованных векторных труб поверх старых.
- Анимация ВО: центры унаследованы из принятой v4.5; анимация КД использует прежние фиксированные transform-origin, нужна live-проверка.
- Важная проверка: переход IN3/IN5/IN14/IN15 на live, соответствие P₀/Pc истинным манометрам и безопасность отображения при обрыве MQTT.

## Внедрение
Перед заменой в HomeUI обязательно экспортировать текущие SVG и список привязок; устанавливать **вместе** onigiri.svg + SVG_bindings.json; всю панель WB конфигурацией старого экспорта не перезаписывать. Физический контроллер и холодильная автоматика этим документальным изменением не затронуты.

Внедрение на WB, рассылка уведомлений и настройки wb-rules остаются отдельными этапами Issue #305.
