# Онигири — привязка аварий к SVG (v4.7, 2026-10-30)

Головное [Issue #305](https://github.com/psv76/Neirolinks/issues/305).

## Подтверждение пользователя

Восемь аварийных входов `EXT1_IN6`–`EXT1_IN13`: **1 = авария**, **0 = норма**. Это относится только к данным восьми каналов; не говорит о сетевой доступности/актуальности MQTT.

## Подготовлен графический прототип v4.7

Из проверяемого артефакта v4.6 сделана следующая версия:

- 8 элементов `raw_ext1_in6`–`raw_ext1_in13` сохраняют показания 0/1, но окрашивают число красным при 1, серым при 0.
- 8 добавленных ID `alarm_pill_in6`–`alarm_pill_in13` меняют цвет карточки: красный при аварии, нейтральный при 0; начальное неизвестное состояние — янтарный.
- Остальные 23 привязки сохранены; стало **31**. Все `write.enable=false`.
- Физические крыльчатки, центры вращения, статичный рисунок, компрессорные трубы, клапаны и ТЭНы **не изменялись**.
- Режимы: наглядная авария по каждому сигналу, но без выдуманной классификации критичности, управления, уведомлений или косвенного определения оттайки.

## Доказательства версии

Файл `onigiri.svg`: SHA256 `fa2b7be83d93ce79c296895d120fa0b1ea8055ae701af3c662a53744a80f0874`.

Файл `SVG_bindings.json`: SHA256 `595e75538d806c8ebc20a5dfd8f8de13e1c2352549798bb1e2a4417849c54a0d`.

Архив SVG+bindings+предпросмотры передан в чате; **байты полного SVG пока не добавлены в GitHub**. Мнемосхема содержит гибридную графику (растровые части внутри SVG). Для подготовки на будущем контроллере нужна именно эта пара файлов, потому что binding JSON ссылается на восемь новых ID в v4.7.

## Проверено

- Парсинг XML и JSON; все 31 ID существуют в SVG.
- Нулевые управляющие write-привязки.
- Все исходные SVG-слои `<image>` сохранили позиции, размеры и содержимое. Центры вращения не изменены.
- Созданы контрольные SVG-рендеры для всех нулей и для нескольких активных аварий; красные карточки визуально проверены.
- ZIP integrity проверен.
- **Chromium/HomeUI для этой версии не проверен**: тестовый браузер в текущей среде заблокировал открытие HTML, установка на контроллер не выполнялась.

## Что проверить на WB

1. Backup установленного `onigiri.svg` и всех текущих параметров существующей панели.
2. Заменить SVG на v4.7 и **целиком** заменить список параметров на 31 элемент из `SVG_bindings.json`.
3. Сверить входы `IN6..IN13` во вкладке «Сигналы»: 0 — нейтральный, 1 — красный. Проверить также отсутствие регрессий в KM/VO и температуре.
4. Остановить при расхождениях и восстановить предыдущую версию.

Полярности IN1/IN5/ИБП не подтверждены; P₀/Pc пока не сопоставлены с аналоговыми входами, связь/ретейны нуждаются в контроле свежести. Для реальных уведомлений необходима отдельная разработка и проверка `wb-rules` по [Rules/ALARM_RULES_SPEC.md](../Rules/ALARM_RULES_SPEC.md).
