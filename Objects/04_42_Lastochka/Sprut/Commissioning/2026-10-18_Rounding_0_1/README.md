# 04 42 Ласточка — округление до 0,1 бар + исправление диагностики при 4 мА (подготовлено, не установлено)

Дата: 18.10.2026. Связь: [Issue #202](https://github.com/psv76/Neirolinks/issues/202).

**Назначение:** заказчик видит давление отопления с одной цифрой после запятой в Sprut, инженер — то же значение в поле `pressure_bar` виртуального устройства WB. Дополнительно устранено ложное признание датчика неисправным при 4 мА / 0 бар и поправке −0,2 бар. Все остальные каналы оставлены с прежней точностью.

## Готовые целые файлы для замены

1. [`414_Pressure_makeup.js`](414_Pressure_makeup.js) — полный 714-строчный скрипт WB. Изменения относительно канонического `Objects/04_42_Lastochka/Wirenboard/wb-rules/414_Pressure_makeup.js`: (а) **при записи в виртуальный `pressure_bar`**, `null` сохраняется, иначе `Math.round(s.pressure * 10) / 10`; (б) в `sensor()` после поправки давление ограничивается снизу нулём: `Math.max(0, pRaw + STATE.offsetBar)`, при этом исходный `raw` и ток проверяются как прежде. Проверка `p < 0` удалена как более не применимая; верхний предел `p > 6` сохранён. **Во всех расчётах порогов, журналировании и управлении физическим K5 используется неокруглённое скорректированное `s.pressure`; другие поля сохраняют прежнюю точность.**
2. [`04_42_Lastochka_Pressure_Makeup_v1.json`](04_42_Lastochka_Pressure_Makeup_v1.json) — полный MQTT-шаблон Sprut, десять исходных сервисов. Изменён **только** `minStep` характеристики `Давление отопления/C_Double`: `0.001` → `0.1`. Привязка остаётся `/devices/(1)/controls/pressure_bar`. Команды `enabled/on`, `reset_alarm/on`, `retain=false`, `SwitchOffTime=0.1` сохранены.

Канонические исходники в `main` пока **не заменены**: пользователь ещё не подтвердил установку и работу этих вариантов. Не путать GitHub-кандидат с уже установленным на живом контроллере.

## Последовательность установки пользователем

1. Убедиться, что реальная подпитка **не выполняет цикл**, и только затем заменить в WB **весь файл `414_Pressure_makeup.js`**, не отдельные фрагменты. Сохранение/перезапуск скрипта выполняет `commandOff("Старт скрипта")`, устанавливает 60-секундную стартовую блокировку, сбрасывает оперативные счётчики циклов; это не пассивная UI-настройка.
2. Проверить значение `lastochka_pressure_makeup/pressure_bar` в WB и давление на плитке Sprut. Если Sprut показывает уже одну десятую без лишних разрядов, **не менять рабочий шаблон без необходимости**: он уже получает округлённое MQTT-число.
3. Если Sprut сохраняет лишние знаки отображения — заменить полный JSON-шаблон в каталоге Sprut на подготовленную версию с `minStep=0.1`, предварительно сохранив существующую версию. Не удалять рабочий Accessory 180 и не создавать второй, не включать прямое K5. Поведение применения `minStep` к **существующему** аксессуару в beta 3.0 должно быть проверено, может требовать обновления шаблона; наугад переподключать устройство нельзя.
4. Сообщить фактический результат WB и Sprut, затем синхронизировать канонические файлы в main и Issue #202.

## Пределы решения и проверка диагностики

- При фактическом 1.178 бар индикация округлится до **1.2 бар**, хотя автоматика продолжит сравнивать **1.178 < 1.2** и может не считать цикл успешным. Это намеренно только изменение индикации.
- Формат `minStep=0.1` задаёт шаг характеристики Sprut, а не гарантирует принудительный суффикс `.0` на всех клиентах.
- **Исправлено в подготовленном скрипте:** при 4 мА и `raw=0` давление после поправки −0,2 бар ограничивается нулём, датчик исправен по электрической диагностике; низкое давление остаётся реальным основанием для подпитки и отдельной тревоги, если разрешено. При **0 мА** и пороге `currentLowMa=3.6` датчик остаётся неисправным; ошибка блокирует начало цикла и останавливает действующий цикл. Остались проверки свежести обоих каналов (120 с), raw 0–6000 и токов выше 20,5 мА.
- Выполнены расчётные тест-кейсы вне живой установки: `0 мА/0 → авария`; `3.5 мА/0 → авария`; `4 мА/0 → p=0, без ошибки датчика`; `4 мА/200 → p=0, без ошибки датчика`; `12 мА/3000 → p=2.8`; `20.6 мА/6000 → авария`; `12 мА/raw=-1 или raw=6001 → ошибка диапазона`. Не являются испытанием датчика на живом WB.
- Валидация: полный JS получен из актуального канонического исходника GitHub. В нём изменены только `sensor()` для корректного нуля после поправки и публикация `pressure_bar` для округления; JSON разобран, 10 сервисов и все командные топики сохранены. **Проверки на WB и Sprut beta после установки ещё не было.**
