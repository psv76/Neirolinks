# 04 42 Ласточка — округление давления до 0,1 бар (подготовлено, не установлено)

Дата: 18.10.2026. Связь: [Issue #202](https://github.com/psv76/Neirolinks/issues/202).

**Назначение:** заказчик видит давление отопления с одной цифрой после запятой в Sprut, инженер — то же значение в поле `pressure_bar` виртуального устройства WB. Все другие каналы оставить с прежней точностью.

## Готовые целые файлы для замены

1. [`414_Pressure_makeup.js`](414_Pressure_makeup.js) — полный 714-строчный скрипт WB. Отличие от канонического `Objects/04_42_Lastochka/Wirenboard/wb-rules/414_Pressure_makeup.js` ровно в одном месте: **при записи в виртуальный `pressure_bar`**, `null` сохраняется, иначе `Math.round(s.pressure * 10) / 10`. **Во всех расчётах с порогами, журналировании, физическом K5, диагностике и других полях остаётся неокруглённое `s.pressure` либо прежние `rounded(...)`.**
2. [`04_42_Lastochka_Pressure_Makeup_v1.json`](04_42_Lastochka_Pressure_Makeup_v1.json) — полный MQTT-шаблон Sprut, десять исходных сервисов. Изменён **только** `minStep` характеристики `Давление отопления/C_Double`: `0.001` → `0.1`. Привязка остаётся `/devices/(1)/controls/pressure_bar`. Команды `enabled/on`, `reset_alarm/on`, `retain=false`, `SwitchOffTime=0.1` сохранены.

Канонические исходники в `main` пока **не заменены**: пользователь ещё не подтвердил установку и работу этих вариантов. Не путать GitHub-кандидат с уже установленным на живом контроллере.

## Последовательность установки пользователем

1. Убедиться, что реальная подпитка **не выполняет цикл**, и только затем заменить в WB **весь файл `414_Pressure_makeup.js`**, не отдельные фрагменты. Сохранение/перезапуск скрипта выполняет `commandOff("Старт скрипта")`, устанавливает 60-секундную стартовую блокировку, сбрасывает оперативные счётчики циклов; это не пассивная UI-настройка.
2. Проверить значение `lastochka_pressure_makeup/pressure_bar` в WB и давление на плитке Sprut. Если Sprut показывает уже одну десятую без лишних разрядов, **не менять рабочий шаблон без необходимости**: он уже получает округлённое MQTT-число.
3. Если Sprut сохраняет лишние знаки отображения — заменить полный JSON-шаблон в каталоге Sprut на подготовленную версию с `minStep=0.1`, предварительно сохранив существующую версию. Не удалять рабочий Accessory 180 и не создавать второй, не включать прямое K5. Поведение применения `minStep` к **существующему** аксессуару в beta 3.0 должно быть проверено, может требовать обновления шаблона; наугад переподключать устройство нельзя.
4. Сообщить фактический результат WB и Sprut, затем синхронизировать канонические файлы в main и Issue #202.

## Пределы решения и отдельная проблема

- При фактическом 1.178 бар индикация округлится до **1.2 бар**, хотя автоматика продолжит сравнивать **1.178 < 1.2** и может не считать цикл успешным. Это намеренно только изменение индикации.
- Формат `minStep=0.1` задаёт шаг характеристики Sprut, а не гарантирует принудительный суффикс `.0` на всех клиентах.
- Дефект диагностики **4 мА + поправка −0.2 бар → −0.2 бар → ошибка диапазона** ранее обсуждался, но **в этом изменении не исправляется без отдельного подтверждения**.
- Валидация: полный JS получен из актуального канонического исходника на GitHub с однострочным изменением; JSON разобран, 10 сервисов и все командные топики сохранены. **Проверки на WB и Sprut beta после установки ещё не было.**
