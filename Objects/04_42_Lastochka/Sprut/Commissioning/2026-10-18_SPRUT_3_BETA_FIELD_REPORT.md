# 04 42 Ласточка — интеграция №414 в Sprut 3.0 beta: полевой отчёт 18.10.2026

Issue: [#202](https://github.com/psv76/Neirolinks/issues/202), родительский навигатор: [#201](https://github.com/psv76/Neirolinks/issues/201).

Статус: представление в Sprut и базовая командная интеграция настроены пользователем на работающем объекте. Push-сценарий v1.0 установлен пользователем и проверен с положительным результатом; исправление v1.1 **предложено к полной замене, но его проверка на live не подтверждена**. Изменений алгоритма №414 и физического K5 в ходе документирования не производилось. Нельзя трактовать этот отчёт как полную физическую приёмку подпитки.

## Конфигурация

- Sprut.hub WB8, Sprut 3.0.0b (20131), каталог шаблонов 8621; WB8 stable wb-2609.
- MQTT-контроллер `mqtt_1` v0.24.0; исходное WB-устройство: `/devices/lastochka_pressure_makeup`, драйвер `wb-rules`.
- Рабочая карточка **Accessory 180**, `Подпитка отопления`, производитель NEIROLINKS, модель `04_42_Lastochka_Pressure_Makeup_v1`, комната `Котельная`.
- На **рабочем столе оставлено только давление отопления**. Переключатель «Автоподпитка» скрыт с рабочего стола по решению пользователя, чтобы исключить случайное отключение; внутри карточки он доступен. Прочие статусы, диагностика и кнопка «Сбросить аварию» доступны только внутри карточки. Статусная строка очищена. Мосты в сторонние голосовые системы для устройства отключены пользователем.
- Рабочий шаблон сохранён целиком: [`Templates/04_42_Lastochka_Pressure_Makeup_v1.json`](../Templates/04_42_Lastochka_Pressure_Makeup_v1.json). Пользователь вставлял полный JSON через редактор каталога Sprut; непосредственная загрузка файла из GitHub ранее выдавала «Невалидный шаблон», причина не подтверждена.
- Запись команды разрешения: `/devices/lastochka_pressure_makeup/controls/enabled/on` (0/1), `retain=false`.
- Импульс сброса: `/devices/lastochka_pressure_makeup/controls/reset_alarm/on` (1→0), `SwitchOffTime=0.1`, `retain=false`.
- Сброс аварии очищает программную блокировку, счётчики и задержки. При низком допустимом давлении и включённых разрешениях **может без ожидания запустить новый цикл**. По выбору пользователя дополнительное подтверждение не предусмотрено; кнопка находится внизу карточки и не выводится на рабочий стол.

## Обнаружение и устранение дублирования

- Native автоматически созданный Accessory **179**, serial `wb:lastochka_pressure_makeup`, был «Не в сети»; при этом WB публиковал актуальные MQTT meta и controls, а `mqtt_1` видел исходное устройство как `Online: true`. В `mqtt_1 → Обнаруженные` было устройство без привязанных аксессуаров. Причина рассогласования native карточки не установлена.
- Создан кастомный MQTT Accessory **180**; подтверждены актуальные значения давления/состояния и скрытие технических плиток.
- Пользователь проверил, что 179 не используется в сценариях, и удалил его.
- Прямое управление физическим K5 через Sprut было в Accessory **88** — `Controller/mqtt_1/Child/wb-mr6cu_196/K5/`, сервис `Клапан подкачки` с `On.write=true`. Пользователь отключил переключатель «Создавать устройство по шаблону» и удалил Accessory 88 после проверки отсутствия зависимостей; плитка клапана пропала из котельной.
- `wb-mr6cu_196/K5` всё ещё виден в списке **«Обнаруженные»**: удаление аксессуара не запрещает ручное переподключение. **Нельзя утверждать, что запись K5 запрещена на уровне брокера или RBAC; в действующем интерфейсе Sprut прямого K5 больше нет.** Скрипт №414 остаётся физическим владельцем команд.

## Полевые проверки MQTT / PROBE

Изолированный шаблон [`Commissioning/04_42_Lastochka_Pressure_Makeup_PROBE_v1.json`](04_42_Lastochka_Pressure_Makeup_PROBE_v1.json) использовал **только** `lastochka_pressure_makeup_probe` (не рабочий канал и не K5).

- Публикация `pressure_bar/meta/type=value` с retain — обнаружен тестовый источник.
- Публикация тестового `pressure_bar=1.345` с retain — Sprut показал **1.345 бар**.
- При включении Sprut отправил ровно `/devices/lastochka_pressure_makeup_probe/controls/enabled/on | 1`, retain=0.
- При выключении Sprut отправил `.../enabled/on | 0`, retain=0.
- Одно нажатие «Сбросить аварию» отправило `.../reset_alarm/on | 1` и затем `.../reset_alarm/on | 0`, оба retain=0.
- Новый подписчик в течение 5 секунд не получил сохранённых reset-команд; только `Timed out`.
- После F5 тестовой веб-страницы за 45 секунд MQTT-команды повторно не публиковались; только `Timed out`.
- Испытание при рестарте самого Sprut, двойном нажатии и **фактический сброс на работающем №414 через Sprut** не выполнялись/не подтверждены.
- Пользователь удалил PROBE-аксессуар и PROBE-шаблон из Sprut. Затем удалил с брокера retained тестовые топики `/devices/lastochka_pressure_makeup_probe/controls/pressure_bar/meta/type`, `.../pressure_bar`, `.../enabled` (пустые retained-публикации). Архивный PROBE-файл в репозитории оставлен как доказательная база.

## Уведомления для заказчика

- Службы уведомлений Sprut: Web v1.0 работает; Telegram `Urgen_bot` присутствует, но пользователь подтвердил, что сообщения через Telegram не доходят. Push в Web на iPhone заказчика получен; Android-планшет дополнительно зарегистрирован пользователем. Отдельная регистрация требуется для каждого браузера/устройства. Настройка — отправлять всем зарегистрированным клиентам и всем доступным службам без явного списка получателей, через `Notify.text(message).send()`.
- Блочный тест отправки Web использовался отдельно; пользователь установил логический сценарий **«414 — Push-уведомления о подпитке отопления»** (v1.0) и сообщил, что он работает.
- Название «Ласточка» в push намеренно не используется. Тексты должны ясно говорить **«автоматическая подпитка отопления»**, называть объект неисправности/блокировки и быть краткими.
- Контролируются изменения сервисов `Автоподпитка`, `Состояние`, `Аварийная блокировка`, `Авторежим WB`, `Датчик давления`, `Низкое давление`; начало/завершение цикла определяются по `state_text`, без новых WB-каналов.
- **Обнаруженный дефект v1.0**: единая строковая `variables.last` использовалась всеми сервисами, поэтому независимые события могли влиять друг на друга. Полная исправленная версия [`Logic/414_Pressure_makeup_push_v1_1.js`](../Logic/414_Pressure_makeup_push_v1_1.js) ведёт историю по имени каждого сервиса и игнорирует стартовое/повторное состояние. **Ожидает установки и проверки пользователем**, не заявлять как проверенное поведение Sprut 3.0 beta.
- Сценарий получает доступ только к Accessory с serial `lastochka_pressure_makeup`; использование реального `getSerial()` в v1.0 пользователем проверено.
- Уведомления по смене `Состояние`/циклам должны проходить отдельную проверку при фактических циклах; объявление о завершении не должно приходить при аварийной остановке.

## Открытые границы проверки

1. **Физическая приёмка №414** остаётся открыта. Полевой тест 17.10.2026: после пяти импульсов давление стабилизировалось на 1.178 бар, ниже цели 1.2 бар; зафиксирована блокировка. Не утверждать, что нормальный успешный цикл подтверждён.
2. v1.1 push-сценария ещё не подтверждён пользователем после замены. Проверить отсутствие дублирования и ложных push между разными сервисами.
3. Прямой K5 в работающем Sprut удалён, но в обнаруженных его можно подключить снова.
4. Нет подтверждения испытания полного сброса №414 на рабочей системе из Sprut.
5. Текущий документ не содержит секретов авторизации WebSocket, Telegram, MQTT и не предназначен для хранения их значений.

## Правило выдачи кода
