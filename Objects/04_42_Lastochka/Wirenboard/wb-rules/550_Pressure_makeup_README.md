# 04 42 Ласточка — подпитка отопления (проект, НЕ ВВЕДЁН В ЭКСПЛУАТАЦИЮ)

## Источник

- Адаптация алгоритма из `Objects/05_31_Ivolga_13/Wirenboard/wb-rules/507_Pressure_makeup.js`.
- Дополнительные защитные подходы сверены с `objects/05_38_Plod_47/etc/wb-rules/550_Pressure_makeup.js`.
- Шаблона подпитки в `Templates/WB-rules/Heating/` поиском не обнаружено.
- Не устанавливать с одинаковым ID виртуального устройства на контроллер, где уже есть другой скрипт владельца подпитки.

## Подтверждённые источники

| Параметр | Канал |
|---|---|
| Ток 4–20 мА | `wb-mai2-mini_46/input_1_current` |
| Пересчитанный вход | `wb-mai2-mini_46/input_1_value` |

Согласно предоставленному скриншоту: режим «Измерение тока 4–20 мА», границы 0–6000. При условии **реального диапазона датчика 0–6 бар** делим значение на 1000. Пример: ток 7,239 мА, значение 1214 => 1,214 бар. Достоверно подтвердить диапазон по паспорту установленного датчика до ПНР.

## НЕ ПОДТВЕРЖДЕНО — обязательные шаги до запуска

1. Выяснить фактический MQTT-выход реле/клапана подпитки и проверить, что у него нет другого писателя.
2. Проверить схему подключения: при OFF / потере питания клапан **физически закрывается**. Команда `OFF` в wb-rules не является обратной связью о закрытии.
3. Проверить защиту водопровода от обратного потока, аппаратное ограничение времени открытия и прочие независимые меры защиты.
4. Согласовать рабочие давления и характеристики контура: порог начала, цель, аварийный верхний предел; допустимую длительность импульса и интервалы. Значения в CFG сейчас **предварительно взяты из аналога**.
5. Согласовать работу без отдельного датчика давления ХВС: скрипт **не контролирует** давление ХВС, в отличие от варианта на Плодоовощной.
6. Убедиться, что вход `input_1_value` действительно означает бар × 1000. Проверить фактическую манометрию при ПНР.
7. После стендовой проверки назначить `CH.valve`, изменить `CFG.commissioned = true`, убедиться в отсутствии второго владельца реле. Виртуальные `enabled` и `auto_mode` по умолчанию выключены. ПНР проводить под наблюдением.

## Предварительная логика (CFG)

| Параметр | Значение |
|---|---:|
| Начало подпитки | ниже 1,2 бар |
| Цель | 1,5 бар |
| Сигнал низкого давления | ниже 1,0 бар |
| Аварийный верхний предел | 2,5 бар |
| Импульс ON | 3 с |
| Пауза | 20 с |
| Не более импульсов за цикл | 5 |
| Контроль зависшего ON | 5 с |
| Блокировка после запуска/сброса | 60 с |
| Устаревание MQTT-данных | 120 с |
| Максимум циклов за 1 ч / 24 ч | 3 / 6 |

**Важное ограничение:** ограничение количества циклов хранится только в памяти wb-rules и сбрасывается после перезапуска. Оно не заменяет независимый аппаратный ограничитель подпитки.

## Исполнительные и диагностические каналы

Реальный клапан до привязки не записывается: `CH.valve = null`, `CFG.commissioned = false`.

Виртуальное устройство: `lastochka_pressure_makeup`. Содержит давление, ток, счётчики импульсов и циклов, ошибки, причины запрета, разрешение/авторежим (оба выключены), ручной останов и сброс блокировки. **Ручное открытие клапана не предусмотрено.**

## Проверка

Проведена проверка синтаксиса через JS-парсер и имитационные тесты с подменённым реле:

- при `commissioned = false` записи в физические каналы отсутствуют;
- после тестового включения конфигурации при давлении 1,1 бар запускается ограниченный импульс;
- по истечении 3 с выдаётся команда OFF и начинается пауза;
- при токе 2 мА фиксируется ошибка датчика, цикл останавливается и блокируется до сброса.

Эти проверки **не доказывают** совместимость конкретного firmware/wb-rules, фактическое отключение контактов реле или физическое закрытие клапана.

Для проверки синтаксиса после сохранения на компьютере:

```bash
node --check 550_Pressure_makeup.js
```

На контроллере проверять журнал по `[отопление][550_Pressure_makeup][ласточка]`. До завершения ПНР нельзя включать `CFG.commissioned`.
