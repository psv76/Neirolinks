## Данные, которых НЕ хватает для включения

1. Подтвердить источник температуры мастер-спальни: допустимо ли
   считать `wb-msw-v4_47` в гардеробе репрезентативным, есть ли
   самостоятельный датчик непосредственно в спальне. Сверить
   **entity_id температурных входов 8 термостатов HA** с первичными
   WB-каналами выше. Ни один из отсутствующих ответов не заполнять
   предположением. Не использовать `wb-m1w2_66/External Sensor 1`
   как комнатную температуру: это датчик подачи жилой ветви.
2. Проверка `Sensor OK` / health / возраста наблюдений для каждого
   сенсора. Не считать неизменную цифру «устаревшей», когда автономный
   датчик продолжает подтверждать своё здоровье, и не считать старую
   retained-цифру свежим измерением.
3. Принятые локальные уставки, режимы и гистерезисы комнат;
   механизм долговременного сохранения на WB и границы команд UI.
4. Объектный ограниченный резервный нагрев **для комнаты без датчика**
   по независимому контролю подачи/защит. Отсутствие измерения не равно
   приказу закрыть все приводы, но автоматическое бесконтрольное
   открытие также нельзя допускать.
5. Протокол single-writer для K1–K11/K4; выдержка открытия, реальные
   readback и открытый гидравлический путь; при переходе с HM2
   не допускать одновременно двух авторов физических команд.

## Что подготовлено

- `Systems/HHM/core/HHMRoomThermostat.js`: чистый ES5 локальный
  расчёт спроса/гистерезис, квалификация основного/резервного датчика,
  ограниченный объектный fallback, локальное сохранение уставок и
  защита от retained/старых запросов UI.
- `Objects/05_16_Iset/HHM/room_zones.js`: подтверждённые ID и выходы,
  плюс 7 подтверждённых локальных WB температурных каналов. Для
  `master_bedroom` первичный датчик `null`, `47` отмечен только как
  кандидат. **Все уставки по-прежнему `null`, `commissioned=false`.**
  `assertCommissionable()` намеренно блокирует установку без
  уточнения спальни и утверждённых параметров.
- `Systems/HHM/core/HHMRoomPathGate.js` — офлайн-расчёт
  разрешения **запуска** K4 только при логически подтверждённом NO-пути;
  все 11 выходов остаются без физических команд. Старое подтверждение
  с другой сессии WB (bootEpoch) не используется. Это не датчик протока.
- Офлайн-тесты — без WB MQTT, без управления приводами и насосом.
