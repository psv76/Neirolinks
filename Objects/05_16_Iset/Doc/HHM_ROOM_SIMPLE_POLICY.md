# 05 16 Исеть — принятое упрощение комнатных термостатов (Issue #204)

**Решение 18.10.2026:** прекратить разработку сложной проверки достоверности
WB-MSW именно для Исети. Экспериментальные модули сохраняются в репозитории,
**не используются в рабочей схеме Исети и не являются условием ПНР**.
Главный риск на объекте — ненужная остановка отопления; запрос тепла из
отдельной комнаты сам по себе НЕ является аварией. Вместе с тем **отключение
одной комнаты при явной неисправности её датчика разрешено**. Не возводить
этот принцип в абсолют: нормальный термостат вправе закрывать свою зону,
пользователь вправе её выключать, а независимые защиты оборудования остаются.

## Принятая логика

Рабочая офлайн-заготовка: `Objects/05_16_Iset/HHM/simple_room_thermostat.js`.
Она использует лишь:
- прямую температуру одного назначенного WB-MSW (последнее опубликованное
  MQTT-значение допустимо даже при неизменной температуре);
- хранимые на WB уставку/режим `HEAT|OFF` и простой гистерезис;
- **явный** сигнал ошибки **этого** датчика от `wb-mqtt-serial`.

| Событие | Решение лишь для данной комнаты |
|---|---|
| Ниже нижней границы гистерезиса | `heatDemand=true` |
| Выше верхней границы | `heatDemand=false` |
| Внутри зоны гистерезиса | Сохранить последнее решение |
| Температура численно не меняется | Работать обычно, без таймера «старости» |
| `meta/error` реально сообщает неисправность | `heatDemand=false` для комнаты |
| Ошибка исчезла и значение доступно | Снова регулировать по температуре |
| Нет значения или значение некорректно | `heatDemand=null`: не выдавать новую команду приводам |
| Пользователь выставил `OFF` | `heatDemand=false` для комнаты |

**Важно:** `heatDemand=false` — штатное решение термостата данной зоны,
а не аварийный запрет отопления всего дома. `null` не равен `false`:
`HHMRoomPathGate` в таком случае предлагает HOLD для привода, а не CLOSE.
Никакой таймер проверки свежести, проверка Modbus poll sequence,
bootEpoch для датчика, RPC `device/Load`, heartbeat HA, алгоритм
сенсорного fallback, SENSOR_HOLD или повторная публикация по
`max_unchanged_interval` для комнат **не требуются**.

Независимые защиты котла/теплоносителя и логика насосов/гидравлики остаются
в других компонентах HHM; модель термостата их не заменяет. Приводы
NO 0=OPEN/1=CLOSE; для K4 сохраняется отдельный единственный физический
автор и штатная выдержка открытия приводов.

## Утверждённая диагностика (18.10.2026)

Выдержка открытия приводов для новой HHM — 120 с по readback,
живой HM2 до переключения остаётся на 180 с. В каждой комнате
показываются отдельные таймеры приводов, в сводке — таймеры
и причина ожидания насоса K4. Это операционная визуализация,
не дополнительная проверка WB-MSW или основание для остановки
отопления по неизменной комнатной температуре.
