# 04 22 Даниловский

Объект: квартира **«Даниловский»**.

Статус: **предварительное проектирование ПНР, 2026-09-24**.

Эта папка становится канонической объектовой папкой для дальнейшей ПНР и разработки автоматики. Не смешивать физические каналы и логику с другими объектами.

## Текущие источники

На старте использованы:

- `Задание на выключатели ДЗ11-102.docx` — текущее функциональное ТЗ на кнопки 201–236, освещение, вентиляторы, движение, влажность и мастер-сценарии;
- `wb-mqtt-serial (5).conf` — текущий снимок Modbus/RS-485 конфигурации контроллера;
- `wb-webui (1).conf` — текущие имена исполнительных каналов и групп в WebUI;
- три старых `wb-rules`-скрипта с контроллера:
  - `Правило включения вентиляторов.js`;
  - `Правило ночного освещения подсветок.js`;
  - `Правило света с различных кнопок.js`.

Старые скрипты используются **только как источник фактических MQTT-каналов и следов предыдущей ПНР**. Их алгоритмы не считаются канонической реализацией ТЗ и не должны копироваться в новую архитектуру без проверки.

## Канонические документы

- [PHYSICAL_CHANNEL_MAP.md](PHYSICAL_CHANNEL_MAP.md) — всё, что на данный момент известно о составе системы и физических/MQTT-каналах.
- [BUTTON_IMPLEMENTATION_MAP.md](BUTTON_IMPLEMENTATION_MAP.md) — по каждой кнопке: физические входы, локальная резервная логика модуля, расхождения с ТЗ и что должен добавить JS.
- [SCRIPT_ARCHITECTURE.md](SCRIPT_ARCHITECTURE.md) — предварительная архитектура новой объектовой логики. Исполняемых скриптов по этой архитектуре пока нет.

## Принцип дальнейшей работы

1. Сначала подтверждаем физическую карту на живом объекте.
2. Затем фиксируем ownership каждого выхода и входного события.
3. После этого пишем новые объектовые скрипты по `SCRIPT_ARCHITECTURE.md`.
4. Старые правила отключаем только после того, как соответствующая функция перенесена и проверена.
5. Любое расхождение между ТЗ, WebUI, Modbus-конфигом и фактическим поведением сначала фиксируем в карте, а не «исправляем по догадке».

## Планируемая структура

```text
objects/04_22_Danilovsky/
├─ README.md
├─ PHYSICAL_CHANNEL_MAP.md
├─ SCRIPT_ARCHITECTURE.md
```

Папка `Wirenboard/wb-rules` будет создана вместе с первыми новыми файлами: пустые каталоги Git не хранит. Общих объектовых модулей заранее не создаём; реальные MQTT-каналы и русские комментарии задаются в начале каждого рабочего скрипта.
