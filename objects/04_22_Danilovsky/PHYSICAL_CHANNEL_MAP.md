# Карта физических каналов — 04 22 Даниловский

Статус: **предварительная карта по состоянию на 2026-09-24**.

## 1. Правило актуальности и уровни достоверности

Карта собрана из четырёх источников:

1. актуального `wb-mqtt-serial (5).conf`;
2. актуального `wb-webui (1).conf`;
3. функционального задания `Задание на выключатели ДЗ11-102.docx`;
4. трёх существующих JavaScript-правил с контроллера, которые используются только для восстановления фактических MQTT-каналов и старых привязок.

Обозначения:

- **CONFIRMED** — канал прямо подписан в WebUI либо однозначно совпадает с ТЗ и аппаратной локальной привязкой;
- **DERIVED** — привязка восстановлена по сочетанию ТЗ, локальной конфигурации модуля и старого скрипта;
- **LIKELY** — инженерная гипотеза, требующая проверки нажатием/физическим тестом;
- **UNKNOWN** — назначение из имеющихся данных не определяется.

Старые JS-скрипты **не являются источником истины по алгоритмам**. Например, в них есть устаревшая логика `ON/OFF` вместо `день/ночь/выкл`, счётчики нажатий в RAM и как минимум одна старая подмена группы `301.2` на `302`.

## 5. Текущие локальные привязки WB-MR6C, важные для миграции

Ниже перечислены привязки, которые уже выполняются **в прошивке самих релейных модулей** и поэтому могут конфликтовать с новым JS.

### `wb-mr6c_203`

- Input 1 SP: toggle K1, force ON K3.
- Input 4 SP: toggle K4, force ON K5 и K6.
- Inputs 3 и 5 активны в режиме кнопки, но явные local-output actions в конфиге не заданы.
- Для Input 4 включены Single/Long/Double Press Counter.

### `wb-mr6c_218`

- Input 2 SP/LP: toggle K2 и K3.
- Input 4 SP: toggle K4.
- Input 4 LP: force OFF K3.

### `wb-mr6c_117`

- Input 1 SP/LP: toggle K1.
- Input 2 SP: toggle K2.
- Input 2 LP: force OFF K1.

### `wb-mr6c_156`

- Input 1 SP/LP: toggle K1.
- Input 3 SP: toggle K3.
- Input 4 Double Press: toggle K4; SP/LP для K4 в текущем конфиге не задействованы.
- Input 5 SP: toggle K5.
- Input 6 SP/LP: toggle K6.
- K4 имеет `safe_state=1`, модуль настроен с `outputs_restore_state=1`; назначение и необходимость этих параметров отдельно проверить.

### `wb-mr6c_206`

- Input 1 Double Press: toggle K1.
- Input 1 Long Press: toggle K5.
- Input 2 SP: toggle K2.
- Input 3 SP: toggle K3.
- Input 4 LP: toggle K4.
- Input 5 SP: toggle K5.
- Input 5 LP: toggle K1.

### `wb-mr6c_138`

- Input 1 SP: toggle K3.
- Input 2 LP: toggle K2.
- Input 3 SP: toggle K1 и K3.
- Input 6 SP: toggle K6.
- Часть SP/LP actions со значением `0` фактически не используется новой архитектурой без отдельной проверки семантики текущей прошивки.

## 6. Инженерные подсистемы, которые присутствуют физически, но ещё не разведены по каналам

### 6.1. Защита от протечек — `wb-mwac-v2_151`

Факт: модуль WB-MWAC v.2 установлен на RS-485-2.

Из текущих файлов **не известно**:

- какой вход S1…S6 относится к какому датчику;
- какие краны подключены к K1/K2;
- используются ли импульсные счётчики воды;
- настроен ли режим «влажная уборка»;
- какие состояния клапанов и аварий выведены в WebUI.

Это обязательная зона полевой проверки.

### 6.2. Энергомониторинг — `wb-map6s_27`

Факт: WB-MAP6S установлен на RS-485-2.

Из текущих файлов **не известно**, что измеряют шесть токовых каналов. До идентификации трансформаторов нельзя присваивать им названия нагрузок или строить автоматические реакции по отдельным линиям.

### 6.3. Климатические датчики — WB-MSW v.4, адреса 56 и 57

- адрес 57 привязан WebUI к душевой и точно даёт температуру/влажность;
- адрес 56 в WebUI не подписан;
- по составу объекта и ТЗ на автоматическую вентиляцию/движение в двух санузлах адрес 56 является естественным кандидатом на ванную, но это пока **LIKELY**, а не подтверждённый факт.

### 6.4. WB-MR6CU, адрес 162

Модуль установлен, но ни один его выход/вход не отображён в текущих объектовых виджетах WebUI и старые три JS-файла его не используют. Назначение необходимо определить на объекте до разработки логики.

## 7. Что нужно добрать на ПНР для закрытия карты

1. Нажатием каждой неизвестной кнопки определить реальный `.../Input N ... Counter`.
2. Проверить, не заведена ли одна физическая кнопка параллельно на два входа разных модулей (особенно 216).
3. Определить назначение WB-MR6CU 162.
4. Подписать S1…S6, K1/K2 и счётчики WB-MWAC 151.
5. Определить назначение шести измерительных каналов WB-MAP6S 27.
6. Подтвердить помещение WB-MSW 56 и наличие/имена `Motion`, `Humidity`, `CO2`, `VOC`, `Sound`, `Illuminance` у обоих датчиков.
7. Проверить полный набор MQTT controls ONOKOM адреса 3 (кухня-гостиная).
8. Сверить фактическое поведение всех локальных input→output bindings перед их отключением или переносом в JS.
