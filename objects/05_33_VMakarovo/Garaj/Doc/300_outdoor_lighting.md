# 300_outdoor_lighting.js

## Объект

- Объект: `05 33 Верхнемакарово`
- Здание: `Гараж`
- Система: `свет`
- Контекст логирования: `улица`

## Назначение

Скрипт управляет наружным освещением по виртуальному устройству `day_night`, которое создаётся скриптом `290__day_night.js`.

Задача — не разовый триггер, а постоянное восстановление требуемого состояния:

```text
текущее состояние день/ночь/вечер
↓
проверка требуемого состояния наружного освещения
↓
если релейный канал не в нужном состоянии — запись команды
```

Это нужно, чтобы освещение восстановилось после:

- перезагрузки контроллера;
- временного отключения электроснабжения;
- перезапуска `wb-rules`;
- перезапуска Modbus-модулей;
- ручного изменения реле через WebUI;
- временной потери связи с интернетом.

Интернет для работы этого скрипта не требуется. Скрипт использует только локальное виртуальное устройство `day_night`.

## Источник состояния

Скрипт читает каналы:

| Канал | Назначение |
|---|---|
| `day_night/calculation_ok` | расчёт дня/ночи выполнен |
| `day_night/is_night` | ночь: от заката до восхода |
| `day_night/is_evening_light_time` | вечернее освещение: от заката до 01:00 |

Если `day_night/calculation_ok=false` или каналы `day_night` недоступны, скрипт не меняет выходы наружного освещения и пишет ошибку в системный журнал.

## Управляемые каналы

### Ночная группа

Включена, пока `day_night/is_night=true`.

| Канал | Назначение |
|---|---|
| `A02/K1` | Забор ул. Дачная |
| `A02/K3` | Забор ул. Колхозная |

### Вечерняя группа

Включена, пока `day_night/is_evening_light_time=true`.

| Канал | Назначение |
|---|---|
| `A03/K1` | Фасад большого гаража |
| `A03/K2` | Фасад Дом заказчика |
| `A02/K2` | Дорожки |
| `A01/K3` | Гирлянда большой гараж |

## Логика работы

### Ночь

```text
если day_night/is_night=true:
    A02/K1 = ON
    A02/K3 = ON

если day_night/is_night=false:
    A02/K1 = OFF
    A02/K3 = OFF
```

### Вечер

```text
если day_night/is_evening_light_time=true:
    A03/K1 = ON
    A03/K2 = ON
    A02/K2 = ON
    A01/K3 = ON

если day_night/is_evening_light_time=false:
    A03/K1 = OFF
    A03/K2 = OFF
    A02/K2 = OFF
    A01/K3 = OFF
```

## Восстановление состояния

Скрипт восстанавливает состояние в трёх случаях:

1. При загрузке скрипта.
2. При изменении каналов `day_night/is_night`, `day_night/is_evening_light_time`, `day_night/calculation_ok`.
3. Периодически раз в минуту через `cron("*/1 * * * *")`.

Периодическая проверка нужна для случаев, когда сам признак `day_night` не менялся, но исполнительный релейный канал сбросился или был изменён вручную.

## Логирование

Формат строк соответствует принятому регламенту:

```text
[свет][300_outdoor_lighting][улица]; ТИП=событие; параметр=значение
```

Примеры:

```text
[свет][300_outdoor_lighting][улица]; СКРИПТ=Скрипт загружен; источник=day_night
```

```text
[свет][300_outdoor_lighting][улица]; СОСТОЯНИЕ=Режим наружного освещения изменён; ночь=да; вечер=да
```

```text
[свет][300_outdoor_lighting][улица]; КОМАНДА=Включить вечернее освещение; группа=evening; причина=day_night/is_evening_light_time=true; канал=A03/K1, A03/K2, A02/K2, A01/K3; значение в канал=ON
```

```text
[свет][300_outdoor_lighting][улица]; ОШИБКА=Нет корректного источника день/ночь; причина=day_night/calculation_ok=false; источник=day_night
```

## Проверка после установки

1. Скопировать файл:

```text
/etc/wb-rules/300_outdoor_lighting.js
```

2. Проверить, что файл `290__day_night.js` уже установлен и создаёт устройство:

```text
day_night
```

3. В WebUI открыть устройство `День / Ночь` и проверить каналы:

```text
Расчёт выполнен = ON
Ночь
Вечернее освещение
```

4. Открыть системный журнал:

```text
WebUI → Системный журнал → сервис wb-rules
```

5. В поиске проверить:

```text
300_outdoor_lighting
```

6. Для проверки восстановления вручную изменить один из релейных каналов, например `A02/K1`. В течение минуты скрипт должен вернуть канал в требуемое состояние.

## Важные замечания

- Скрипт является писателем для каналов `A02/K1`, `A02/K3`, `A03/K1`, `A03/K2`, `A02/K2`, `A01/K3`.
- Эти же каналы не должны параллельно управляться другими независимыми сценариями `wb-rules`.
- Если пользователь вручную выключит канал в WebUI во время активного режима, скрипт вернёт его в автоматическое состояние при ближайшей проверке.
- Физическое состояние контакторов по обратной связи этим скриптом не проверяется. Скрипт отправляет команды в релейные каналы.
