# 05 31 Иволга 13 — HM2 ownership и фактическая гидравлика

Статус: **рабочая версия от 2026-09-10**.

Документ фиксирует не новую архитектуру, а объектную адаптацию уже принятой архитектуры Heating Manager 2.0 к фактической гидравлике и каналам Иволги.

## 1. Источники истины

Для отопления Иволги использовать в таком порядке:

1. `objects/05_31_Ivolga_13/HEATING_CHANNEL_MAP.md`
2. `objects/05_31_Ivolga_13/THERMOSTAT_MAP.md`
3. `objects/05_31_Ivolga_13/etc/wb-rules/620_thermostats.js`
4. `objects/05_31_Ivolga_13/etc/wb-rules/600_Heat_diagnostics.js`
5. `objects/05_31_Ivolga_13/etc/wb-rules/507_Pressure_makeup.js`
6. `Templates/WB-rules/Heating/HM2/MixingController/`
7. issue `#18` — общая разработка HM2
8. issue `#20` — объектная адаптация HM2 для Иволги

Старые карты и старые подписи сантехников не использовать как источник истины, если они противоречат актуальной карте каналов.

## 2. Не принимаем архитектуру заново

Для Иволги не проектируется новая схема HM2. Применяется уже принятый общий принцип:

```text
consumer → атомарный request → arbiter → source manager → единственный writer источника
```

Объектная особенность Иволги: зональные термостаты находятся в Wiren Board, а не во внешнем Home Assistant.

Следовательно, `620_thermostats.js` является нижним зональным слоем, а контурные managers должны читать его результат и публиковать HM2 consumer contracts.

## 6. Роль `620_thermostats.js` в HM2

`620_thermostats.js` не является полным Heating Manager 2.0.

Его роль:

```text
датчик помещения/пола → simple-термостат → команда сервоприводу зоны → состояние зоны для контурного manager
```

Для последующих managers он является источником состояния зон:

| Контур | Зоны / выходы |
|---|---|
| 501 ТП дом, паркет | `A08/K1`, `A08/K2`, `A08/K3`, `A08/K4` |
| 502 ГП дом, плитка | `A13/K1…K6`, `A14/K1…K3` |
| 503 Радиаторы дома | `A08/K5`, `A08/K6`, `A09/K1…K5` |

## 7. Роль `MixingController.js`

`MixingController.js` — не самостоятельный скрипт контура Иволги.

Это общий модуль регулирования положения смесительного клапана. Он не содержит:

- MQTT-адресов Иволги;
- насосов;
- зональных термостатов;
- погодной кривой конкретного объекта;
- HM2-арбитража;
- логики источника тепла.

Для Иволги нужны object managers, которые используют этот модуль.

Рабочие имена файлов пока считать предложением, а не исторически утверждённым фактом:

```text
560_mixing_tp_dom_manager.js
561_mixing_gp_dom_manager.js
562_mixing_gp_besedka_manager.js
```

## 8. Контракты будущих consumers

Каждый контурный manager должен публиковать атомарный HM2 request:

| Поле | Смысл |
|---|---|
| `state` | `ACTIVE / INACTIVE / UNKNOWN` |
| `valid` | достоверность обязательных входов |
| `heat_demand` | нужен ли теплоноситель контуру |
| `requested_source_temperature` | требуемая температура общей подачи |
| `request_reason` | причина запроса |
| `request_timestamp` | время расчёта |
| `request_ttl_s` | срок действия запроса |
| `path_ready` | готов ли физический путь после задержки сервоприводов |
| `pump_on` | команда/состояние насоса контура |
| `fault_latched` | защёлкнутая авария, запрещающая участие в арбитраже |
| `grant_state` | результат арбитража, пишет arbiter |
| `grant_reason` | причина результата арбитража |

Булев `true` без timestamp/TTL не считать полноценным запросом тепла.

## 10. Следующий рабочий шаг

### Шаг 1. Сделать первый object manager для 501

Первым контуром делать `501`:

```text
Дом, тёплый пол, паркет
насос A03/K1
клапан A05/Channel 1
подача 413
обратка 414
зоны A08/K1…K4
MixingController как общий регулятор клапана
```

Причина: этот контур наиболее критичен из-за паркета и ограничения температуры.

### Шаг 2. После 501 повторить схему для 502 и 504

`502` и `504` делать тем же архитектурным способом, но с их собственными каналами, датчиками и tuning.

## 11. Что не делать

- Не копировать объектные каналы Исети.
- Не писать новый самостоятельный PID/step-hold с нуля, если уже есть `MixingController.js`.
- Не делать `MixingController.js` владельцем насоса.
- Не давать арбитру право писать насосы или клапаны.
- Не включать `A14/K4`.
- Не считать `507_Pressure_makeup.js` экспериментальным: на Иволге он уже полево проверен.
