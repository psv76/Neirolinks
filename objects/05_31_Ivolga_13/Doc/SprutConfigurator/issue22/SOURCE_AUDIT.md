## Найденные конфликты / вопросы, которые нельзя решать угадыванием

### 1. `PHYSICAL_CHANNEL_MAP.md` содержит устаревший раздел зонального отопления

Раздел 5 карты от 2026-09-07 противоречит `HEATING_CHANNEL_MAP.md`, `THERMOSTAT_MAP.md` и `620_thermostats.js` от 2026-09-09. Для Issue #22 используются данные 2026-09-09. Сам `PHYSICAL_CHANNEL_MAP.md` позже нужно синхронизировать, чтобы убрать внутреннее противоречие репозитория.

### 2. Гостиная: два воздушных термостата при целевом UI `Воздух + Пол`

Текущая объектовая логика имеет:

- `NL_simple_thermostat_010` → `A09/K4`;
- `NL_simple_thermostat_011` → `A09/K5`;
- оба используют `902.01_MSW_TH/Temperature`;
- плюс `NL_simple_thermostat_611` для пола.

При этом Issue #22 задаёт целевой пользовательский вид жилой комнаты как два термостата: `Воздух` и `Пол`.

Нельзя самовольно решить, должны ли `010` и `011` быть объединены в один пользовательский воздушный термостат, либо один из них должен быть скрыт/иначе представлен. Требуется явное решение до финального YAML для гостиной.

### 3. Актуальные alias правой половины дома не полностью отражены в `PHYSICAL_CHANNEL_MAP.md`

Карта 2026-09-07 всё ещё содержит физические имена `wb-msw-v4_*` / `wb-m1w2_*`, тогда как отопительные документы 2026-09-09 уже используют часть актуальных `903.xx_*` alias.

Подтверждены используемые отоплением alias:

- `903.09_TEMP_NONE/External Sensor 1` — пол мастер-спальни;
- `903.08_MSW_TH/Temperature` — воздух мастер-спальни;
- `903.05_MSW_TH/Temperature` — воздух мастер-санузла;
- `903.06_TEMP_NONE/External Sensor 2` — пол мастер-санузла;
- `903.03_MSW_TH/Temperature` — воздух кладовки;
- `903.02_M1W2_LEAK_TEMP/External Sensor 2` — пол кухни.

Для дополнительных presentation-сущностей (например Humidity) соответствующие controls можно считать стандартными возможностями профиля `MSW_TH`, но сам объектовый alias должен быть подтверждён текущими материалами до включения в финальный plan.
