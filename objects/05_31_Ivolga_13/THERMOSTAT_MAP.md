# Карта зональных термостатов — 05 31 Иволга 13

Статус: **рабочая инженерная карта, 2026-09-07**.

Этот документ фиксирует, **какой тип термостата нужен каждой зоне, какие датчики он использует и какими физическими исполнительными каналами управляет**. Документ не является исполняемым кодом.

Основные источники истины:

- `PHYSICAL_CHANNEL_MAP.md` — фактические датчики и исполнительные каналы объекта;
- `Templates/Sprut/Heating/README.md` — принятые типы `simple / combo / climate`;
- `Templates/Sprut/Heating/NL_simple_thermostat.json` и `NL_combo_thermostat.json` — MQTT-контракт со Sprut.hub;
- инженерные решения по зонам, подтверждённые владельцем проекта 2026-09-07.

---

## 1. Где живёт логика

**Wiren Board — владелец логики зонального отопления.**

Wiren Board:

- читает физические датчики;
- хранит уставки;
- считает гистерезис и состояние зоны;
- формирует команду нагрева;
- управляет физическими сервоприводами/клапанами;
- логирует решения и ошибки;
- формирует виртуальные MQTT-устройства `NL_*_thermostat_XXX`.

**Sprut.hub — пользовательский интерфейс.**

Sprut.hub:

- показывает температуру и состояние;
- позволяет менять уставку;
- позволяет включать/выключать термостат;
- для `combo` показывает температуру пола и дополнительные уставки пола.

Критичная отопительная логика в сценарии Sprut.hub не переносится.

## 2. Типы термостатов

| Тип | Когда применяется | Датчики | Команда нагрева |
|---|---|---|---|
| `NL_simple_thermostat` | Один температурный датчик и одна команда нагрева | один датчик: воздух **или** пол | один исполнительный контур |
| `NL_combo_thermostat` | Есть воздух + пол и нужно каскадное регулирование | воздух + пол | один итоговый сигнал нагрева зоны; допускается несколько сервоприводов, работающих синхронно |
| `NL_climate_thermostat` | Есть отопление и охлаждение | воздух + пол + климатические данные | нагрев + охлаждение |

На Иволге `climate` на текущем этапе **не требуется**.

### 2.1. Логика COMBO

`NL_combo_thermostat` — каскадный термостат:

```text
температура воздуха
        ↓
сравнение с уставкой помещения
        ↓
выбор цели температуры пола
        ↓
температура пола
        ↓
открыть / закрыть сервопривод(ы) зоны
```

Принцип:

```text
если воздух ниже уставки:
    цель пола = "Пол при нагреве"

если воздух в норме:
    цель пола = "Пол при поддержании"

сервопривод регулируется по температуре пола
относительно выбранной цели
```

Один `COMBO` может управлять несколькими физическими сервоприводами, если они **всегда должны работать как одна зона**. Это используется на Иволге для мастер-спальни + тамбура и гостиной + коридора.

MQTT-устройство WB:

```text
NL_combo_thermostat_XXX
```

Основные controls:

```text
air_temperature
floor_temperature
target_temperature
target_state
current_state
floor_min_temperature
floor_max_temperature
```

Штатные значения шаблона Sprut для дополнительных настроек пола сейчас: `25 °C` «Пол при поддержании» и `29 °C` «Пол при нагреве». Это **значения шаблона, а не утверждённые уставки Иволги**.

### 2.2. Логика SIMPLE

`NL_simple_thermostat`:

```text
один датчик температуры
        ↓
сравнение с уставкой + гистерезис
        ↓
один сигнал нагрева
```

Датчиком может быть воздух или пол.

На Иволге SIMPLE применяется в двух разных смыслах:

1. **SIMPLE по полу** — пол держится тёплым независимо от температуры воздуха;
2. **SIMPLE по воздуху** — отопительный прибор догревает помещение по температуре воздуха.

MQTT-устройство WB:

```text
NL_simple_thermostat_XXX
```

Основные controls:

```text
temperature
target_temperature
target_state
current_state
```

- `611` не является отдельным термостатом — это второй исполнительный выход термостата `612`.

## 4. Зоны, где пол и радиатор регулируются независимо

### 4.1. Прихожая

Цель — тёплый пол независимо от температуры воздуха, открытых дверей и сквозняков. Радиатор используется как дополнительный зимний нагрев.

```text
606 SIMPLE по полу
902.06 -> A13/K1

620 SIMPLE по воздуху
902.05 -> A09/K1
```

Это **два независимых термостата** с разными физическими задачами.

### 4.2. Гостевая спальня

Принята такая же архитектура:

```text
604 SIMPLE по полу
902.11 -> A08/K4

621 SIMPLE по воздуху
902.10 -> A09/K2
```

Пол поддерживает комфорт поверхности, радиатор догревает воздух.

## 5. Синхронные исполнительные контуры

### 5.1. Мастер спальня + тамбур

Отдельного температурного датчика тамбура нет. Поэтому один COMBO-термостат управляет двумя сервоприводами одновременно:

```text
NL_combo_thermostat_601

воздух: wb-msw-v4_206/Temperature
пол:    wb-m1w2_147/External Sensor 1

выходы:
A08/K1  601 ТП Мастер спальня
A08/K2  602 ТП Мастер тамбур
```

`NL_*_thermostat_602` **не создавать**.

### 5.2. Гостиная + коридор

Коридор идёт вместе с гостиной. Один COMBO-термостат управляет двумя сервоприводами:

```text
NL_combo_thermostat_612

воздух: 902.01_MSW_TH/Temperature
пол:    902.02_M1W2_TEMP_NONE/External Sensor 1

выходы:
A14/K1  612 ГП гостиная
A13/K6  611 ГП коридор
```

`NL_*_thermostat_611` **не создавать**.

## 6. Вентиляция по влажности — отдельная логика, не термостаты

Вентиляторы не включаются в отопительные термостаты. Для них требуется отдельное WB-правило по влажности.

### Ванная

```text
датчик влажности: 902.12_MSW_TH/Humidity
вентилятор:       A12/K6
```

Отопление ванной при этом независимо:

```text
609 SIMPLE по полу
902.13_M1W2_LEAK_TEMP/External Sensor 2 -> A13/K4
```

### Мастер ванная

```text
датчик влажности: wb-msw-v4_128/Humidity
вентилятор:       A16/K1
```

Отопление мастер-ванной независимо:

```text
614 SIMPLE по полу
wb-m1w2_138/External Sensor 2 -> A14/K3
```

`A16/K1` зафиксирован как канал вентилятора по уточнению владельца проекта 2026-09-07; его нужно также добавить в `PHYSICAL_CHANNEL_MAP.md`, поскольку в текущей карте этот канал ранее не был отражён.

Для вентиляции ещё должны быть отдельно утверждены пороги влажности, гистерезис/задержки и ручное управление.

## 7. Нумерация виртуальных устройств

Номер виртуального термостата наследуется от **основного проектного исполнительного канала**.

Примеры:

```text
601 -> NL_combo_thermostat_601    // управляет A08/K1 + A08/K2
604 -> NL_simple_thermostat_604   // пол гостевой
606 -> NL_simple_thermostat_606   // пол прихожей
612 -> NL_combo_thermostat_612    // управляет A14/K1 + A13/K6
620 -> NL_simple_thermostat_620   // радиатор прихожей
621 -> NL_simple_thermostat_621   // радиатор гостевой
```

Не создаются отдельные виртуальные термостаты `602` и `611`, потому что их физические выходы входят в зоны `601` и `612` соответственно.
