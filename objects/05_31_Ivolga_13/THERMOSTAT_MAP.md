# Карта зональных термостатов — 05 31 Иволга 13

Статус: **актуальная рабочая версия от 2026-09-09**.

Основа:

- свежий файл `wb-webui(3).conf`, присланный в рабочий чат 2026-09-09;
- свежий файл `wb-mqtt-serial (2).conf`, присланный в рабочий чат 2026-09-09;
- фактическая проверка на объекте 2026-09-09;
- скрипт `etc/wb-rules/620_thermostats.js`.

Старая карта термостатов от 2026-09-07 больше не используется как источник истины для дома. Физика отопления оказалась собрана иначе: почти во всех комнатах есть радиаторы, поэтому комбо-термостаты убраны, а зональная логика переведена на simple-термостаты.

## Архитектурное решение

**Wiren Board — владелец логики зонального отопления.**

Wiren Board:

- читает датчики температуры воздуха и пола;
- хранит уставки;
- рассчитывает гистерезис;
- закрывает сервопривод при ошибке датчика;
- логирует команды, аварии и пользовательские изменения;
- создаёт виртуальные устройства `NL_simple_thermostat_*`.

**Sprut.hub — пользовательский интерфейс.**

Sprut.hub показывает термостаты и позволяет менять `target_state` и `target_temperature`, но не должен напрямую владеть физическими сервоприводами отопления.

## Почему теперь simple

На объекте 2026-09-09 выяснено, что почти во всех комнатах есть отдельные радиаторы. Поэтому прежняя схема с `combo` больше не является базовой.

Принято:

```text
один датчик температуры -> один simple-термостат -> один или несколько синхронных выходов
```

Двумя выходами управляют: `601` — `A08/K1` и `A08/K4` (мастер-спальня и мастер-гардероб); `010` — `A09/K4` и `A09/K5` (радиаторы гостиной).

## Исполняемый файл

```text
etc/wb-rules/620_thermostats.js
```

Особенности скрипта:

- все термостаты создаются выключенными при первом запуске: `DEFAULT_TARGET_STATE = false`;
- есть проверка валидности датчиков воздуха и пола;
- при ошибке датчика зона закрывается;
- команды в физические выходы пишутся только при изменении;
- есть периодическая синхронизация раз в минуту;
- есть логирование команд, аварий и изменений уставок;
- для паркетных полов 601/602/603 задан `hardMax = 27 °C`;
- `A14/K4` не используется.


`NL_simple_thermostat_011` не создаётся: A09/K5 работает вместе с A09/K4 в термостате 010. A09/K5 используется, это не пустой канал.

После merge и аккуратной установки 620 на WB требуется retained-check по `NL_simple_thermostat_011`: исключение устройства из ZONES само по себе не подтверждает очистку старых MQTT retained-сообщений.

## Проверка перед установкой

На контроллере нужно убедиться, что нет второго писателя в те же выходы:

```bash
grep -R "A08/K\|A09/K\|A13/K\|A14/K" /etc/wb-rules /etc/wb-rules-modules
```

После копирования скрипта:

```bash
systemctl restart wb-rules
journalctl -u wb-rules -f | grep -E "620_thermostats|rule error|TypeError|ReferenceError|SyntaxError"
```
