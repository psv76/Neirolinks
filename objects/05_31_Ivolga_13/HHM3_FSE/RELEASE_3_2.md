# HHM 3.2 — выпуск компонента для NLI 0.1.9

Основание: Этап 9 #81, проверенный HEAD PR #83
`4015b576b2e280569951cf7d328a83420cbd90b6`. Этапы 1–8 не повторяются.
Алгоритм не меняется; runtime-версия и видимая версия обеих ролей — 3.2.
Контракт датчиков остаётся `m1w2-health-v1`.

## Два неизменяемых коммита

1. Runtime commit R содержит исходники 3.2 и проверенный комплект HHM3.
2. Manifest commit M добавляет `NLI/releases/hhm-{boiler,gazebo}-3.2.json`
   и контрольные суммы. Оба manifests ссылаются на R, а не на самих себя.
3. После полного PASS HHM3 CI и NLI CI каталог строится из M:

```sh
python -B NLI/tools/release_catalog.py --commit <M> \
  --manifest NLI/releases/hhm-boiler-3.2.json \
  --manifest NLI/releases/hhm-gazebo-3.2.json \
  --minimum-nli 0.1.9 --output nli-catalog.json
```

Каталог содержит только две роли HHM 3.2, без нового пакета NLI.
Stable GitHub Release `nli-approved-hhm-3.2` направляется точно на M.
Asset `nli-catalog.json` должен иметь GitHub SHA256 digest.
Полные SHA R/M, результаты CI и SHA256 каталога фиксируются в #81/PR #83
после создания соответствующих коммитов. Исторические releases/known 3.1
сохраняются без изменений. NLI production-код и пакет 0.1.9 не меняются.

## Принятое полевое подтверждение MAO4

В Этапе 9 #81 приведён результат от 28.09.2026: повторная запись неизменных
Switch OFF и Level=59 создаёт свежую MQTT-публикацию; запись неизменного
Level сама по себе AUTO-ON не дала. При изменении Level AUTO-ON ранее
подтверждён PR #60. Реализация учитывает оба варианта. Физический тест
в этой работе не повторяется.

Архив `mao4-same-value-20260928-162246.tar.gz`, SHA256:
`5ec95f16cfdb41aac80e78fa3fc54d9608941e1b857c59124bca5db8a50cb783`.
По отчёту #81 подтверждение получено прямым MQTT capture; журнал этого
вспомогательного теста не собран из-за формата timestamp.

После публикации пользователь сам выполняет штатное `nli update hhm` на
зарегистрированном контроллере. Здесь не выполняются live-команды,
SSH, deploy, restart или merge. Выпуск не доказывает расход или ход штока.
