# Проверки HHM 3.0 FSE

Среда: Windows, Node.js 24.19.0. Повторная проверка после ревью PR #60, включая дополнительное испытание из комментария 5749789135. Запуск: node tests/run.js. **45 групп PASS**, включая node --check для всех runtime JS и проверку ES5-синтаксических ограничений. Повторяемые сценарии находятся в tests/run.js и tests/review-regressions.js.

Тестовая модель запускает настоящие скрипты обоих WB и модули в изолированных VM, реализует PersistentStorage, MQTT callbacks, timers, virtual devices и проверяет единственного writer каждого физического адреса. Данные датчиков и отказов синтетические. Все пять контуров нагружаются одновременно.

Проверены:
- Физические адреса и зональная карта, новый 505 без переназначения 010; первоначальный OFF, 1 °C гистерезис и сохранение OFF.
- Пять насосов, зональные реле, порядок Level/Switch, MAX и tie-break, 0 без 42, различие неизвестных и достоверно нулевых заявок, оба конфигурируемых режима физической команды NO_DEMAND.
- Первичный ввод без преждевременных writes, повторный запуск с сохранёнными intent/защитами, перезапуск задержки клапанов при скачке часов.
- LAN/bridge loss 504, автономные 30 °C, повреждённые настройки, floor-only при отказе 418 с пределом 50, одновременно недоступные обратные связи.
- Перегрев 504 по подаче/полу с порядком закрытия/остановки и новыми выборками, локальный перегрев 501/502, source/direct перегрев и автоматическое восстановление.
- Отказ одного датчика пола без остановки исправных зон; потери OT/411 без каскадного выключения насосов; NO_RESPONSE без latch; выходная ошибка с автоматическим повтором.
- stale/retained/null/invalid, wire v2 session/seq/TTL/clock/replay, house v3 семантика и диапазон счётчиков, локальный fallback с задержкой приводов.
- 506/507/GazeboPanel/ГВС отсутствуют среди отопительных writers; события переходов на обеих платах.

Дополнительные 11 групп по ревью: отдельные закрытые пары всех трёх каналов; AUTO-ON/AUTO-OFF; ожидание нового readback перед Switch ON; ошибки Level/ON до и после применения на первом открытии и работающем контуре; отказ OFF после AUTO-ON без повторного Level; ошибка остановки насоса при ожидании readback с немедленной попыткой OFF клапана; отсутствующий OFF readback, внешнее изменение уровня и автоматический повтор; SENT/CACHE_SKIP/ERROR и журнальные уровни; миграция 18 существующих VD с пустым storage; чистое создание OFF и перезапуск с явным OFF; интеграционные ошибки клапана при работающих соседях. Прежние 28 групп также проходят с новой моделью.

Ещё 6 групп по комментарию 5749789135: сохранённые 20/ON → 20/OFF с расчётной позицией 0 → 20/ON с позицией 20; приоритет OFF перед изменением Level при закрытии; ошибка/отсутствие readback первого OFF без записи Level; ошибка/таймаут повторного OFF без использования прежнего подтверждения; открытие с новым Level без восстановления старых 20 по ON; интеграционный отказ закрытия при работающих соседях и восстановление. Проверяется false закрытого признака и недействительность заявки при ошибках, даже если ошибочная команда фактически применилась в модели.

Модель MAO4 отдельно хранит Level, Switch и вычисляемое физическое положение (Switch OFF — 0, ON — сохранённый Level). Она консервативно включает Switch при любой записи положительного Level и выключает при нуле. Это синтетическая модель для поиска ошибок, не калибровка приводов: новое физическое наблюдение не содержит номера канала. Прежнее испытание владельца доказало переходы 0↔1 на каналах 1/2, не все возможные переходы и не свойства канала 3. Тесты специально моделируют применение команды до исключения: ERROR не означает отсутствие воздействия. Периодические non-retained readback в модели не доказывают их частоту/доступность на реальном wb-mqtt-serial.

tests/manifest.js --check проверяет список файлов, SHA-256, отсутствие потерянных зависимостей INSTALL и общую идентичность комплекта. zones-reference.json — контрольная карта 18 существующих термостатов из 620 плюс согласованный 505.

Это **программные mock/VM-тесты**, не физические испытания, не измерение температуры, протока или положения привода. Настоящий wb-rules/Mosquitto/TLS broker-stand здесь не запускался; на рабочем месте нет соответствующего стенда. Поддержка MQTT API реальным runtime, bridge ACL/TLS, физическое закрытие 562 и выключение CH при сохранении ГВС проверяются по INSTALL.md. SSH, установка, физические команды, рестарты служб контроллеров, сбросы аварий и merge не выполнялись.
