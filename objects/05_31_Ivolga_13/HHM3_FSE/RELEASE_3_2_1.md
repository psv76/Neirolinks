# HHM 3.2.1 — исправление полевой регрессии A05 readback

Основание: Issue #81, полевой тест boiler WB `wirenboard-ABF62SL` 28.09.2026.

## Наблюдение

После штатного обновления NLI 0.1.9 с HHM 3.1 на approved HHM 3.2 насос
смешивающего контура 502 во время устойчивого нагрева периодически получал
краткий OFF, затем снова ON. В журнале тот же механизм виден и для 501.

Полевой rollback `3.2 -> 3.1` прошёл штатно; после возврата 3.1 дёрганье
насоса прекратилось.

## Причина

В 3.2 новый контракт MAO4 требовал свежий `Dimming Level` и `Switch`
readback не только после новой команды, но и на каждом steady-state цикле.
Общий runtime readback использует sensor TTL 120 s. Если неизменившийся A05
не публиковал новое значение за этот срок, `io.readback()` возвращал
`value=null` при неизменившемся sequence. Это ошибочно запускало
`WAIT_OUTPUT_READBACK`, а затем `ENABLE_UNCERTAIN` и безопасный OFF насоса.

TTL-истечение без нового sequence не является новым противоречащим readback.

## Исправление 3.2.1

- fresh Level/Switch остаётся обязательным после каждой новой команды открытия;
- после подтверждения steady HEAT отсутствие новых A05 событий не снимает READY;
- более свежий противоречащий Level/Switch запускает повторное согласованное
  подтверждение;
- подтверждённый OFF сохраняется без heartbeat, но свежий последующий ON
  запускает bounded OFF retry;
- существующие command timeout/retry и fail-safe OFF не ослаблены.

## Regression

Добавлены отдельные сценарии:
- steady HEAT переживает >120 s без нового A05 readback без команды OFF насосу;
- подтверждённый OFF переживает TTL без ложного повторного закрытия;
- свежий противоречащий readback по-прежнему требует нового подтверждения.

До повторного live retry обязательны полный HHM3 CI и NLI CI.

## Версия и публикация

Опубликованный `nli-approved-hhm-3.2` не изменяется: RELEASES.md запрещает
заменять approved asset/manifest. Исправление выпускается как **HHM 3.2.1**
с новым immutable runtime commit R, новым manifest commit M и новым unique
approved tag. NLI остаётся 0.1.9.

Сначала повторный boiler live test: устойчивый 502 должен отработать дольше
старого 120 s TTL без `ENABLE_UNCERTAIN` и без `A03/K2=false`. Беседка
обновляется только после этой проверки.
