## Текущая программная ревизия

Исправление PR #63 поверх установленного в объекте комплекта PR #60. Три изменяемых файла котельной:

- `modules/HHM3Outputs.js` — принятие команды без ложного ожидания публикации MQTT и без заявления о физической работе насоса/клапана; после Level отправляется явный Switch ON, закрытие — только Switch OFF, Level сохраняется. Детальные структуры остаются только в памяти процесса для regression-тестов, а события — в отдельном event-topic и `wb-rules` journal. Нулевой известный спрос не ошибочно маркируется как отсутствие данных. Вычисленная команда никогда не называется доказательством механического движения.

Остальные исходники и конфигурация объекта сохраняются, кроме отдельно зафиксированных в PR #65 изменений 620 и диагностического слоя: беседка 624, 507 подпитка, Sprut, MQTT, OT, ГВС и другие контроллеры не меняются. Исходный рабочий комплект находится в PR #60. Issue #61 описывает историческую несовместимость wb-rules 2.40.0; котельная впоследствии обновлена до 2.46.5. Версия беседки в этом выпуске не меняется и не подтверждена заново.

## Контракт управления A05

Обычный целочисленный `A05/Channel N Dimming Level` задаёт уровень, но сам по себе **не включает** выход; скрипт записывает сначала Level, затем явный `Switch ON` и только затем команду насосу ON. Отдельные каналы с автовключением доступны с FW 2.9.0, но в этом объектном конфиге не используются. Закрытие горячего входа — `Switch OFF` без изменения последнего Level. Успешное присваивание в `dev` означает только принятие команды программой; MQTT readback диагностический, не доказательство положения клапана, циркуляции или наличия питания. При синхронной ошибке записи новая заявка контура запрещается, предпринимается Switch OFF, после восстановления повтор автоматический. Контроллер не должен останавливаться из-за отсутствующего повтора неизменного MQTT состояния за 10 секунд.

## Известные границы готовности

Программные модельные тесты **не являются физическими испытаниями**. На объекте ещё требуется отдельная приёмка фактического хода 560/561/562, температур, насоса и пути циркуляции, режима отключения только CH с сохранением ГВС (`source.noDemandMode='unconfirmed'`), 504 `FLOOR_SENSOR_INVALID` и интерфейса WB после применения. До завершения этих проверок статус — подготовленный выпуск для контролируемой установки и ПНР, не акт ввода отопления в эксплуатацию.

Установка, восстановление после ошибки и запрет на вмешательство в 507 — `INSTALL.md`. Проверенные факты и ограничения — `TEST_RESULTS.md`; точные файлы и контрольные суммы — `manifest.json`. Историческое исследование ветки 2.40 — `ISSUE61.md`.
