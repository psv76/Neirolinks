# Быстрая проверка HM2 / 501 — 05 31 Иволга 13

Задача: [#26](https://github.com/psv76/Neirolinks/issues/26), родительская — [#20](https://github.com/psv76/Neirolinks/issues/20).
Основа: GitHub `origin/main`, commit `000c3590a06187ef59224d6913283da6476f6382`.
План и runner подготовлены для последующего выполнения человеком на WB. Live-проверка этого runner не проводилась; деплой на WB не выполнялся.

**Физический ПНР 501 пока заблокирован до проверки источника 411 и гидравлики. Нормальный теплоперенос 501 ещё не подтверждён.** Наличие команды `physical-start --physical` не снимает блокировку. Её применяют только после отдельного инженерного решения, очно у котельной.

Runner не заменяет инженерный контроль физики: насос, клапан, арматура, воздух, температура труб. MQTT-readback реле и выхода 0–10 В не доказывает проток или фактическое положение штока. Отсутствие ненулевых значений в выборках не доказывает отсутствие коротких импульсов между ними.

## Подготовка и установка человеком

Использовать runner из проверенного commit/PR #26, сверенного с актуальным GitHub. Не брать скрипт из старой локальной папки. Установить **только этот shell-файл** на WB, например в `/root/hm2_501_test_runner.sh`. Он не должен лежать в `/etc/wb-rules`: это не правило JavaScript. Пример копирования с рабочей станции (заменить `WB_ADDRESS` адресом нужного WB):

```sh
scp objects/05_31_Ivolga_13/tools/hm2_501_test_runner.sh root@WB_ADDRESS:/root/hm2_501_test_runner.sh
```

Дальнейшие команды выполняются в SSH-терминале **на нужном WB**, под root. Нужны Bash, `mosquitto_pub`, `mosquitto_sub` с `-W`, GNU `timeout`, `flock`, `date`, `sleep`, `journalctl`, `grep`. Брокер — `localhost`. Runner не принимает адреса, произвольные MQTT-топики, shell-команды и дополнительные аргументы. Все выполняемые команды печатаются перед запуском; stdout и stderr сохранять вместе.

```sh
chmod +x /root/hm2_501_test_runner.sh
bash -n /root/hm2_501_test_runner.sh
```

До начала сверить установленную версию 501 с указанным выше hardening: при блокировке он пишет три безопасных нуля. Проверить отсутствие конкурирующих writers для `A03/K1` и `A05/Channel 1`, работоспособность MQTT и wb-rules. Если версия/ownership не подтверждены — не выполнять изменяющие сценарии. Этот runner не меняет 501, 507, 620, другие managers, OpenTherm или конфигурацию служб и не перезапускает wb-rules.

## Допустимо удалённо после согласования тестового окна

`snapshot` и `collect-journal` только читают. `safe-stop` физически выключает насос/клапан и прерывает отопление 501. `open-601` и `close-601` реально управляют зональными приводами через существующий 620, хотя насос/клапан 501 остаются выключенными. `gate-tests` меняет разрешения, поэтому требует подтверждённой версии 501 и отсутствия стороннего управления. Если эти условия не обеспечены — выполнять очно.

1. Снять исходное состояние и записать прежние `target_state` / `target_temperature` зоны 601:

   ```sh
   /root/hm2_501_test_runner.sh snapshot
   /root/hm2_501_test_runner.sh safe-stop
   ```

   У всех шести разрешений ожидается 0; `A03/K1=0`, `A05/Channel 1 Dimming Level=0`, `A05/Channel 1 Switch=0`. «НЕТ ДАННЫХ» или ненулевой readback — ошибка, не успешный stop. Runner пытается отправить все девять команд даже при отказе отдельной записи.

2. Включить расчёт без разрешения нагрева и открыть тестовую зону:

   ```sh
   /root/hm2_501_test_runner.sh enable-shadow
   /root/hm2_501_test_runner.sh open-601
   ```

   `enable-shadow`: `outputs_enabled=0`, `manual_commissioning_grant=0`, `response_commissioned=0`, затем `commissioned=1`, `local_permit=1`, `enabled=1`.
   `open-601`: уставка 26 °C, затем `target_state=1`. Это запрос тепла: если комната теплее уставки, открытие не гарантировано. Прямых записей в A08 runner не делает.

3. Дождаться `actuator_delay_s` из snapshot **после фактического открытия зоны** плюс одного `period_s`. В исходном 501 это 180 + 30 секунд:

   ```sh
   sleep 210
   /root/hm2_501_test_runner.sh snapshot
   ```

   Ожидается `valid=1`, `heat_demand=1`, `path_ready=1`, `pump_cmd=1`. Если открыта только 601: `active_zone_count=1`, `physical_active_output_count=2`, `A08/K1=1`, `A08/K4=1`. Другие действующие зоны могут увеличить счётчики. Три физических выхода 501 остаются 0; `grant_state=NO_ARBITER`. Не уменьшать actuator delay ради теста.

4. Проверить две блокировки:

   ```sh
   /root/hm2_501_test_runner.sh gate-tests
   ```

   Сначала `outputs_enabled=1`, grant=0, response=0; затем grant=1 при response=0. В каждой фазе runner читает три физических выхода примерно раз в секунду в течение не менее 35 секунд, ожидая только 0. Перед/после фазы проверяет готовность и свежесть `request_timestamp` (не старше 90 секунд). Нет demand/готовности — ошибка, а не положительный результат теста. В конце, при ошибке и при Ctrl-C выполняется `safe-stop`.

5. Собрать журнал и закрыть 601:

   ```sh
   /root/hm2_501_test_runner.sh collect-journal
   /root/hm2_501_test_runner.sh close-601
   ```

   Журнал: `journalctl -u wb-rules --since '30 minutes ago' --no-pager`, фильтр `501_tp_dom|hm2_501|MixingController|rule error|TypeError|ReferenceError|SyntaxError|Exception`. Отсутствие совпадений не считается ошибкой; отказ journalctl считается ошибкой. Для сохранения вывода можно добавить `> /root/hm2_501_journal.txt 2>&1` (файл перезаписывается).

   `close-601` задаёт `target_state=0`; уставка остаётся 26 °C. После теста восстановить прежнюю уставку через штатный интерфейс при закрытой зоне, согласно записанному исходному состоянию. Runner автоматически не возобновляет отопление и не восстанавливает прежние разрешения. Закрытие приводов занимает время.

## Только очно у котельной: будущий физический тест

**Сейчас этот раздел не выполнять: источник 411 и гидравлика должны быть отдельно проверены.** Инженер должен подтвердить температуру источника, корректность датчиков 411/413/414, насос, направление/шкалу клапана 560, арматуру, отсутствие воздуха и параметры response watchdog. Runner не нагревает источник и не пишет OpenTherm. Уставки/пороги нельзя считать подтверждёнными только по MQTT.

После снятия блокировки и при постоянном наблюдении повторно подготовить shadow: предыдущий `gate-tests` выключил все разрешения, а `close-601` закрыл зону.

```sh
/root/hm2_501_test_runner.sh enable-shadow
/root/hm2_501_test_runner.sh open-601
sleep 210  # заменить на фактический actuator_delay_s + period_s при их отличии
/root/hm2_501_test_runner.sh snapshot
/root/hm2_501_test_runner.sh physical-start --physical
```

Нужны готовность к расчётному нагреву, свежий timestamp, отсутствие fault и `freeze=0`. Без `--physical` команда отклоняется. В интерактивном терминале после крупного предупреждения требуется точный текст:

```text
START 501 PHYSICAL
```

Только после подтверждения и проверок устанавливаются `outputs_enabled=1`, `manual_commissioning_grant=1`, `response_commissioned=1`. Последний флаг означает инженерное подтверждение параметров watchdog, а не просто обход защиты. Затем snapshot и пятиминутное наблюдение с таймером/показаниями каждые 10 секунд. Медленные/недоступные данные или fault прерывают тест. В конце всегда `safe-stop`; автоматического продолжения нагрева нет.

При нежелательном поведении нажать Ctrl-C и контролировать физическое выключение. Trap также обрабатывает TERM/HUP, но не гарантирует stop при SIGKILL, потере питания, отказе ОС или брокера. Программный stop не заменяет доступного инженеру аппаратного отключения. Время остановки зависит от доставки MQTT-команд; каждая операция ограничена timeout. Одновременно разрешён один runner; для аварийного stop работающего runner использовать Ctrl-C в его терминале.

## Финал любого тестового окна

```sh
/root/hm2_501_test_runner.sh close-601
/root/hm2_501_test_runner.sh safe-stop
/root/hm2_501_test_runner.sh collect-journal
```

Записать фактические результаты, ошибки, readback и наблюдения человека. До выполнения на WB результаты остаются «не проверено на объекте». Если stop не подтверждён — нужен очный контроль, тест не считать успешным.
