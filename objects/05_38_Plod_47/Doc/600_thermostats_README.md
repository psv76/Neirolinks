# 600_thermostats.js

Зональные термостаты Wiren Board для Sprut.hub.

Скрипт создаёт виртуальные термостаты WB и управляет отоплением зон через сервоприводы, а в климатических зонах дополнительно управляет кондиционерами ONOKOM.

## Архитектура

```text
WB = логика отопления/охлаждения, защиты, исполнительные команды, системный журнал
Sprut.hub = интерфейс пользователя, уставки, режимы, отображение
```

Критичная логика отопления и охлаждения выполняется в `wb-rules`, а не в сценариях Sprut.hub.

## Типы виртуальных термостатов

```text
NL_simple_thermostat_[0-9]{3}
NL_combo_thermostat_[0-9]{3}
NL_climate_thermostat_[0-9]{3}
```

### NL_simple_thermostat

Простой термостат. В текущем скрипте используется для зон, которые работают только по полу.

Основные каналы виртуального устройства:

```text
target_state
temperature
target_temperature
current_state
```

### NL_combo_thermostat

Комбинированный термостат для зон с датчиком воздуха и датчиком пола.

Логика:

```text
воздух ниже уставки → цель пола = "Пол при нагреве"
воздух в норме     → цель пола = "Пол при поддержании"
фактическая команда сервоприводу считается по температуре пола
```

### NL_climate_thermostat

Климатический термостат для зон с отоплением через пол и охлаждением через кондиционер ONOKOM.

Режимы `target_state`:

```text
0 = OFF
1 = HEAT
2 = COOL
3 = AUTO
```

Режимы `current_state`:

```text
0 = OFF
1 = HEAT
2 = COOL
```

## Управление кондиционером

Основной управляющий канал ONOKOM:

```text
Active mode
```

Значения:

```text
0 = выключен
1 = нагрев
2 = охлаждение
3 = авто
4 = осушение
5 = вентиляция
```

В этом скрипте кондиционер используется только для охлаждения. Нагрев кондиционером не используется.

## Уставки охлаждения

В климатическом термостате есть две разные уставки:

```text
target_temperature  = Порог нагрева
cooling_temperature = Порог охлаждения
```

Минимальный зазор между нагревом и охлаждением:

```javascript
var CLIMATE_MIN_HEAT_COOL_GAP = 1;
```

Добавлено ограничение от старых/случайно завышенных значений:

```javascript
var CLIMATE_MAX_HEAT_COOL_GAP = 2;
```

Если `cooling_temperature` ушёл слишком далеко вверх относительно `target_temperature`, скрипт возвращает его к понятному значению:

```text
cooling_temperature = target_temperature + 1°C
```

Это нужно, чтобы ситуация вида `уставка климата 22°C, а порог охлаждения 30–31°C` не блокировала охлаждение.

## Горизонтальные жалюзи

В `NL_climate_thermostat` добавлены каналы:

```text
ac_vanes_control          = Контроль жалюзи
saved_horizontal_vanes    = Запомненное положение жалюзи
```

По умолчанию:

```text
Контроль жалюзи = выключен
```

Если `Контроль жалюзи` выключен:

```text
WB вообще не пишет в Horizontal vanes
кондиционер работает со своим последним положением жалюзи
```

Если `Контроль жалюзи` включен:

```text
при старте охлаждения WB ставит Horizontal vanes в запомненное положение
по умолчанию это 5 — выше среднего
если пользователь изменил жалюзи с пульта/карточки на фиксированное положение 2...6, новое значение запоминается
следующий старт охлаждения использует уже запомненное значение
```

Значения `0` и `1` не используются как запомненное положение для автоматического старта охлаждения:

```text
0 = остановить качание / не выбирать положение
1 = качание
2...6 = фиксированные положения жалюзи
```

Если в `saved_horizontal_vanes` по старому состоянию WB оказалось `0` или `1`, скрипт автоматически возвращает запомненное положение к `5`.

## Таймеры охлаждения в виртуальном устройстве

В `NL_climate_thermostat` добавлены диагностические поля:

```text
ac_min_on_timer_sec       = Таймер работы охлаждения, сек
ac_min_off_timer_sec      = Пауза между включениями, сек
ac_manual_pause_timer_sec = Ручная пауза охлаждения, сек
ac_timer_status           = Статус таймеров охлаждения
```

Назначение:

```text
если кондиционер не выключается сразу — видно, что идёт минимальное время работы
если кондиционер не включается повторно — видно, что идёт пауза между включениями
если кондиционер выключили извне — видно, что действует ручная пауза охлаждения
```

## Минимальное время работы охлаждения

```javascript
var AC_MIN_ON_TIME_MS = 10 * 60 * 1000;
```

Если охлаждение включилось автоматически, оно не выключается сразу по первому достижению порога. Отключение по температуре возможно только после минимального времени работы.

Исключения:

```text
target_state = OFF  → кондиционер выключается сразу
target_state = HEAT → кондиционер выключается сразу
```

## Минимальная пауза между включениями

```javascript
var AC_MIN_OFF_TIME_MS = 10 * 60 * 1000;
```

После автоматического выключения охлаждения скрипт не включает кондиционер повторно сразу. Это снижает короткие циклы вида:

```text
10 минут работает → 2 минуты пауза → снова включается
```

## Ручная пауза после внешнего выключения кондиционера

```javascript
var AC_MANUAL_OFF_PAUSE_MS = 2 * 60 * 60 * 1000;
```

Скрипт не может точно доказать, что кондиционер выключили именно с пульта.

Он определяет внешнее выключение так:

```text
WB ранее включил кондиционер в охлаждение
WB не отправлял команду OFF
канал Active mode стал 0
```

В этом случае скрипт считает, что кондиционер выключен извне, и ставит ручную паузу охлаждения на 2 часа.

Пауза снимается:

```text
по истечении таймера
при изменении целевого режима термостата
```

## Взаимоисключение нагрева и охлаждения

Правило:

```text
если отопление зоны активно → кондиционер выключен
если охлаждение зоны активно → сервоприводы отопления закрыты
```

При активном нагреве пола команда кондиционеру:

```text
Active mode = 0
```

При охлаждении команда сервоприводам:

```text
сервоприводы зоны = OFF
```

## Логирование

Скрипт пишет события в системный журнал `wb-rules`.

Формат:

```text
[система][скрипт][контекст]; ТИП=событие; параметр=значение
```

Примеры:

```text
[отопление][600_thermostats][гостиная]; КОМАНДА=Включить охлаждение кондиционера; причина=авто: воздух выше порога охлаждения; канал=ONOKOM-AIR-GR-3-MB-B_10/Active mode; значение в канал=2
```

```text
[отопление][600_thermostats][спальня]; СОСТОЯНИЕ=Охлаждение поставлено на ручную паузу; причина=кондиционер выключен извне; пауза_сек=7200
```

```text
[отопление][600_thermostats][гостиная]; СОСТОЯНИЕ=Пауза между включениями охлаждения; причина=минимальная пауза после выключения кондиционера
```

Важно:

```text
КОМАНДА = попытка записи в канал
```

Это не физическое подтверждение выполнения команды кондиционером.

## Проверка после установки

Положить файл:

```text
/etc/wb-rules/600_thermostats.js
```

Проверить синтаксис:

```bash
node --check /etc/wb-rules/600_thermostats.js
```

Перезапустить `wb-rules`:

```bash
systemctl restart wb-rules
```

Смотреть журнал:

```bash
journalctl -u wb-rules -f | grep "600_thermostats"
```

Проверить climate-зоны:

```text
NL_climate_thermostat_605
NL_climate_thermostat_612
```

Проверить новые поля:

```text
Контроль жалюзи
Запомненное положение жалюзи
Таймер работы охлаждения, сек
Пауза между включениями, сек
Ручная пауза охлаждения, сек
Статус таймеров охлаждения
```

## Проверка синтаксиса

Для файла из этого архива выполнено:

```bash
node --check 600_thermostats.js
```

Результат:

```text
OK
```
