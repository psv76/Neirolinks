# 550_Pressure_makeup.js

## Назначение

Скрипт управляет автоматической импульсной подпиткой давления отопления на объекте `05 38 Плодоовощ 47`.

Система для системного журнала:

```text
[отопление][550_Pressure_makeup][давление]
```

## Основная логика

- Контролирует давление отопления.
- Контролирует давление ХВС.
- Проверяет ток датчиков давления 4–20 мА.
- Открывает клапан подпитки короткими импульсами.
- После каждого импульса закрывает клапан, делает паузу и заново оценивает давление.
- Останавливает подпитку при достижении целевого давления.
- Блокирует подпитку при недостаточном давлении ХВС.
- Блокирует подпитку при ошибке датчиков давления или тока.
- Блокирует автоматический старт подпитки на 60 секунд после запуска `wb-rules`.
- Блокирует автоматическую подпитку при слишком частых циклах подпитки.

## Пересчёт давления

Модуль отдаёт давление как `бар × 1000`.

Скрипт делит значение на `1000`, фильтрует и округляет до двух знаков.

## Защита от частой подпитки

Назначение защиты — поймать ситуации, когда подпитка технически работает, но сам факт частой подпитки стал аварийным признаком.

Типовые причины:

- протечка в системе отопления;
- расширительный бак не держит давление;
- предохранительный клапан сбрасывает;
- воздух в системе;
- постоянная микропотеря давления.

Настройки по умолчанию:

```text
max_cycles_1h = 3
max_cycles_24h = 6
```

Логика:

```text
каждый автоматический старт цикла подпитки записывается в счётчик;
если количество циклов за 1 час больше max_cycles_1h — авария;
если количество циклов за 24 часа больше max_cycles_24h — авария;
при аварии frequent_makeup_alarm автоматическая подпитка блокируется;
сброс — через reset_alarm.
```

`0` в настройке лимита отключает соответствующий контроль.

Важно: история циклов хранится в памяти `wb-rules`. После перезапуска `wb-rules` счётчик начинается заново. Для долговременного расследования использовать системный журнал и историю физических каналов.

## Исправление readNumber()

Исправлена опасная логика `Number(null) === 0`.

Теперь `null`, `undefined` и пустая строка возвращают `fallback`, а не превращаются в `0`.

Это защищает от ложного старта подпитки при запуске, когда MQTT-топик давления ещё не пришёл.

## Логирование

Скрипт пишет события в системный журнал `wb-rules`.

Формат:

```text
[отопление][550_Pressure_makeup][давление]; ТИП=событие; параметр=значение
```

Логируются:

- загрузка скрипта;
- стартовая инициализация;
- старт цикла подпитки;
- включение и выключение клапана;
- начало и окончание паузы;
- успешное завершение;
- ручное закрытие;
- ручной импульс;
- отклонение импульса;
- ошибки датчиков давления и тока;
- недостаточное давление ХВС;
- аварийно низкое давление отопления;
- watchdog клапана;
- слишком частая подпитка;
- восстановление после ошибок датчиков и давления.

Пример команды:

```text
[отопление][550_Pressure_makeup][давление]; КОМАНДА=Открыть клапан подпитки; причина=автоматический импульс; отопление=1.18; хвс=3.2; запас_хвс=2.02; канал=wb-mr6cu_219/K5; значение в канал=ON
```

Пример аварии частой подпитки:

```text
[отопление][550_Pressure_makeup][давление]; АВАРИЯ=Слишком частая подпитка отопления; причина=превышен лимит циклов за 1 час; циклов_1ч=4; циклов_24ч=4; лимит_циклов_1ч=3; лимит_циклов_24ч=6
```

## Рефакторинг

- Существующие имена каналов и виртуальных параметров не переименованы.
- Новые параметры добавлены отдельными каналами.
- Прямые записи в клапан выполняются через функцию `writeValve()` с проверкой доступности канала.
- `КОМАНДА` в журнале означает попытку записи в канал, а не физическое подтверждение открытия клапана.
- Убрана ложная диагностика “закрыто”, если канал клапана недоступен.
- Добавлена защита от старта автоматической подпитки сразу после перезапуска `wb-rules`.
- Добавлена блокировка при слишком частых автоматических циклах подпитки.
- Код оставлен в ES5-стиле для `wb-rules`.

## Проверка после установки

Положить файл:

```text
/etc/wb-rules/550_Pressure_makeup.js
```

Проверить синтаксис:

```bash
node --check /etc/wb-rules/550_Pressure_makeup.js
```

Перезапустить правила:

```bash
systemctl restart wb-rules
```

Смотреть журнал:

```bash
journalctl -u wb-rules -f | grep "550_Pressure_makeup"
```

Проверить в WebUI виртуальное устройство:

```text
550 Подпитка давления отопления
```

Контрольные поля:

```text
Слишком частая подпитка
Циклов подпитки за 1 час
Циклов подпитки за 24 часа
Максимум циклов за 1 час
Максимум циклов за 24 часа
```
